## Product policy

One shared explicit emoji picker search serves English, Spanish and mixed queries. This is a content-language policy, not three engine modes. No language switch or invented context/history parameter is required. Contextual suggestions retain the unchanged English implementation and resources.

Source semantics are intentional: existing English names and keywords retain their full legacy diacritic folding and all existing alternatives, including consonant diacritics. New Spanish speech-name aliases fold vowel accents/case/canonical composition but preserve the letter ñ. A query has both an English legacy interpretation and a Spanish orthographic interpretation. Thus English legacy results may overlap an ñ query; Spanish aliases must distinguish every fresh n/ñ pair under test. This distinction must hold in a synthetic fixture without depending on particular words. English input spelling remains compatible, including ASCII spellings of accented English keywords.

An ASCII one-character query returns the exact baseline English list, in order, including q and z. Such broad prefixes intentionally do not add localized results until two characters. A shortest non-ASCII letter query (including ñ and NFD equivalent) retains its baseline English alternatives and may add Spanish orthographic matches. There is no blanket short-query invariance claim.

Legacy English result membership and relative order are preserved for every nonempty query, with no newly imposed result cap. New localized exact results may precede English prefix-only matches, after legacy exact matches; remaining new matches follow legacy results. This ranking must be deterministic and duplicate-free. Existing English exact matches must not be demoted by new prefix matches. The single ASCII-character list has the stricter rule above.

Whitespace and punctuation split localized words, including hyphens, colons and underscores; wrappers consisting solely of punctuation/whitespace retain baseline empty/recents behavior and must not inject aliases. No operators, minus exclusion, quoted phrase language, locale tags or fuzzy edit-distance syntax is introduced. Leading/trailing punctuation does not change localized token meaning. The legacy interpretation keeps its existing syntax. Mixed and Spanish multiword matching requires every token to prefix a word from a single entry's English-plus-Spanish vocabulary, with Spanish ñ retained in the Spanish vocabulary and legacy English folding on English vocabulary. Token order does not change added localized membership; inherited baseline English order-sensitive behavior is recorded, not relabeled a new regression. Repeated tokens do not create or duplicate results.

Empty search and recents, limits/wrappers, skin tone and stored recent behavior remain as baseline. No writes, history learning, remote lookup, query cache, growing dictionaries or per-query index builds. Public fixture APIs and resource absence behavior must be accurately mapped before independent authoring.

COMMON PUBLIC BINDING
Each test launches a fresh app scene with -PKPreview -PKSystemKeyboard
-PKResetSettings. There is no -PKResetLearning, learned-word clear, emoji clear,
defaults-domain removal, account operation, or transcript operation. The native
host must be the ordinary Text Try It UITextView, accessibility id system-text;
preview-text is rejected. If needed, Next keyboard is tapped to reach Pulpo's
key-q. Failure to reach the installed extension is recorded without fallback.

Before action 1, app navigation opens Keyboard Settings. Exact baseline switch
titles Auto-Correction, Auto-Capitalization, “.” Shortcut, Smart Punctuation and
Learn New Words are set OFF through their visible public switches. The authored
Slide to Type, Show Slide Trail, Sound and Haptic Feedback initial states are
established through app switches. The disabled Show Slide Trail row in ES-04 is
prepared ON while Slide to Type is temporarily ON, then Slide to Type is set OFF,
all before numbered actions. No numbered settings visit changes an unnamed
control. All four slide/feedback switch values are read and screenshotted during
each such visit, including the disabled retained trail value. Predictive Text is
not an authored transform oracle and no suggestion is selected.

The host's baseline traits specify sentence capitalization/default correction;
the app has no public host-traits switch. The fixture therefore explicitly
requires ordinary public iOS Settings > General > Keyboard preparation with
system Auto-Capitalization, Auto-Correction, Smart Punctuation and period
shortcut OFF. That is behavioral preparation, not a hidden trait assignment.
Pulpo must already be enabled with Full Access for app settings to reach the
extension; the observer verifies these public controls without clearing data.
If the OS controls/permission cannot be observed or established, the binding is
unavailable with its precise obstacle, not silently presumed satisfied. No
candidate entitlement, permission store or internal trait is inspected.

Language is selected using the baseline public keyboard-language menu and the
exact English / Español / English + Español choice, checking its displayed
label. Initial literal text is entered by visible key taps. Public Clear handles
an unexpected scratch draft. The initial caret is then prepared using ONLY
ordinary host touch/magnifier/selection editing, never a controller/delegate or
the space-slide feature under test. Each initial host/caret is independently
observed before action 1. Letter actions map to key-<letter>, space to key-space,
and Backspace to key-delete, one tap per listed input. No test-only text setter
or host delegate call prepares or observes the document.

Every immediate checkpoint compares the full host AX string as literal UTF-16
(not canonical-equivalent Swift string equality), and captures the ordinary
screen. A human separately records the actual host text, full text before and
after the collapsed visible caret, and screenshot/live-frame adjudication.
Empty strings must be explicit responses, not missing fields. No caret is
inferred solely from document length. Subsequent authored insertions/deletions
serve as additional caret witnesses, without adding sentinel input actions.

EXACT MECHANICAL LIMITS / NO SILENT SUBSTITUTIONS
1. XCTest exposes the host text value but no public selectedTextRange/caret API
   here. It also cannot inspect a live caret while its ordinary drag API holds
   a finger and stop on a visually chosen boundary. EN-02/ES-02/BI-02 therefore
   hand the ONE hold-space/slide/release action to a human who stops at the
   visible authored boundary. Fixed pixel distances, counts of cursor commands,
   repeated correction gestures, and post-gesture caret repair are forbidden.
   The actual action and caret must be recorded; inability to drive/observe the
   continuous public gesture is unavailable, never an automated behavioral pass.
2. Try It's baseline onDisappear unfocuses the host. A normal coordinate tap on
   return can move the insertion point and would confound the unchanged-caret
   oracle. The return handoff explicitly requires ordinary public edit activation
   preserving the saved selection, e.g. a supported VoiceOver activation, with
   no manual caret placement/repair. Its availability is not established by this
   unexecuted review. If the platform cannot provide it, the settings-return
   caret observation is unbindable there. The fixture must report this obstacle,
   not tap-and-repair or relaunch/reseed the host. This applies to EN-04, ES-04,
   BI-04 and their common setup; all setup still requires public focus.
3. A visible emoji picture cannot by itself distinguish every invisible selector
   or scalar spelling. Baseline grid identifiers use the catalog base while the
   drawn glyph may use a stored preferred variant. Accessibility values can
   describe tone without exposing its exact Unicode sequence. The fixture does
   NOT strip an id prefix and call that a displayed-emoji observation. A human
   must transcribe the full actually displayed sequence before selection,
   corroborating the visible glyph with public accessibility; the record includes
   literal scalar values. If the full sequence cannot be established through
   the allowed public presentation, report that exact obstacle as unavailable.
   Do not infer E or R from the subsequently inserted host substring, silently
   drop selectors/modifiers/ZWJ components, or choose a fixed convenient emoji.
4. The transient slide trail is not a reliable post-release screenshot oracle.
   Before each native TouchPath trace a human starts a real recording. The
   subsequent human adjudication references that SAME recording, attached to the
   test result, and states trail presence/absence and an actual nonempty committed
   span at the host caret. No screenshot after release is used to assert absence.
   An unavailable native multi-point helper/extension delivery is not replaced
   with a straight drag or a controller call. TouchPath is the existing helper
   expressly permitted by the task; no additional private event API is introduced.
5. Recents membership is a visible section observation, not a history-store read
   or an insertion-derived proxy. The public Frequently Used button opens it;
   ordinary browsing can reveal E without an ordering/count/empty-history rule.
   The observer must distinguish that section from an adjacent category in the
   same collection viewport. If E is absent this is a failed membership outcome;
   inability to observe/drive the UI is separately unavailable.
6. Physical system-click audibility and tactile haptics are unavailable
   observations on Simulator. ES-04 records both as unavailable at actions 2,
   4 and 6; no fake sound/tactile assertion and no physical release prerequisite
   is added. Displayed independent switches and literal editing remain asserted.

HANDOFF / OBSERVATION CONTRACT
The fixture's header documents PK_R53_V2_HANDOFF_DIR. Each observation/action
publishes a uniquely named request and screenshot into that runner-accessible
directory. A human supplies the corresponding atomic JSON response with the
exact token, observer, evidence/adjudication and observed fields. Fresh nonce
names prevent stale responses from being reused. The response is attached to
the XCTest result. For transient slide checks, the same actual recording must
exist at its supplied absolute path and is also attached. Missing human binding
is explicitly unavailable/skipped, not a pass. A reported absence of required
membership, wrong text/caret/query/trail/state or empty slide commit fails.
The 1800-second handoff limit and ordinary XCUI locator waits are fixture
mechanics, not new public latency/performance thresholds. No performance claim
is made. These handoffs store observer evidence only; they neither read nor
write candidate private state.
Visible candidate enumeration uses the public hit-testable element and viewport
intersection, not a new full-cell-geometry threshold. The human must observe the
full displayed glyph; a clipped cell hitbox alone does not disqualify a complete
glyph. The frozen locator/name/value/frame is rechecked before accepting its
observation and again before selection, including membership-only observations.

Review conclusion: all twelve authored textual/action sequences have coherent
public semantics. Complete unattended action/observation binding is unavailable
for the specific caret, focus, full-emoji-scalar and transient-trail reasons
above. The new fixture represents those limits explicitly with native input,
public UI observations and mandatory human evidence, preserving every authored
input/oracle instead of retuning it. An environment unable to fulfill a required
public observation must retain that unavailable result and exact obstacle.
No blanket gate, pass result, test execution authorization, or claim that the
unavailable physical feedback must be measured is invented here.

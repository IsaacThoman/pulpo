# R40 normative capability and acceptance contract v1 (DRAFT; domain approval pending)

Baseline 00e2a0e7. One explicit shared picker searches English, Spanish, or mixed text regardless of the app's three language settings. Contextual EmojiSuggester.suggestions remains exactly English with unchanged legacy resource fields/order. No remote lookup, adaptive learning, cache or per-query index construction.

## Capabilities

Emoji retains value/name/version/tones/keywords and gains an optional Spanish CLDR48 speech name, JSON key s and initializer spanishName (default nil). Catalogs without s remain valid. The public APIs are EmojiSuggester(catalog:), suggestions(for:limit:prefixes:), search(_:limit:preferring:), emoji(for:), EmojiSearch.results(for:suggester:history:limit:), EmojiSearchQuery, EmojiHistory. Fixture catalogs use the existing JSON decoder and independent entries with optional s. A fixture alias for an absent glyph has no effect. No language/context parameter exists.

English names/keywords/exact names, folding of all diacritics, contextual behavior, prefix/order/ranks and legacy picker subsequence are preserved for every query and preference map at every existing limit. Existing English names such as consonant-diacritic words keep ASCII/case/NFD compatibility. New fields do not alter old fields or order. Duplicate base values are not introduced. The shipped catalog has unique bases; arbitrary fixtures must too. Tone selection maps base matches to the stored tone through unchanged wrapper behavior. Search does not write history. Empty wrapper searches use recents then popular and preserve recent variants/dedupe, exactly as baseline. Punctuation-only wrappers retain baseline empty-result behavior; they are not empty-query recents.

New localized interpretation lowercases with a fixed locale, canonically decomposes, folds combining marks only after vowel bases, and recomposes. Consonant marks including n/ñ remain distinct for ALL Spanish speech names, including synthetic arbitrary controls; no word exceptions. All punctuation, symbols, digits and whitespace separate Spanish words; punctuation wrappers carry no operators. Vowel accents, uppercase and NFC/NFD are equivalent. No stemming, typo matching, transliteration, stopword removal or invented synonyms for Spanish. Every unique query token must prefix a word of the SAME entry's English-plus-Spanish vocabulary, using legacy folding against English and Spanish orthography against Spanish. At least one Spanish token match is required. English vocabulary includes name words, keyword words and the legacy compact forms. Query tokens are canonicalized to a sorted unique set BEFORE matching/ranking/caps. Reordering or repeating tokens changes neither the selected localized membership nor its order, for fixed limit/preferences, including caps1,48,60 and overfull synthetic catalogs. English subsequence may retain its inherited order dependence.

An ASCII one-letter canonical token returns exactly the baseline list, including punctuation wrappers and repetition. Non-ASCII one-letter tokens (including ñ/NFD) may add localized matches while preserving baseline results. Empty localized token sets and raw queries over80 Characters add nothing. The unchanged R36 EmojiSearchQuery buffer has its accepted40-Character behavior; direct search supports up to80. Search nonpositive limits return[], default48, ceiling60. Wrapper limits and buffer behavior remain unchanged, including its uncapped empty-query path. No blanket invariance is claimed across different raw buffer truncations; equivalent tokens must reach the search API.

## Fixed merge policy, including constrained capacity

First compute the unchanged legacy English result at the requested limit/preferences. Separately compute an order/repetition-invariant English envelope E(T) from the sorted unique canonical localized token set T. Define P(x) as fixed en_US_POSIX Foundation case/diacritic-insensitive folding, canonical decomposition, then retention of scalar bases satisfying BOTH Foundation CharacterSet.letters.contains AND Swift Unicode.Scalar.properties.generalCategory in {uppercaseLetter,lowercaseLetter,titlecaseLetter,modifierLetter,otherLetter}, joining without separators. Let A be the unique P(t) for ALL canonical tokens including ignored words. Let R be A after removing the legacy ignored words. Let V(e) be normalized English full names/keywords, their words, and compact forms; let I(e) be exactly the English terms actually indexed for e by the unchanged legacy initializer (same minimum3/maximum80 and ignored-word filter), plus its exact folded name for exact-name lookup. Entry e is in E(T) iff (1) each r in R is a substring of some P(v), v in V(e), AND (2) some P(i), i in I(e), begins with some a in A. Both predicates operate on projected terms, not raw terms. An empty projection imposes no restriction for that token; empty R makes (1) true but does NOT bypass (2). Empty T adds nothing. There is no generic full-catalog fallback. No per-word, per-language or ñ-specific envelope exception.

The localized tokenizer admits base letters through the SAME Foundation/Swift intersection, accepts Mn/Mc/Me marks only after an existing base-letter token, and treats other scalars as separators. Before letter admission, marks after vowel a/e/i/o/u are removed; consonant marks remain. P removes all marks and digits for capacity only. English normalization remains unchanged, including apostrophe deletion. Apostrophes split localized tokens, so substring witnesses remain necessary, while at least one indexed-term prefix witness must also exist. Ignored query tokens are INCLUDED for the existential prefix witness because a whole-phrase legacy match can start with an ignored word, while they are excluded from conjunctive reservation requirements. Exact-name lookup must be included separately for technical names. This prefix witness is a proposed necessary condition, not established by this prose: independent executable domain proof and adversarial Unicode/capacity controls are mandatory BEFORE implementation. All actual legacy results must belong to E(T) for all valid raw inputs with T, fixed cap and preference map. Any counterexample blocks this contract version before production changes.

Useful capacity is REQUIRED as an observable behavior, not merely permitted: for arbitrary admitted non-ASCII letter x and Spanish alias beginning with x, if no indexed English term projection begins with P(x), unrelated internal occurrences of P(x) in English words consume ZERO reservation slots. The alias must be returned at caps1/48/60 when otherwise eligible. Synthetic overfull localized catalogs must fill min(cap,eligible.count) in fixed canonical order in this situation. Include controls with vowel/consonant marks and case/NFD; do not substitute a ñ-specific fix. Reordered/repeated canonical tokens must select identical localized membership and order even under English saturation, exact lookups, stopword phrases, apostrophe joins, preferences and all caps. A candidate failing any declared smoke assertion is rejected before authoring/reveal.

Reserve min(limit,envelope.count) slots for English. Localized candidates exclude the ENTIRE English envelope. Fill at most limit-reserved slots from canonical localized candidates. This fixed localized tranche is then appended after the actual legacy list. Never evict, interleave or reorder legacy results. Unused reserved slots intentionally stay unused. This prevents order-dependent legacy occupancy from altering new localized membership at the cap. Envelope completeness is a required executable arbitrary-control safety gate, not an assumption.

Localized ranking: canonical Spanish speech-name token-set equality first, then fewer tokens requiring prefix completion across combined vocabulary, then fewer distinct Spanish name words, then original catalog order. Every ranking input is canonical and token-order/repetition independent. Existing recent/popular preferences keep their legacy effect only; they do not change localized ordering. No whole-string equality bonus. No first-token bonus. A Spanish exact match can follow an English prefix match because legacy preservation has priority. Conservative reservation can suppress an otherwise available localized result; audit this as a limitation, never count mechanically added arrays as useful alternatives.

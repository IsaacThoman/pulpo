# R19 pre-inspection contract

Frozen before reading engine source, R15 patches, or the parent native fixture. Baseline is c4a354f3, whose engine has no R15 change. R11/R15 and parent diagnostic examples are exposed development only. No fresh credit for their gains.

An anchored path may suppress automatic correction/learning only for its final component. Recognize a complete token beginning /, ~/, ./, ../ (possibly repeated ../), ASCII drive-letter colon plus slash or backslash, or UNC double-backslash server plus share. Require a nonempty real directory component before the final component for Unix-root paths; bare root / and comment-leading // are excluded. For UNC require nonempty server and share. Relative/home anchors themselves constitute directory evidence. Components permit letters, digits, underscore, hyphen, dot and tilde; directory components consisting solely of dots do not count as real directories. Reject empty interior components. Final component may contain dots; no extension/word/dictionary exceptions. Reject colon except drive prefix. Scope is the uninterrupted lexical fragment at the caret, bounded by whitespace or prose/shell separators ; | & < > ( ) [ ] { } ! ? = , + #. Quotes and backticks make the whitespace token ineligible rather than opening a new path. Never scan backwards across a separator to recover an anchor. Unix double-root paths, semicolon-containing filenames, quoted paths, bare filenames/options and ambiguous punctuation-containing directory names are intentional remaining misses, even though real files can use them. Existing behavior outside this narrow grammar must remain unchanged.

Safety rationale: filesystem intent cannot be inferred from a slash alone. A recognized anchor plus directory structure provides stronger evidence than bare filenames or ordinary a/word. Rejecting // sacrifices POSIX double-root paths to keep comments useful; UNC has a separate backslash anchor. Semicolon and other prose/shell punctuation immediately terminate eligibility, knowingly sacrificing real filenames to preserve ordinary correction. Even this grammar remains ambiguous for prose that exactly resembles a path; independent review must challenge that risk. No acceptance claim beyond frozen observed cases.

Freeze candidate and runner before one independent sealed reveal. All three actual stacks (English, Spanish, bilingual), normal correction policy, exact full-document outcomes, marker deletion, caret, selection, suffix, Undo, reset and private-field nonlearning are required. Preserve case denominators, unavailable operations and oracle errors. Any passing ordinary/control/safety regression in any mode rejects source; no tuning after reveal. No devices/native runtime acceptance claimed. Full core/services checks must retain only the five known failures. R16 before-existing-text policy and R18 completion ranking are out of scope.

Input schema: JSON object {cases:[{id,category,before,after,operations,expected,expectedByMode?,notes?}]}. before/after are full host context around caret. Operations are objects with op insert(text), backspace(count default 1), move(offset signed character count), select(start,end absolute character offsets), undo, reset, private(enabled), or sync. expected is exact full final document; optional expectedByMode keys en/es/bi override it. Authors may use expected checkpoints via operation expectDocument and explicit state expectations. Categories: literal, ordinary, control, safety, intentional-miss. Unknown operations/oracles are errors, never silently skipped. Inputs are synthetic and small.

Pre-reveal runner semantics clarification: reset replaces the full document with text (default empty), moves to its end and gives it a new document identifier; it does not erase the personal dictionary. private toggles isSecure and re-reads context. undo is the actual keyboard Backspace Undo action, not host undo. select uses absolute Character offsets; move is relative to the caret. sync accepts a host document callback. save flushes pending learning synchronously. State checkpoints are evaluated after the operation: expectDocument, expectDocumentByMode, expectNoLearning (both personal entries and touch weight), expectNoAutocorrection, expectAutocorrection. No source or original development oracles were revised. Supplementary exposed state cases retain any mistaken normal-policy expectations rather than relabeling them.

Pre-reveal source-review disposition: the grammar interprets the fragment to the left of the caret, not a complete right-hand filesystem token. Existing suffix policy is unchanged and no claim is made for quoted/right-hand/intermediate components. The existing nonseparator branch still learns alphabetic subfragments before hyphen/tilde/underscore, including inside a final filename; this candidate only suppresses learning through the existing terminal delimiter branch. No complete final-component or path-wide nonlearning claim is made. Secure-field nonlearning must still pass. Source review has now frozen ordinary-intent `/and/` and comment-nested-anchor diagnostics in review-diagnostics.json; losses there reject the source even though the parser intentionally matches their syntax. No source tuning will reclassify them.

Runner state vocabulary is extended before reveal with expectCursor (absolute Character offset), expectSelection (selected Character count), expectUndoAvailable, expectLearns, expectAutocorrects, and expectLearningUnchanged (personal spelling counts and total touch weight since latest private=true transition). Unknown keys/modes/categories/operations and malformed operations create errors. The final post-save state is always reported; a last-operation nonlearning oracle is rechecked after that flush. Full dictionaries remain fresh per row. Original oracles remain unchanged, including acknowledged errors.

The author necessarily saw the tasks while authoring; this is a source-blind, self-authored holdout, not an independently administered benchmark.

Each case starts with an exact left/right caret context and language mode. Actions are sequential user-visible operations: snippet means the production externally supplied snippet/transcript insertion API; suggestion means accept a visible completion replacing the current fragment; swipe means accept a resolved swipe word; emoji means insert an emoji through its production route; type means literal key input; mode means change language mode without changing text. Case inputs must use their actual production entry points or explicitly record an unavailable route; never normalize results to match expected text. Empty snippet is inert. Snippets preserve supplied text and internal whitespace. Neither generic word insertion nor punctuation insertion is assumed to require spaces everywhere.

All development failures, including unchanged failures outside that fix, must be reported.

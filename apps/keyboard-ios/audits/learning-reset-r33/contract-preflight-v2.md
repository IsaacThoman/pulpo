Supersedes REJECTED v1 without editing it or R29. No product edits. Exact independent review v1 is retained alongside. This version selects a durable bounded outstanding-token registrar (review R1), with SQLite transactions rather than a JSON replacement protocol. Approval of this exact contract AND accompanying executable schema is required before coding.

## 1. Domain and storage

Canonical sibling URLs PersonalDictionary.json and TouchModel.json map to dedicated `PersonalDictionary.json.learning-v2.sqlite` in the same canonical directory. Standalone noncanonical URLs map to `<original basename>.learning-v2.sqlite` and contain only that requested store. No path alias/symlink ambiguity: resolve existing parent symlinks and standardize before deriving all authority, marker and slot paths; reject a symlink at an original store, authority, marker or slot leaf (O_NOFOLLOW where applicable). AppGroup fallback remains separate, inaccessible to app clear. NoURL objects remain local, no coordinator/filesystem access, existing transient words/private-field rules remain intact.

A durable O_EXCL `<database>.initialized` marker fences legacy imports. Under a stable global `<database>.lock` flock(EX|NB), first migration reads BOTH canonical legacy siblings from disk, validates them, creates the marker before creating SQLite, then creates/imports schema+payload+fresh UUID epochs in one SQLite transaction. Marker without a complete supported DB is FAIL CLOSED; DB without marker is also fail closed (no legitimate completed creation has this order). Crash before complete initial migration may require explicit recovery outside this patch; report failed persistence, never silently reimport. Missing legacy ENOENT means empty; malformed, unreadable, unsupported or semantically invalid existing legacy data fails migration without marker creation. Max legacy/store payload bytes 8MiB each. v1 words <=5000 and pairs<=20000 except valid oversized legacy allowed only if deterministic current pruning brings within limits; do not silently drop invalid data. Existing blocks retained (user preference data, capped by input-byte bound rather than a new fixed-count eviction policy). Dedicated namespace means old binaries cannot overwrite new authority; old binary learning after migration is not imported. New protocol does NOT prevent an old binary from independently reading/writing legacy files or presenting old suggestions; mixed-version behavior is a rollout limitation, not proof of full erasure. No compatibility claim for concurrent old writers.

After supported DB creation every new read/write uses it, never legacy contents. Successful two-store clear deletes reachable legacy store files before reporting completion; database revocation/empty payload already committed, so a postcommit cleanup failure returns a distinct failure via Bool=false/error and cannot restore old data. Subsequent clear may retry cleanup; prior durable clear remains. Ordinary operations do not claim physical legacy cleanup. DB/marker/slot/global-lock use owner-only permissions and iOS completeUntilFirstUserAuthentication protection. SQLite rollback journal mode DELETE, synchronous FULL, busy timeout 0; no persistent WAL/shared-memory dependency. Transactions under global stable lock additionally cover migration/cleanup/sidecar registration. SQLite’s transaction journal handles process-death recovery and fixed journal naming; no custom temp namespace or crash debris. Power-loss durability limited to SQLite/filesystem documented guarantees, not measured power-failure proof. Never interpret EACCES/corruption/unknownversion as empty.

## 2. Fixed registrar and local ownership

P=8 writer slots per authority. Each process shares one coordinator per canonical authority (weak registry capped at32 live domains; no global unbounded cache). One slot covers all its dictionary/touch instances. Each stable `<database>.writer.0` ... `.writer.7` sidecar has an exclusive nonblocking flock held for coordinator lifetime. Acquisition occurs before global transaction ownership. A slot can be reclaimed ONLY by successfully obtaining this lifetime lock, never by PID/time/revision/reset. Incarnation UUID changes on reuse. Other instances in same process share the coordinator; they do not reclaim each other. Slot files are never replaced/unlinked. A stopped/suspended process retains its slot, a killed/exited process releases it. DB registrar stores slot+incarnation+sequence, kind (dictionary/touch), epoch, normalized key for dictionary, and status pending/committed/revoked. Touch registrar stores NO text or numeric trace. P*256 dictionary + P*256 touch outstanding records =4096 max. Acknowledged terminal records are removed transactionally before admitting new records. Orphan records are deleted only by proved slot reclamation. Reset may mark relevant records revoked without taking writer slot locks.

Actual learn/pin payloads and touch numeric samples remain LOCAL in per-instance pending arrays, maximum256 per store PER COORDINATOR across all local instances, not256 per unbounded instance. One dictionary record has word <=40 graphemes AND <=256 UTF8 bytes, history <=256UTF8 bytes; normalized registrar key <=256UTF8 bytes. Touch records contain <=40 finite slot/dx/dy triples, preserving kept-word grouping and order; words requiring more samples are rejected, never truncated. Invalid admission returnsfalse before mutation. Sequence Int64 overflow rejects admission; revision Int64 overflow rejects commit. NoURL keeps existing ordinary length semantics because no registrar bytes are stored.

All coordinator mutable persistence state is protected by a nonblocking local NSLock.try(). A foreground persistence boundary returnsbusy/false if local I/O owns it, never dispatches sync behind it. If local model mutation cannot observe/register, it returnsfalse and teaches nothing new; existing pending data/base stay intact. No new unregistered stale-epoch deferred operations. A storage operation already started (open/read/SQLite/fsync) has no hard kernel deadline; zero waiting applies to local/global/slot acquisition, not arbitrary filesystem stalls. No per-letter work or new visibility hooks. Main word boundaries pay one SQLite admission transaction; measure maximum storage cost before freeze. Background saves remain genuine background payload commits. Coalesce requests per coordinator into at most one running/scheduled attempt plus one retry-request bit; no FIFO of snapshot closures.

## 3. State machine, observation and merge

Learning acceptance = successful transactional registration of a token after observing the current durable store epoch, NOT durable count increment. Locally visible projection = latest valid durable base plus this instance's pending, still-pending eligible tokens in action order. Registration success binds causal order. A completed clear/forget revokes registrations earlier in transaction order; genuinely later accepted learn/pin registers in the current epoch and survives. On failed observation/admission returnfalse; callers can continue typing without adaptation, no false successful observation. Public API should expose last persistence result (ok/busy/capacity/invalid/io) where Bool cannot distinguish outcomes. Existing callers may ignore return; no silent claim that learning is guaranteed under failed storage/admission.

Dictionary learn = count+1 for exact spelling, updated lastUsed from captured admission time (only ranking, never causality), pinned OR existing pin, unblock normalized key, optional lowercased history→exact target pair+1. Pin on missing entry creates count1 pinned; pin existing preserves count. Forget is an immediate durable transaction: remove all normalized-equivalent word forms, all normalized target pairs (not histories), block exact requested spelling/key, revoke ALL currently pending dictionary learn/pin tokens for that key across slots, then commit before accepted=true. No historical forget watermark map. Local projection refresh after forget removes revoked local operations; a new same-instance learn/pin registers afterward. Other keys' tokens remain valid under arbitrary forget/relearn/prune cycles. Existing blocks and transient contacts may coexist exactly as today; clear doesn't remove transient words. Deterministic existing pruning and known/cache/history rules preserved.

Touch acceptance registers opaque token in current touch epoch, local record contains raw key-normalized numeric tap offsets. Replay computes reference offsets ONCE at word start, uses original ordered samples and existing clamp/decay/sum algorithm. Never replay aggregated deltas or recompute reference per sample. isLearning/private gates before registration. No persistence of text/tap sequences, no adapting on every raw key.

Save execution: acquire nonblocking local/global lock then BEGIN IMMEDIATE; read latest payload/epochs and token statuses; validate identities at EXECUTION and inside same transaction through COMMIT. Apply only matching pending incarnation/epoch/status tokens in stable local sequence, atomically set statuses committed with payload. Revoked/previously committed tokens are no-ops. At most one coordinator commit in flight. Local pending identities removed only after definitive commit or observation of terminal status; retry after failure reuses same token/value/order. If COMMIT returns error, explicitly ROLLBACK if transaction is active, then re-read statuses in a fresh transaction before any retry. If result cannot be determined preserve pending as uncertain; next attempt consults durable status, never blindly replays. Status committed handles successful commit + delayed/lost local acknowledgement. Empty/all-revoked save succeeds after reconciliation; busy/io/invalid/capacity fails without dropping valid tokens. Save success reflects this instance's eligible payload committed, not just enqueue. One-store reset revokes only that store, preserves sibling payload/pending. Combined reset atomically assigns BOTH new UUID epochs, empties BOTH payloads/blocks and revokes both-store tokens; no dictionary-only success claim.

Reads are per-store successful-observation coherent, not a claim of simultaneous in-memory dictionary/touch snapshots. Existing hostWillAppear calls each observer separately; reset may interleave, and cached suggestions can persist until next successful existing appearance/reload/kept-word boundary. No per-letter poll. Ordinary reload preserves still-pending tokens, never double-overlays committed tokens and never replaces state on read failure. Bool reload reports changed visible model (own completed save with same projection=false). Clean saves still reconcile epochs/token state.

# Word documents

Pulpo opens Word documents (`.docx`, plus `.dotx`, `.docm`, and `.dotm`) as collaborative live documents: a Y.Doc holds the document, everyone editing it sees the others' cursors and changes, and downloads and agents still get real Word files. The engine lives in `@pulpo/client-core/office/docx` (codec, model, diff) and `@pulpo/client-core/office/docx/view` (the editor); the web editor is `apps/web/src/features/files/live/docx`. Files opens it on the web, desktop, and mobile through the live-formats registry.

## Codec

`docxCodec` implements `LiveFormatCodec`. It runs without a DOM, so the server can use it.

- **Import** reads the package with `OoxmlPackage`, stores every part's bytes in the `LiveAssetStore` (the Y.Doc keeps only hashes), and converts the main document, headers, footers, footnotes, endnotes, comments, styles, numbering, and a few settings into the model below.
- **Export** rebuilds the package from the original parts and regenerates only the parts the model owns. Each regenerated part has a fingerprint taken at import; when the regenerated XML still matches it, the original bytes are written instead, so a file opened and saved without edits comes back byte for byte, and an edit to the body leaves headers, styles, and every other part untouched. Saving under another extension switches the main content type (`.docx` drops macros, as Word does; `.docm` keeps `vbaProject.bin` as bytes, never running it). Zip entries carry a fixed time, so the same document always exports the same bytes; agents' versions are checksums of exports, and an export that changed with the clock would look like an edit.
- **`applyFile`** imports the new bytes and writes them into the Y.Doc as a minimal diff: paragraphs that did not change keep their Yjs items, so edits other replicas have not synced yet merge instead of being overwritten. Keyed maps (styles, lists, comments) change only the entries that differ. A file that reads the same as the current document is not a change, even if its bytes differ from the last export.
- **`toText`** is what agents read (`pulpo files cat`) and search indexes: the text with tracked changes accepted, list labels as Word draws them, headings marked `#` by outline level, tables as `|` rows, footnotes as `[^n]` with their text at the end, and comments with their author and the text they cover. Custom-marked footnotes and endnotes also include their bodies, using stable `custom-n` labels in a separate counter so automatic numbering stays unchanged. A shared note inventory registers custom and automatic references for text, review summaries, rendering, and pagination, with tracked-deleted references excluded from the accepted inventory. Rendering resolves document-wide note defaults and section overrides once for both body references and story markers, honoring format, starting value, continuous numbering, and section/page restarts.

Hostile files fail with `LiveFormatError`: encrypted and legacy binary files (`encrypted`), zip bombs, absurd sizes, and tables wider than 1,000 columns or larger than 250,000 cells (`too_large`), strict Open XML (`unsupported`), and malformed XML, DTDs, deep nesting, and deeply nested tables (`corrupt`). Zips whose central directory, local headers, or Unicode Path fields name parts differently are refused, because different readers would see different documents in them.

## Model

ProseMirror via TipTap's packages (`@tiptap/pm`, `@tiptap/y-tiptap`), with a schema of its own (`schema.ts`), separate from Markdown documents'. The principle: **everything is kept, and only what is edited is rewritten.** Anything the editor does not model rides along as JsonML (`[name, attrs, ...children]`, stored as a JSON string) and is written back exactly.

- **Paragraphs** carry their style and one attribute per paragraph property (alignment, indents, spacing, keep options, widow control, numbering, borders, shading, tab stops, outline level, bidi), plus the rest of `w:pPr`, the paragraph mark's run properties (and its revision marks), the section it ends (`w:sectPr`), `w:pPrChange`, and the element's own attributes (`w14:paraId`).
- **Runs** are text with one mark per run property (character style, fonts, bold, italic, caps, small caps, strike, double strike, hidden, color, spacing, scale, position, size, highlight, underline, shading, vertical alignment), a mark for the remaining `w:rPr` children, and `w:rPrChange`. Separate marks mean two people changing different properties of the same text both win.
- **Wrappers** around runs are marks too: hyperlinks, content controls, simple fields, smart tags and custom XML, and the revisions `w:ins`, `w:del`, `w:moveFrom`, `w:moveTo`.
- **Inline objects** are atoms: tabs, breaks (line, page, column), drawings (pictures, charts, shapes, text boxes, VML, alternate content; the picture's bytes are an asset hash), note references, comment markers, bookmarks, field characters and field codes, symbols, Office Math, and anything else (`inlineXml`). Yjs keeps marks only on text, so atoms store theirs in a `marks` attribute.
- **Tables** use prosemirror-tables roles. Horizontal merges are `colspan`, vertical merges become `rowspan` (the hidden cells are kept and written back), and rows that skip grid columns (`w:gridBefore`/`w:gridAfter`) get invisible placeholder cells so every table is a rectangle. Content controls around rows and cells, and bookmarks between them, are kept.
- **Block content controls and custom XML** wrap blocks; unknown blocks (`w:altChunk`, …) are opaque blocks. Bookmarks and comment ranges between blocks ride on the neighbouring block.

### Y.Doc layout

| Key | Type | Holds |
| --- | --- | --- |
| `body` | XmlFragment | The main story. |
| `story:<id>` | XmlFragment | Each header and footer (`header:<part>`), footnote, endnote, and comment. Root-level, so two replicas creating one merge. |
| `stories` | Map | Story id → kind, part, and root attributes. |
| `styles` | Map | `style:<id>`, `docDefaults`, `latentStyles` → JsonML. |
| `numbering` | Map | `abstract:<id>`, `num:<id>`, `picBullet:<id>` → JsonML. New lists take the next numeric id above the existing definitions. |
| `comments` | Map | Comment id → author, initials, date, parent (replies), resolved. |
| `settings` | Map | Settings the editor reads or writes (track changes, even/odd headers, default tab stop). |
| `rels` | Map | The main part's relationships (headers and footers resolve through them). |
| `parts` | Map | Every original part → asset hash and size. |
| `docx` | Map | Document root and body attributes, the final section, the theme's colors and fonts, part fingerprints. |

Hyperlinks and pictures keep their target (URL, asset hash) rather than a relationship id, so they survive being copied between stories or documents; the exporter reuses or creates relationships and media parts as needed. New comments and notes get string ids that the exporter numbers. New notes start at 1 or above; -1 and 0 are reserved for the separator and continuation separator.

`DOCX_SCHEMA_VERSION` must be bumped when the schema or layout changes in a way older clients would misread. Version 2 added portable relationship metadata. Version 3 permits table rows fully covered by rowspans and retains image hashes in preserved merge continuations; older editors must not join these documents because they cannot read these structures safely.

## Editor

`DocxEditor` (`view/editor.ts`) is framework-agnostic: it takes `{ container, doc, awareness, readOnly, assets, user, labels }`, renders into the container, and exposes commands (`toggleBold`, `setStyle`, `toggleList`, `insertTable`, `addComment`, `acceptAll`, …), `state()` for toolbars, and `update`/`layout`/`request` events. All visible text comes from `labels`.

- **Rendering** turns styles into a scoped style sheet (document defaults, paragraph and character styles with `basedOn` resolved, table-style conditions) and direct formatting into inline CSS, in Word's order of precedence. Lists are numbered like Word (abstract definitions shared between instances, overrides, restarts, legal numbering, bullets in symbol fonts). List controls read resolved numbering; turning a list off suppresses numbering inherited through paragraph styles, including when direct numbering is also present. Enter on an empty list item and Backspace at its start use the same behavior. Table styles' borders, banding, and first/last row and column formatting are computed per cell. Theme colors and fonts resolve through the document's theme. Tab stops (left, center, right, decimal, with leaders) are laid out after rendering.
- **Insertion** puts the caret in a new table’s first cell, after an inline picture or symbol, after a page or section break, and in the paragraph following a table of contents. New footnotes and endnotes open for typing after their note marker; Escape returns to the body reference. Pasting a whole table puts the caret in a paragraph after it, creating one when needed so typing cannot enter an adjacent table. Shift+Enter breaks the line inside the paragraph (`w:br`, so a list item keeps one number). Tab moves between table cells and adds a row from the last one; in an editable document Tab and Shift+Tab never move focus out of the page (Shift+Tab outdents an indented paragraph); Escape, then Tab or Shift+Tab, moves focus on for keyboard users. A horizontal line is a bottom-bordered paragraph with the caret below it.
- **AutoFormat as you type** (`autoformat` option and `setAutoformat`, on by default): `1. `, `4) `, `a. `, `iv. ` start a numbered list in that format and from that number, `- `, `* ` and `• ` a bulleted one (not in headings or existing lists); straight quotes become curly; `--` between words becomes an em dash and ` - ` or ` -- ` an en dash once the next word is typed; web and email addresses become links on space or Enter. Each conversion is an undo step of its own after the typing that caused it, so Ctrl/Cmd+Z (or Backspace right after a list starts) gives the literal text back with the caret after it. Nothing converts while an input method composes. Suggesting mode skips lists and links, which have no tracked form; quotes and dashes are tracked like typing.
- **Print layout** paginates for real: the column is measured into lines, table rows, and blocks, and a pure layout pass (`view/layout.ts`) breaks pages with widow and orphan control, keep with next, keep lines together, page breaks and page-break-before, section breaks (next page, continuous, odd, even) with each section's page size and margins, room for the footnotes each page references, and repeated table header rows. Headers and footers (default, first page, even pages, inherited between sections) are drawn per page with PAGE, NUMPAGES, and SECTIONPAGES filled in; a header taller than its margin pushes the text down. Body paragraphs, tables, and nested block wrappers use their own section’s text width before lines and rows are measured. Percentage tables retain their column proportions and alignment within that width, including repeated header rows. Body layout, pagination, headers, footers, and notes share the same section text-width calculation; inherited stories use their destination section and endnotes use their final destination width. Offscreen header, footer, footnote, and endnote heights are measured in unzoomed layout pixels; canvas content, tab stops, and repeated rows convert their screen geometry to the same space. Changing zoom preserves reserved margins, note heights, and page breaks. Header/footer fields use the total document page count for NUMPAGES and the current section’s count for SECTIONPAGES, independently of page-number restarts. **Web layout** shows one continuous column with notes at the end. Zoom scales the canvas.
- **Headers, footers, and notes** are edited in place by double-clicking them (a second editor on that story). Relationship targets use the package path resolver, including parent-relative and absolute part names. The live surface stays mounted outside the rebuilt page bands, so repagination preserves its focus, selection, and ongoing input. Local story edits, undo, and style/numbering changes schedule pagination too. Static stories use the same computed node formatting as the editor, including list labels and indents, contextual spacing, table-cell styling, and paragraph revisions. Formatting state, find/replace, outline/bookmark navigation, and focus follow the active story. Note numbers update from the body while the story is open. Undo captures shared numbering-map changes only with the fragment that was edited, so body undo cannot remove a story’s list definitions. Accept/reject actions also cover tracked text in comment stories. Comments can currently be created only in the body: comment controls are disabled during story editing, rather than applying to the stale body selection. Section breaks, new notes, and table-of-contents commands are also body-only and disabled in a story. `addHeaderFooter(kind, type)` opens the header or footer the cursor's section shows, or creates one (a new part with a collision-free name and relationship id, in the Header or Footer style) referenced from the first section, so later sections inherit it as Word's "Link to Previous" does; first-page ones turn on that section's different first page, even-page ones the document's different odd and even pages. `insertPageNumber` adds a PAGE (and optionally "Page X of Y" with NUMPAGES) field paragraph at the top of the header or bottom of the footer, aligned, or a field at the caret of an open one. While a header or footer is open, "the section" of `headerFooter()`, `addHeaderFooter`, `removeHeaderFooter`, `setDifferentFirstPage`, and `pageSetup`/`setPageSetup(…, 'section')` is the one of the page it was opened on (kept while it stays open, so turning on a different first page edits that section even when the band moves), not the body cursor's, as Word's header tools act on the header's section; double-clicking a later chapter's header never moves the body caret. `removeHeaderFooterStory(storyId)` (the header bar's Remove) takes that story away from every section showing it, with its relationship and story, as one body undo step that brings back its text, part, relationship, and references (the `stories` and `rels` maps share the body's undo scope, and the removed story's fragment joins it before it is emptied). Creating one stays outside undo, like comments. Both are refused while suggesting; creating is refused in web layout. Export leaves out a removed header's or footer's part, relationship, and content type, and so does a header or footer the editor created whose last reference is gone, so removed text does not ship in the file; parts the original file had and still has are kept, so unedited files stay byte for byte. Its pictures stay as unreferenced parts, as they may be shared.
- **Page setup**: `pageSetup()` reads the size, orientation, and margins (points) of the cursor's section; `setPageSetup(change, 'document' | 'section')` writes `w:pgSz`/`w:pgMar`, keeping their other attributes and the section's other properties, refuses sizes that leave no room for text, and is one undo step even when only the final section changes. It is refused while suggesting.
- **Concurrent section properties are last-writer-wins.** The final section's properties are one packed value in the `docx` map, and a paragraph's section end is one node attribute, so two collaborators changing the same section before they sync (page setup, different first page, a new header's or footer's reference, a removal) keep only one write; offline editing widens that window to the whole offline period. Losing a page setup or first-page change is silent. When the change that loses is a new header's or footer's reference, or a collaborator removes the one that is open, the editor closes the open header or footer and emits `headerFooterRemoved` (the web app shows a toast), rather than letting typing go on into text no page shows; that text stays only in the Y.Doc and is left out of exports. When a removal loses to a section write that kept the reference, the export drops references to header and footer relationships the document no longer has (also when the original file still has that relationship) and then the part itself, so Word never sees a dangling reference and the file matches what the editor shows. Storing each section child (references by kind and type, `w:pgSz`, `w:pgMar`, `w:titlePg`) under its own key would let unrelated changes compose; that needs a model and schema version change and is not done.
- **Tracked changes**: Suggesting mode turns typing, deleting, Enter, formatting, paragraph changes, and inserted or deleted table rows into Word revision markup with the author and date; deleting your own suggestion removes it. Changes can be accepted or rejected one at a time or all at once, and the review panel lists them. `nextRevision(±1)` selects the next or previous change through the body and then headers, footers, and notes, wrapping around and passing over stories that cannot open (Viewing mode); `acceptRevisionAtCaret`/`rejectRevisionAtCaret` resolve the changes the selection touches, and `state().inRevision` says whether there are any. The document's own Track Changes setting picks the starting mode.
- **Comments** have ranges, replies, resolution, and deletion; creating or deleting them stays outside text undo. They are written to `comments.xml` and `commentsExtended.xml` so Word shows the threads.
- **Clipboard**: copying within a document keeps its notes and comments. Lists copied between documents bring their numbering definitions, with fresh ids in the destination document. The clipboard carries only a copy id; the content comes from this origin's memory and local storage, so HTML from other sites or apps is never trusted as Word data. Footnote and endnote references and comment markers copied from another document are removed, even when their ids exist here. Copies capture every relationship reference in preserved XML and marks (`r:*` and `o:relid`), including VML, both alternate-content branches, charts and embedded objects. Crossing documents or stories transfers the complete referenced part graph and its content types before insertion, without fetching external links. Export allocates relationships in the destination part and rewrites every reference. Private metadata holds asset hashes, so removing pasted content releases its copied assets; package bytes stay outside the Y.Doc. Copies are limited to 5,000 parts, 256 MiB of assets and 16 MiB of XML/relationship metadata. A pending paste follows transactions at its original selection and is cancelled if that editor closes. Legacy copies without captured graphs retain only pictures and links that can be rebound safely. The last copy is kept in local storage for an hour, for pasting in other tabs. Pasting from Word, Google Docs, or web pages keeps paragraphs, headings, lists (Word's `mso-list` too), tables (up to 63 columns and 250,000 cells), links, and run formatting, after removing scripts, styles, frames, event handlers, images, and non-web URLs. Document values that reach CSS (theme colors and fonts, font names) are checked or quoted, and links never navigate the page the editor is in. Pasted picture files (screenshots, or a copied picture whose HTML is only an `<img>`) and dropped picture files are inserted where they land, sized to their section's text width; formats Word cannot show (SVG, WebP, HEIC) are refused with an `imageRefused` event. `pasteData({ html, text, files }, { plain })` runs data a host read from the async clipboard through the same paste path, for context menus.
- **Tools**: find and replace (match case, whole words) maps results through transactions, validates their query and word boundaries after local edits, rescans after remote edits, and validates again before replacement. Replace All applies ranges from the end of the source document, including when accepted table rows relocate spanning cells. Searches and word counts omit deleted table rows/cells and include inserted ones. Other tools: word count (of the story, the selection, or with `body` the main text while a header or note is open) and the cursor's page (`currentPage`), a headings outline, format painter (applied to the next mouse or Shift+arrow selection, or the word clicked; `formatPainter({ sticky: true })` keeps it on until Escape; as in Word, it copies the paragraph format only from a cursor, a whole paragraph, or a selection past a paragraph's end), change case (lower, UPPER, Title, Sentence, tOGGLE, using each run's language), paragraph format (indents, spacing, exact or at-least line spacing, keep with next, keep lines together, page break before, widow control, borders), cell vertical alignment, repeated header rows, table alignment, table of contents (inserted as a real TOC field linked to bookmarks, and updatable), insert table, picture, link (at a caret in a link, `setLink` edits or removes the whole link and `linkAt` describes it; `#name` links to the bookmark named exactly that, `%` included, and `goToBookmark` (following a link, in the web app and on the phone) tries the name as written and then URL-decoded, never throwing on a stray `%`), horizontal line (from an empty paragraph it splits that paragraph like Enter, so Suggesting mode keeps the border on the suggested paragraph), page and section break, footnote, endnote, symbol. `contextAt(x, y)` describes what is under a point (table cell, picture, link, comments, changes) for host context menus. Keyboard shortcuts follow Word and Google Docs (Ctrl/Cmd+B/I/U, +E/L/R/J, which toggle back to left when pressed again, +Alt+1–6 for headings, adding Word's built-in heading style when the document has none, +Alt+0 and +Shift+N for Normal, +Space to clear character formatting only, +\\ to clear all formatting, Shift+F3 to cycle case, +Shift+E to switch between Editing and Suggesting, +Shift+7/8, +]/[, +Enter, Shift+Enter, +K, +F, +H, Tab and Shift+Tab in lists and tables). Keys an editable document handles, including those the app also uses (Ctrl/Cmd+B, +J, +K, +\\, +,), are always consumed (`preventDefault`), so app shortcuts can check `defaultPrevented`. Commands are undo steps of their own. Pointer events drive resizing, so touch works.
- **Web chrome** (`apps/web/src/features/files/live/docx`), laid out as Google Docs' with Word's commands where Docs has none, on the shared [Editor chrome](./files.md#editor-chrome) (menus are data in `docx-menus.tsx`, unit-tested in `docx-menus.test.ts`):
  - **File**: the host's items, Page setup… (orientation, Word's paper sizes, margins with the Normal/Narrow/Moderate/Wide presets in inches or centimeters by the browser's region, lengths typed with their own unit such as `2.5 cm`, for the whole document or the cursor's section, writing only what changed, so other sections keep their own paper and margins when only the orientation changes; it explains and applies nothing while suggesting), Download ▸ Plain text (.txt) (accepted text, list labels kept, table cells tab-separated), and Print (Cmd/Ctrl+P).
  - **Edit**: Undo, Redo, Cut, Copy, Paste, Paste without formatting (Cmd/Ctrl+Shift+V), Select all (the document's text only, also when read-only, to copy), Find and replace. Menu Paste reads the async clipboard through `pasteData`; when the browser refuses, a toast points at Cmd/Ctrl+V.
  - **View**: Print or Web layout, Show outline, Comments, Review changes, Show markup, Show word count, Zoom (with Fit in print layout).
  - **Insert**: Image (PNG, JPEG, GIF, BMP; anything else gets a toast), the table grid (reachable with the arrow keys), Link, Comment, Horizontal line, Special characters, Header, Footer, Page numbers (top or bottom, left/center/right, or "Page X of Y"; at the cursor in an open header), Page and Section breaks, Footnote, Endnote, Table of contents. Headers, footers, and page numbers switch web layout back to print layout first; Header and Footer open the one the cursor's page shows, as Word's Edit Header does (a title page's own, created when missing).
  - **Format**: Text (bold to all caps, underline styles, font size steps), Change case, Paragraph styles (Docs' Normal text, Title, Subtitle, Heading 1–6 with Cmd/Ctrl+Alt+number, then the document's own), Align & indent, Line & paragraph spacing, Bullets & numbering, Paragraph borders, Paragraph… (Word's dialog: alignment, left/right and first-line or hanging indents, spacing before and after, line spacing as a multiple, exactly, or at least, and the line and page break options, in one undo step writing only what changed), the Table menu in a table, Clear formatting.
  - **Tools**: Word count (Cmd/Ctrl+Shift+C: pages, words, characters with and without spaces, paragraphs, for the document and the selection, with "Display word count while typing"), Editing mode, Review suggested edits (next, previous, accept or reject at the cursor, all), AutoFormat as you type, Keyboard shortcuts. AutoFormat and the word count are remembered per browser (`docx-preferences.ts`).
  - **Toolbar**: Docs' font size box (type a size; −/+ step through Word's sizes), the format painter (a click paints once, a double-click keeps it on until Esc), and Comment (Cmd/Ctrl+Alt+M), which opens the comments panel with a new comment box focused on the selection, as Docs does; its badge counts unresolved threads. For a read-only viewer it shows or hides the comments panel instead. In the panel, Cmd/Ctrl+Enter sends and Escape cancels, a click on a thread puts the cursor at its text, and your own comments (by name) can be edited. The review panel has Previous and Next change and shows dates.
  - **Status bar**: the cursor's page ("Page 2 of 5"), the word count ("12 of 345 words" with a selection; a click opens the dialog), the layouts, and the shared zoom control; Ctrl/Cmd+wheel or a pinch zooms around the pointer. Zoom belongs to the viewer.
  - **Right-click** over a table cell, a picture, a link, or a comment opens Pulpo's menu (Cut, Copy, Paste, then Open, Edit, or Remove link; Open or Resolve comment; table rows, columns, merging, and cell alignment; Delete picture). Elsewhere, over a read-only document's tables and pictures, and always with Shift, the browser's own menu stays, with its spelling suggestions or Copy image.
  - While a header or footer is open, a slim bar names it and offers Different first page, a page number at the cursor, Remove, and Close (Esc); in a narrow window its buttons show icons only. As in Word and Docs, turning Different first page on or off with a section's first page open keeps you on that page, editing the header it now shows (a new first-page header, or the regular one again). The status bar and Word count count the body's words while a header, footer, or note is open (`wordCount('body')`). With the caret in a link, Docs' link bubble shows where it goes (opening in a new tab), with Copy, Edit, and Remove.
  - Cmd/Ctrl+K opens the link dialog: with nothing selected it asks for the text to insert, an address without a scheme gets https://, `#Name` links to a bookmark, and with the caret in a link it edits or removes that whole link. Suggesting mode offers no link dialog, since Word revisions cannot track links. Cmd/Ctrl+/ lists the shortcuts (kept in step with the keymap by `docx-shortcuts.test.ts`), and Cmd+Shift+H replaces on macOS, where Cmd+H hides the app.

## Review diff

`revisions.ts` owns the semantic resolver used by the editor’s Accept all/Reject all, text extraction, search, word counts, and both sides of file review. `acceptedText` resolves a temporary document with accept-all; `baseText` uses reject-all. The shared engine handles run insertions/deletions, moves, paragraph boundaries, row/cell insertions/deletions, vertical cell merges/splits (including preserved continuation XML), and run/paragraph property changes. Paragraph joins retain the same paragraph/list/section ownership as the editor. Search maps projected positions back to editable source positions, including relocated rowspan cells, without per-character arrays. Projections are cached by immutable document node and never write to Yjs. Each agent file version uses its accepted projection; stored base and pending proposals therefore use the same semantics. Canonical source comparison still reports revision metadata and preserved changes that resolve to the same visible text.

`diffDocxFiles`, `diffDocxDocs`, and `diffDocxModels` compare two versions into a structured redline: paragraphs and table rows aligned, changed ones diffed word by word, added and removed ones listed, formatting changes on unchanged text noted by property, and changes to headers, footers, notes, comments, and styles. `DocxDiffView` renders it, collapsing unchanged runs. Resolved list labels participate in the comparison, including lists inside tables: changing only a numbering definition or start override produces a visible redline, with before/after labels reported as List formatting changes for body paragraphs. Equality uses canonical full node trees and ancestor properties, independently of the descriptions the current editor understands. Tables, rows, cells, story content and metadata, section properties, preserved XML, and picture asset hashes all participate. Known properties get specific notes (table/column/cell widths, borders, shading, alignment, story run formatting and picture changes); unexplained differences get **Formatting changed** or **Layout changed** at their structural location. Document-level settings and definitions also have fallback notes. File review additionally compares canonical XML and opaque binary part hashes, so content outside the modeled trees cannot disappear from review. Attribute ordering and Word session rsids do not count as edits. Long formatting lists can be expanded in the review UI.

## Testing

The semantic revision suite checks explicit expected results and seeded combinations of every supported revision type: accepted text equals plain extraction after the editor resolver’s accept-all transaction, and base text equals plain extraction after reject-all. It runs 24 trials by default and 256 with `PULPO_DOCX_FIDELITY=1`, including story/comment text, merged cells, formatting, and source-mapped replacement.

## Concurrent paragraph split limitation

`concurrency.test.ts` contains a deterministic two-replica reproduction, both with the Word schema and a minimal schema containing only `doc`, `paragraph`, and `text`. Starting from `abcdef`, two disconnected replicas splitting after `abc` converge to three paragraphs: `abc`, `def`, `def`. Splitting after `ab` and after `abcd` produces `ab`, `cdef`, `ef` with the test's fixed client ordering. Each local edit alone is correct; exchanging updates introduces duplicated text. Convergence does not imply that content was preserved exactly once.

The cause is the shared `@tiptap/y-tiptap` binding's `updateYFragment` / `createTypeFromTextOrElementNode`, rather than paragraph properties, marks, preserved XML, or the Word Enter command. Paragraphs own separate nested `Y.XmlText` nodes. A split keeps one side's original Yjs node and deletes text from it, then copies the other side into a newly allocated paragraph/text node. The replicas create independent copies; Yjs merges both insertions. Schema cleanup or deduplicating equal text cannot repair this safely: repeated text and concurrent typing can be intentional. It can happen while offline or under sync latency, without matching wall-clock timing, in body or story paragraphs. Markdown uses the same binding and representation.

A proper fix needs a binding and representation that preserves character identity across paragraph boundaries, such as a shared inline sequence with paragraph delimiters and anchored paragraph properties, or a move-aware CRDT/binding protocol. This is not a contained Word command change: it affects the codec/model, all structural editing and tracked changes, relative cursor positions, undo, web/mobile bundles, persisted Yjs snapshots and backups, and old clients. It requires versioning, migration, and mixed-client compatibility work. Until that is designed and verified, the deterministic characterization and randomized convergence tests document the remaining limitation; no text-deduplication heuristic is applied.

## Not supported yet

In rough order of importance:

- Suggesting section breaks, page setup, new or removed headers and footers, hyperlink changes (including AutoFormat links and lists), cell shading/borders/vertical alignment, header rows, table alignment, column insert/delete, cell merge, and cell split; these commands are disabled in Suggesting mode. Section property changes cannot be tracked as Word revisions here. Custom transactions that change columns are not tracked as column revisions. In Suggesting mode, a paste that replaces a whole paragraph's text or starts at the beginning of a paragraph keeps that paragraph's own mark (as Word keeps a paragraph mark when only its text is deleted), so accepting can leave an empty paragraph that Editing mode would have removed; selections that cross table cell boundaries are tracked cell by cell and can resolve differently from the same edit in Editing mode.
- Concurrent splits of the same paragraph can duplicate text after syncing, including edits made offline. This is a shared Yjs binding limitation, also affecting Markdown; see the deterministic reproduction and proposed fix above.
- Concurrent changes to the same section's properties (page setup, different first page, adding or removing a header or footer) keep only the last writer's; see the editor notes above for how an open header or footer is guarded.
- Multi-column sections render as one column (the setting is kept). Floating pictures wrap with CSS floats and page-relative positions are approximated against the paragraph. Text boxes, shapes, SmartArt, and charts show their fallback picture or a sized placeholder with their text; they cannot be edited.
- Table rows taller than a page are not split across pages. Pictures copied from another document are left out when pasted (their assets belong to that document); inserted pictures are PNG, JPEG, GIF, or BMP. Column widths cannot be dragged. Inserting columns spreads the grid evenly.
- Content controls show and edit their content but their properties (date pickers, drop-downs, checkboxes) cannot be changed in the editor. Fields other than PAGE/NUMPAGES/SECTIONPAGES and the TOC show their cached result and are not recalculated.
- No ruler, line numbers, page borders, watermarks, or drop caps (all kept). Pictures' alt text is kept but cannot be edited. Endnotes are drawn after the text without pagination of their own. Suggestions belong to their author by name, as in Word, so two reviewers with the same name can remove each other's suggestions as their own. Move revisions are shown and can be accepted or rejected per side, but moving text in Suggesting mode records a deletion and an insertion. Comments' text is plain when edited in Pulpo.
- Fonts render with the browser's fonts: Calibri, Cambria, and others fall back to metric-compatible open fonts when installed (Carlito, Caladea, Liberation), else to similar system fonts, which can move line and page breaks.
- Strict Open XML documents are refused.

Settings discoverability/usability sweep for PR782

Problem and feature
The actual list was reachable at largest system text size on the assigned iPhone 18 Pro (402x874 points). First observations from home top showed language after 3 full swipes, one-handed after 11, learning/privacy after 16. The previous bounded six-scroll failure is not evidence of a product reachability defect.
The candidate adds Find Setting, a native toolbar menu that scrolls to the existing language, one-handed, and learning rows. Each destination takes 2 taps with 0 manual scroll gestures. Controls, values, bindings, reset/clear confirmations, and local draft ownership remain the existing ones. It is selective navigation, not comprehensive settings search.
The initial long menu labels passed interaction tests but crowded/clipped the final label in a screenshot. Labels were shortened BEFORE final source freeze, independent source review, and blind reveal. The final largest-type native test verifies target visibility/hittability, defaults, subsequent bilingual/Right selection, jumps, cancellation, and retained values. Complete concise-menu rendering was also visually inspected.

Frozen/independent procedure
Development intents were saved before relevant source inspection (exact hash in freeze-receipt.json). The original internal R26 label is historical and not a reference to another agent's R26 work.

The blind author saw only exact frozen contract/schema/capability/executor bytes and hashes. A second independent agent strictly validated all 99 actions in 5 cases before sealing. A third fresh agent reviewed only frozen candidate source/development evidence, never the sealed payload. Source review approved with limits. The payload was revealed once after source review and the exact final candidate's largest-type pass. No production, contract, schema or fixture edits followed reveal.
The blind executor uses existing scrolling and settings actions only. It does not exercise the new menu. Its paired outcomes are regression evidence, not proof that blind users discover the shortcut or that typing accuracy/Gboard performance improved. Every command, including any failed or unavailable command, remains in the denominator. Frozen label assertions use substring checks; an additional post-reveal diagnostic compares every recorded settings readback against its exact full expected label. This strengthens the raw-value audit without changing frozen scores or code.

Files and reproduction
SettingsUsabilityContractTests.swift is the exact frozen executor, archived outside the ordinary UI-test target. Its original path in historical receipts was UITests/SettingsUsabilityContractTests.swift; the bytes/hash are unchanged. replay.py verifies those bytes and the sealed payload, injects the executor temporarily into an explicit checkout, generates that checkout's Xcode project, runs serialized native XCTest with UUID pinned to 7E1D7979-7307-4C53-8466-BB41154B383C, preserves every outcome, removes only its temporary executor and restores the original content size. Use a unique label per run:
  python3 apps/keyboard-ios/benchmarks/settings-usability-sweep/replay.py --checkout /absolute/path/to/isolated/checkout --label unique-parent-check
Only run while owning this device. Settings-only execution does not change hardware keyboard state. The helper intentionally does not boot/reset/delete devices or alter global Simulator preferences.
Raw logs, result bundles, screenshots and DerivedData are local under /tmp/pulpo-settings-usability-sweep. No generated projects, caches, dictionaries or corpora are archived in this change. Successful raw logs were not read; only structured reports were read. Raw error lines were read after indicated failing command output.

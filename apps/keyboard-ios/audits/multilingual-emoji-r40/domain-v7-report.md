## Arbitrary-domain source argument

The baseline sources were obtained from commit 00e2a0e7a283bc4a780b02f847ea9d82dfe9e5ae and compared byte-for-byte with the current production files. EmojiCatalog.swift SHA256 c7f929ada6398c9c849e1b764e7bdacc3aca6956f3444fa74953db43cea5468e; EmojiSearch.swift SHA256 b31bb9dfd4f0eaca8e7c71e5d5779d43a2e60649067b9a78ac6b0b12bc5b7d47. Their complete English bodies are unchanged in the harness.

The relevant Swift semantics are Character sequences, canonical Character/String equality, and hasPrefix over corresponding extended grapheme clusters. These are documented by [Swift's language guide](https://docs.swift.org/swift-book/LanguageGuide/StringsAndCharacters.html#Comparing-Strings) and [Apple's hasPrefix documentation](https://developer.apple.com/documentation/swift/substring/hasprefix(_:)). The installed Swift interface also exposes the generic StringProtocol hasPrefix as starts(with:); the concrete String overload is opaque there, so the executable challenges exercise that concrete overload.

Let D be exactly the ASCII space Character. Splitting an equal Character sequence on D yields equal subsequences, including the same positions of omitted empty pieces. Constructing Strings from those subsequences and applying Set equality preserves canonical equality. Thus foldedName(entry.name)==foldedName(query) implies F(entry)==X(query). This argument never applies Foundation normalization to an already folded name. A space plus a mark or Prepend plus a space can be a different Character; it is then not D in either equal sequence. Canonical musical spellings preserve this literal split even when Foundation's later scalar classification would differ.

For the prefix lemma let p be a nonempty normalized query and k.hasPrefix(p). In the Character sequence model, p is an initial segment of k. Each D delimiter inside p is the same delimiter at the same position in k. Every nonfinal word in p is therefore a complete word in k; its final word is either complete or an initial segment of a word in k. A terminal D merely completes the preceding word. Consequently every word in p prefixes a D-split word of k. The first word of p also prefixes k itself: normalization's split(whereSeparator: isWhitespace) removes initial whitespace Characters and joins nonempty pieces, so its nonempty result cannot start with a standalone D. Embedded space scalars in other graphemes do not count as D. Taking Set/deduplicating the words changes none of these witnesses. This proof applies to arbitrary lengths and sequences within the public input guards, rather than extrapolating from scalar enumeration.

The prefix lemma supplies both the existential W/B anchor and every nonignored W/V witness. V must include the retained key's literal-space words and the whole compact key. The 3...80 key guard, ignored-key filter and 12-per-key truncation occur before B is observed.
3. Fallback starts with the union of per-word collect posting members for nonignored W words. Its 800-candidate cap only removes candidates. Its all-words check is already exactly against unchanged searchWords, a subset of V. The originating per-word collect supplies the existential anchor. Repeated query words do not change the truth of either condition.

No other search membership insertion exists. Query/limit guards remove all results as applicable. Search-text filtering, binary-search behavior, early fallback suppression, ordering, preference clamping and final min(limit,60) truncation cannot add another entry. Empty W means normalized query is empty and legacy search returns none before exact lookup; the specified empty envelope is therefore safe. Technical exact winners and one-character names need no posting witness. All public preference maps and signed limits preserve this reasoning.

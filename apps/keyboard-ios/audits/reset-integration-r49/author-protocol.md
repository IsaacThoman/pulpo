# R49 fresh author protocol

Use only the separately approved R48 `public-domain-v3.md`, clean
`PublicDomainReference.swift`, this document, and the independently approved
R49 generic runner/API schema. Do not read product source, dictionaries, old
case payloads or product outputs. Foundation-only reference calculations and
inert declaration-only typechecking are permitted; no product API execution.

Author a compact new public TouchModel compatibility workload with at least
12 intent families and 16 local/persistent instances. Declare which checks are
correlated. Include nonvacuous accepted controls, target-length versus actual
contribution boundaries, sparse and expanded Character alignment, finite and
ignored displacements, settled invalid-call conservation, explicit learning
policy, synchronous save/reopen and meaningful full-state cross-mode relations.
Keep all public-domain semantics unchanged. Orthographic variety does not imply
distinct language-model resource modes in this pure model API.

Use the approved runner unchanged. Its wire format is a shared versioned format;
the environment's version label and frozen input hashes identify this new round.
Propose fixture/schema/evaluator artifacts separately. Any required runner change
must return to independent mechanics review before product execution.

The runner accepts a JSON object with `operations`, an ordered array of objects:

- Every operation has unique `id`, `op`, and object `input`.
- `center`: `input.byte` is a declared ASCII letter byte; output supplies that
  letter's geometry for later relative taps.
- `normalize`: `input.text` is a literal string.
- `construct`: unique `session` plus `input.persistent` Boolean.
- Subsequent model operations name the existing `session`.
- `setLearning`: explicit `input.value` Boolean. Establish policy before relying
  on it, including after reopening; no unspecified constructor-policy oracle.
- `learn`: literal `input.text`, `input.target`, ordered `input.taps`. Each tap is
  null, `{base, dx, dy}` using a previously observed center, or `{x, y}`. Direct
  nonfinite numbers use the explicit `nan`, `posInf`, `negInf` string tags.
- `save`, `reload`, `observe`, `reopen`: empty input objects.

Output records retain exact inputs/resolved inputs, invocation, availability,
return, last-operation status, full weight and all 26 two-dimensional offsets,
regular-file content inventory and explicit error. An unavailable observation is
never a zero state, expected invalid rejection or success. A false reload with
status ok can be a valid unchanged observation. Successful transport is separate
from a complete passing workload. Save is synchronous; each persistent instance
uses fresh unique storage. No concurrent work or automatic mutation retry.

Freeze every literal/relational oracle before execution, with finite strict JSON,
unique complete IDs, declared numeric tolerance, full-state comparisons and
meaningful accepted references. File-invariance claims must obey the public
domain's settlement limits. Account separately for families, instances, checks,
actual calls, unavailable/unfired actions, expected invalid rejections and statuses.
Enforce relations; don't merely label them. Reject missing, extra, duplicate,
corrupt, nonfinite or input-mismatched output under normal and optimized Python.

Deliver immutable fixtures, schema, evaluator, reference assumptions, synthetic
adversarial checks and execution instructions with hashes and declared counts.
Metadata may reveal counts and bindings while the parent keeps the fresh payload
unopened. Parent checks exact duplicate programs against previously revealed
inputs without using product answers to select cases. Exposed repeats cannot
support novelty claims.

Independent review checks every oracle, action binding, relationship and strict
accounting rule. Both compiled binaries, environment, source, runner, inputs,
evaluator and approvals are frozen before one new paired execution. Preserve
every failed/unavailable result. No post-reveal source/runner/input/oracle tuning
or rerun can admit that round, including when a later review finds a harness or
oracle fault. No population accuracy, native performance, durability beyond the
executed actions, or overall Gboard advantage is implied by a passing workload.

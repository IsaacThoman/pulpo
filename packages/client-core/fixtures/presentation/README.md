# Presentation fixtures

Test corpus for the PowerPoint (.pptx) engine. Tools that read, compare and render
these files live in [`../../test-tools/presentation`](../../test-tools/presentation/README.md).

| Folder | What | Regenerate |
| --- | --- | --- |
| `poi/` | Microsoft-authored files from Apache POI's test data | copied as-is |
| `generated/` | Decks written with python-pptx (plus targeted XML) | `generate_fixtures.py` |
| `libreoffice/` | Generated decks re-saved by LibreOffice 26.8 | `generate_fixtures.py --libreoffice` |
| `hostile/` | Malformed and malicious packages | `generate_hostile.py` |

Regenerating rewrites the files byte-for-byte except embedded chart workbooks
(XlsxWriter timestamps them), LibreOffice's own metadata, and the encrypted file
(random salt). The big performance deck is not committed:
`generate_fixtures.py --big 200 --big-out /tmp/pulpo-big-deck.pptx`.

## libreoffice/

The generated decks above, converted by `soffice --headless --convert-to pptx`
(LibreOffice 26.8.2.2, macOS). LibreOffice rewrites the whole package: placeholders
become explicit shapes with resolved properties, layouts are reordered, shape ids are
renumbered, `docProps/custom.xml` is added and the thumbnail dropped, and preset
geometries/effects are re-expressed in its own way. Useful for "foreign writer" input.

| File | Source |
| --- | --- |
| `lo-text-formatting.pptx` | `generated/text-formatting.pptx` |
| `lo-autoshapes.pptx` | `generated/autoshapes.pptx` |
| `lo-tables.pptx` | `generated/tables.pptx` |

## hostile/

Written by `test-tools/presentation/generate_hostile.py`. None should open normally;
each must fail with a typed error in bounded time and memory, or degrade gracefully.

| File | Contents | Expected engine behavior |
| --- | --- | --- |
| `zip-bomb-overlap.pptx` | Valid deck plus 12 central-directory entries sharing one deflate stream of 64 MiB of zeros: ~94 KB file, 768 MiB declared and actual | Reject on declared size (`too_large`) |
| `zip-bomb-understated.pptx` | Same overlap, but every bomb entry declares 1 KiB uncompressed | Must not inflate 768 MiB; fflate's `unzipSync` currently inflates all of it (~1.5 s CPU) and silently truncates each entry to the declared size |
| `zip-bomb-declared-size.pptx` | One entry declares 700 MiB but inflates to 16 bytes | Reject on declared size without allocating it |
| `deep-nesting-groups.pptx` | Slide with 100,000 nested `p:grpSp` (same id) around one shape | No stack overflow; depth limit or parse error |
| `deep-nesting-xml.pptx` | Slide `p:extLst` holding 100,000 nested unknown elements | No stack overflow while parsing or round-tripping unknown XML |
| `xml-entities.pptx` | Slide 1: "billion laughs" internal entities; slide 2: external entities `file:///etc/passwd` and `http://127.0.0.1:9/…` | No entity expansion, no file or network access |
| `missing-parts.pptx` | Picture rel to a missing media part; slide without a layout rel and with an undefined `r:embed`; missing notes and chart parts; `sldId` with an unknown `r:id`; slide rel to a missing part; content-type override for a missing part | Open, show placeholders for missing pieces |
| `rels-path-traversal.pptx` | Image rels to `../../../etc/passwd`, `/etc/passwd`, deep `../`, backslashes, percent-encoded `..`, external `file://` and `http://127.0.0.1` links, `javascript:` hyperlink; zip entries named `../../pulpo-zip-slip.txt` and `/tmp/pulpo-absolute-entry.txt` | Resolve only inside the package, never read files or fetch URLs, never write outside |
| `cyclic-references.pptx` | SmartArt frame whose diagram rels all point at the slide itself; picture whose image is the slide part; group, nested group and child sharing one id; connector glued to itself; slide whose layout is itself; layout → "master" layout → layout cycle | Terminate (cycle detection), no infinite recursion |
| `huge-values.pptx` | `sldSz` 2³¹−1, invalid `notesSz`; shapes with int32 max, int64 overflow, negative, `NaN`/`Infinity`/hex extents, max rotation, max font size and spacing, invalid `flipH`; group with zero `chExt` (divide by zero) and with 1-EMU `chExt` (2³¹ scale); 1000-column table of 1-EMU columns with 2³¹ row height; custGeom with 2000 points and a 2³¹ arc | Clamp or reject values; no NaN coordinates, no huge allocations |
| `duplicate-slide-ids.pptx` | Two `sldId` with id 256, one slide listed twice, an id below 256; three shapes with id 2; two relationships with the same `rId1` | Deterministic choice, no crash, unique ids on save |
| `duplicate-zip-entries.pptx` | Two zip entries named `ppt/slides/slide1.xml` with different content and a case-variant `ppt/slides/SLIDE1.xml` | Reject as corrupt or pick one deterministically |
| `missing-presentation-xml.pptx` | Valid package without `ppt/presentation.xml` | `corrupt` error |
| `missing-content-types.pptx` | Valid deck without `[Content_Types].xml` | `corrupt` error |
| `wrong-main-content-type.pptx` | Main part labelled as a Word document | Reject as not a presentation |
| `truncated-zip.pptx` | First half of a valid deck (no central directory) | `corrupt` error |
| `not-a-zip.pptx` | Plain text and bytes with a `.pptx` name | `corrupt` error |
| `encrypted-password-pulpo.pptx` | Real Agile-encrypted package (CFB container), password `pulpo`, made with msoffcrypto-tool | `encrypted` error |
| `legacy-ppt-renamed.pptx` | CFB header with legacy PowerPoint stream names, as a renamed `.ppt` | `encrypted`/legacy error |

`generate_hostile.py --extra DIR` also writes, outside the repo, a package with
20,000 entries (`too-many-entries.pptx`) and a 4 GiB overlap bomb.

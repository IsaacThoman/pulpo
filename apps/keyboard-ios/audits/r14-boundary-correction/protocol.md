# R14 boundary correction frozen development protocol

Frozen before reading KeyboardEngine/controller implementation. Base: 8c7d00a2. Prior R11 revealed cases and rejected broad literal-token experiment are development evidence only; do not count as independent held-out improvement. No dictionary edits or word exceptions.

Goal: permit ordinary correction of a newly typed complete word before an existing word, while preserving genuine inside-word edits. The initial full document, caret and explicit user task define intent; expected text is never used to infer intent. Identical observable input with different intentions is ambiguous and diagnostic only. Exact literals retain punctuation, casing and bytes. Preserve all existing prefix/suffix and selection remainder, allow only intended replacement. Cases use Unicode character offsets.

Frozen dev.json covers EN, ES, bilingual, new boundary words, fragments, literals, caret changes, selection replacement, correction Undo, privacy/field policy. Every case runs actual KeyboardEngine handleCharacter/handleSpace, comparing exact full document under immediate proxy, delayed optimistic own-state proxy, and delayed reports that flush during input. Harness can correct demonstrable fixture transcription mistakes before baseline execution only, with a recorded addendum; never silently redefine expected after observing output. Ambiguities remain visible and outside accuracy denominators.

Lifecycle actions: initial document/caret/selection; type characters (space through handleSpace), optional move relative by Unicode offset, select absolute, flush reports, backspace-based correction undo. Field variants normal/email/url/number/password. Delayed mode applies writes to true document immediately but proxy reports remain frozen until flush. Intentional host edits must report changed context; known identical old/new proxy context ambiguity remains unreconstructable, not a novel gain.

Select at most one general source candidate on development. Require actual fresh-word improvement and zero new failures of unambiguous development conservation/fragment/literal/selection/undo/privacy gates, plus core/data checks. Existing failures remain failures and must be disclosed. Reject unsafe candidate; do not tune after held-out reveal. Freeze candidate source SHA256 and Git tree/commit before revealing independent held-out cases. Evaluate held-out once with same harness for baseline vs frozen candidate; report exact before/after denominators per timing and category, all failures and ambiguities. Passing report generation is not accuracy acceptance. No cherry-picking or aggregate hiding.

Independent author receives contract/exclusions only and writes sealed cases externally, reporting count/hash only. No dev cases, failures, implementation or candidate shared. Version synthetic inputs, executable benchmark, compact per-case reports/hashes and audit. Keep full result bundles/build logs outside Git. No deployment, device use, push, or source changes in parent checkout. After core selection inspect actual UIKit controller tests for meaningful coverage without devices; retain unavailability reasons. Obtain independent source review after freeze, with no repair round after reveal. Conventional Commits. Record elapsed timings and delegated work/cost limitations.

Pre-execution fixture addendum: manually recomputing character offsets corrected move-away expected text to use tehtax il next. Reading the existing Undo contract showed Backspace restores the typo WITHOUT its separator; undo-fresh now expects join tehmeeting. These changes precede any benchmark execution. Automatic capitalization is disabled through InputTraits.capitalization = .none in this correction-focused harness; smart quotes and double-space settings remain defaults. This isolates correction while preserving raw-case input intent.

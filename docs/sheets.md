# Spreadsheets

Spreadsheets (`.xlsx`, `.xlsm`, `.xltx`, `.xltm`, `.csv`, `.tsv`) are a live format: a file opens as a collaborative Y.Doc that people and agents edit at the same time, and it is written back as a real file for downloads, agent `pull`, and exports. Everything lives in `@pulpo/client-core/office/sheets` (codec, model, formula engine, number formats, charts, diff) and `@pulpo/client-core/office/sheets/view` (the editor core). The web editor is `apps/web/src/features/files/live/sheets/`, and the mobile app's is `apps/mobile/editor/sheet/`. It's the `sheet` format of the [live formats](./live-formats.md) catalog, so Files creates, converts, syncs, exports, and hands spreadsheets to agents like any other live document (see [Files and agents](#files-and-agents)).

## The collaborative model

The layout is in `office/sheets/model/schema.ts`. Its design follows from two requirements: concurrent edits must keep their intent, and nothing in a file may be lost.

**Rows and columns have stable ids.** Each sheet keeps the order of its rows and of its columns as a `Y.Array` of ids (`model/axis.ts`). Cells, formats, notes, links, merges, rules, and drawings refer to rows and columns by id, never by index. So when one person inserts a row while another types further down, the typed cell moves down with its row instead of being overwritten; a deleted row takes what was in it along. Rows nobody has touched are not stored: the axis continues past its end with *virtual ids* (the decimal numbers after the highest one used), so a formula can name row 5000 of a 100-row sheet before that row exists, and still finds it once someone stores it. Two replicas that store the same virtual ids at once each append a copy; the first copy wins, and rows inserted right before the losing copy move to just before the winning one, so an insertion lands where it was made. Storing happens in chunks (1,024 rows, 64 columns, and the first chunk when a sheet is created) so this is rare. Deleted ids are tombstoned with the index they had and the ids of their surviving neighbors, so they never come back and a reference to a deleted range edge resolves to the neighbor that took its place, even after other deletions.

**Formulas are stored by id.** A formula's references are written as tokens naming the sheet, row, and column ids (`⟦s:…;r:…;c:…;R:…;C:…⟧`, `model/formula-ids.ts`), and turned into A1 text for display, calculation, and export. Inserting, deleting, or moving rows and columns and renaming sheets never rewrites a formula (in cells, defined names, conditional formats, or validations), even one typed concurrently elsewhere. The two ends of a range resolve together, from current positions and the neighbors each tombstone recorded, never from indexes recorded when they were deleted. References resolve through axis tombstones: a deleted range start takes the next surviving neighbor and a deleted end the previous one, shrinking the range as in Excel; reversed ranges shrink toward their surviving interior and remain valid after moves. A deleted single-cell reference, a neighbor cycle with no surviving boundary, or a range whose rows or columns are all gone becomes `#REF!`.

**Sheet names and visibility resolve on read.** Concurrent additions or renames keep their stored names. In tab order, the first live sheet with a name keeps it (compared case-insensitively), and subsequent sheets get ` (2)`, ` (3)`, and so on, truncated to Excel's 31-character limit and skipping names already reserved by other live sheets. All model readers, formula conversion, calculation, exports, and tabs use these resolved names; formulas retain their original sheet ids.

**Deleting a sheet keeps a tombstone.** Its sheet map gains `deleted: true`, while its id stays in the tab order and its cells and scoped defined names stay stored. Readers skip deleted sheets and their scoped names. If every ordered sheet is deleted concurrently, the first one counts as live with its contents and names intact. If every live sheet is hidden, the first live one counts as visible. These fallbacks are derived without writing repairs, so replicas converge regardless of update delivery order. Older documents have no `deleted` flags and need no migration.

**Defined names resolve on read.** Each case-insensitive name and sheet scope has one live definition, chosen by the smallest storage key when older documents contain duplicates. Calculation, formula conversion, export, and the name box share this accessor. Applying a file updates existing definitions under their existing keys; concurrent additions use a deterministic key from the scope and lowercased name, so their values converge through Y.Map conflict resolution.

**Every property is its own map entry.** A cell's content (`cells`), its base format (`xf`, an index into the workbook's stylesheet), and each style override (`fmt`, keyed `row:col|prop`) are separate entries, as are row and column properties. Two people editing the value and the color of a cell, or making a range bold while another fills it yellow, both keep their change. The stylesheet itself (`styles.xml`) is kept as read; edits are overrides on top of it, and on export each distinct format-plus-overrides gets one new `xf`, appended, so formats nobody touched keep their indexes.

**What isn't modeled is kept.** Each worksheet keeps its XML as a skeleton without the parts the model owns (cells, columns, merges, conditional formats, validations, links, filters, tables, legacy drawings); on export the model's parts are put back in schema order and the skeleton supplies everything else (sheet protection, print settings, page setup, `extLst`, `mc:AlternateContent`, unknown elements and attributes). Rows, cells, formulas, columns, styles, and rich-text runs keep their unmodeled attributes and children. Every package part the export doesn't rebuild is kept byte for byte in the asset store (themes, VBA projects, pivot tables, external links, custom XML, printer settings, chart parts). Parts no longer referenced after deleting sheets or objects are dropped; parts the file already had loose are kept.

## Codec

`SheetCodec` implements `LiveFormatCodec`:

- **Import** (`codec/read-xlsx.ts`, `read-worksheet.ts`): sheet data is parsed by a small streaming parser (`light-xml.ts`) a row at a time, since a DOM for millions of cells would cost too much; the rest goes through `@xmldom/xmldom`. Shared formulas are expanded with their references moved; array formulas keep their cached results on the anchor (`spillCache`); data tables are kept exactly. Strict OOXML is refused (`unsupported`), encrypted files and legacy binaries (`encrypted`), anything malformed (`corrupt`), and workbooks past 2,000,000 cells (`too_large`). DTD entities are never expanded.
- **Export** (`write-xlsx.ts`, `write-worksheet.ts`): rebuilds the workbook, worksheets, shared strings, styles (only when edited), comments, the notes' VML, drawings, and tables; patches content types and relationships; and drops the calculation chain (Excel rebuilds it). Saving a macro-enabled workbook as `.xlsx` drops its macros, as Excel does. `vbaProject.bin` is kept and never run.
- **applyFile** (`apply.ts`): imports the new version into a scratch doc and rewrites the live doc to match with the fewest changes, in one transaction: sheets are paired by name, part, or position; rows and columns inserted or deleted in the new version are found by diffing their contents (`diff/sequence.ts`, Myers) and inserted or deleted here, for every sheet before any content is compared; cells are written only where they differ (formulas compared as A1 text, styles by what they look like, the new stylesheet merged into ours). Applying the file the doc would export changes nothing.
- **CSV and TSV** (`csv.ts`): one sheet of values. The delimiter (sniffed for `.csv`), quoting, encoding (UTF-8, UTF-16 with a byte order mark, Windows-1252), byte order mark, line endings, trailing newline, and ragged rows are kept, and fields nobody edited are written with their exact text (`007`, `1.50`). Formulas typed into a CSV are kept as text.
- **toText**: each sheet's values as displayed, tab-separated, then its formulas as `B7: =SUM(B2:B6)` lines, for agents, search, and grep. CSV files read as themselves.

## Calculation

`formula/` is the engine, `SheetCalc` (`calc.ts`) binds it to a workbook, and views, `toText`, and exports read values through it.

- **Grammar**: Excel's formula language in full: operators with Excel's precedence (including `%`, `^`, `&`, the range, union, and intersection operators), A1 and whole-row/column references, 3D references (`Sheet1:Sheet3!A1`), defined names (workbook and sheet scope), structured references (`Table[[#This Row],[Qty]]`), array constants, `LET` and `LAMBDA`, and error literals.
- **Functions**: 404, from `SUM` to `XLOOKUP`, `FILTER`, `SORTBY`, `UNIQUE`, `SEQUENCE`, `TEXTSPLIT`, financial, statistical, engineering, and database functions, with Excel's coercion rules. `formula/functions/docs.ts` describes each for autocomplete and argument hints. Unknown functions and external references keep the values cached in the file. Local edits mark file caches dirty. The first dirty metadata change, including one received from another replica, fully recalculates supported formulas in the live calculator; later structural rebuilds also refresh them. Exports and text use the document’s calculation time, the editing client’s UTC offset, and seeded randomness for stable checksums; yearless dates use that snapshot’s calendar year. Imported snapshots without an offset calculate in UTC and retain unedited file caches. The live view uses the current local time and randomness.
- **Dependencies and recalculation**: a dependency graph (ranges indexed once per rectangle, run-time references from `OFFSET` and `INDIRECT` recorded as read), incremental recalculation of what changed and depends on it, volatile functions (`NOW`, `RAND`), and circular references (0, or iteration when the workbook enables it).
- **Arrays**: dynamic arrays spill into empty cells (`#SPILL!` when blocked), and are written back with the dynamic-array metadata Excel needs; legacy array formulas keep their range. Intermediate arrays are limited to 1,000,000 cells; a recalculation stops after 50,000,000 work units and keeps pending values, and circular calculation runs at most 1,000 iterations. Formulas read from a file without the dynamic-array flag keep pre-365 implicit intersection.
- **Number formats** (`numfmt/`): Excel's format codes in full: sections and conditions, colors, digit placeholders, thousands and scaling commas, percent, scientific, fractions, dates and times (1900 and 1904 systems, elapsed time, fractional seconds), text sections, fill and padding characters, and the built-in formats. `TEXT` uses the same formatter.
- **Range dimensions**: whole-column and whole-row references keep their full logical bounds even when blank tails are omitted from storage. Lookups, conditional aggregates, paired statistics, array operators, and spill sizing use those bounds and read omitted cells as blanks. Uniform tails stay compact through arithmetic and scalar functions. Operations that require a dense result check the existing array/work limits before expanding it. Text joins include omitted blanks and their delimiters, measure repeated tails before allocating strings, and enforce Excel's 32,767-character result limit. `forEachLogical` visits logical cells in row-major order, optionally weighting uniform tail runs; reductions must honor those weights. Use `logicalSize`/`matrixGet` for dimensions and point reads, `alignedRanges` for paired ranges, and `denseRange` only for algorithms that require every cell. Direct storage reads are limited to operations that preserve the tail (mapping/transposing), explicitly bounded dense matrices, and prefix algorithms that separately account for omitted runs.
- **Agreement with Excel**: the corpus test recalculates every cached formula value in the Excel-saved fixtures from scratch: 2,202 of 2,236 (98.5%) agree. The rest are edge cases in Apache POI's test sheets (external workbook references, error precedence in a few functions).

Charts (`chart/`) are parsed from DrawingML (bar, column, line, area, pie, doughnut, scatter, bubble, and radar, including stacked, percent, and 3-D variants drawn flat) and drawn as SVG overlays from the live values, so they follow edits. Other chart types (stock, surface, pie of pie) show as a placeholder, and every chart part is kept as written.

## Editor

The editor core (`view/sheet-view.ts` and its helpers) is framework-free: web and mobile web views share it. It takes `{ container, doc, awareness, readOnly, assets, user, labels }` plus optional calculated values, function documentation, and a chart renderer, and exposes commands (`setStyle`, `toggleStyle`, `merge`, `insert`, `deleteLines`, `freeze`, `sort`, `toggleFilter`, `setNote`, `setLink`, `find`, `replace`, `undo`, sheet operations, …) and `getState()`/`subscribe()` for toolbars.

- **Rendering**: a canvas sized to the viewport at the device pixel ratio, redrawn per frame, under a native scroll container (so trackpads and touch scroll natively). Only visible cells are drawn: frozen panes as separate clipped panes, fills, gridlines, Excel's border styles, text with alignment, indent, wrapping, rotation, overflow into empty neighbors, `####` for numbers that don't fit, rich-text runs, merges, conditional formats (fills, fonts, color scales, data bars, icon sets), notes markers, filter buttons, and validation list arrows. Column widths use Excel's character units and maximum digit width, so they match Excel. Images and charts are positioned overlays. Light and dark palettes; in dark mode automatic text and black borders follow the theme, except that automatic text on a light fill stays dark.
- **Editing**: an always-focused hidden textarea takes typing (and IMEs and mobile keyboards) and becomes the in-cell editor; Enter, Tab, Escape, F2, Alt+Enter, Ctrl+Enter, arrow-key commit and pointing, F4 to cycle absolute references; formula autocomplete, argument hints, and colored references; clicking or arrowing inserts references while a formula is typed; data validation is enforced on commit.
- **Selection and navigation**: ranges, multiple ranges with Ctrl/Cmd, whole rows and columns, Shift and Ctrl+arrows (data edges), Home/End, PageUp/Down, Tab/Enter flows inside a selection, the name box (cells, ranges, `Sheet!A1`, defined names).
- **Clipboard**: copies put tab-separated text and an HTML table (with styles) on the clipboard, plus this app's own snapshots so pasting here keeps formulas and exact formats; pastes from Excel and Google Sheets read their HTML (inline styles and Excel's class styles) or text. Paste values only and formats only.
- **Fill**: the fill handle and Ctrl+D/Ctrl+R continue series (linear trends, dates by day or month, text with numbers, day and month names) or copy with references moved.
- **Structure and format**: insert, delete, hide, resize, and auto-fit rows and columns; merge and unmerge; freeze panes; fonts, sizes, bold/italic/underline/strike, text and fill colors from the theme palette, border presets, alignment, wrapping, number formats (menu and custom codes), decimals.
- **Data**: stable multi-key sort (numbers, text, booleans, stable errors, blanks last in either direction), optional case sensitivity, autofilter with value lists and search, find and replace (values or formulas, one sheet or all). `sortRange` accepts worksheet-column keys and `SortOptions`; `SheetView.sort` accepts explicit `header` and `caseSensitive` options, and `sortArea` is the common toolbar/filter-menu entry point. Known filter/table headers stay put; text-over-numeric or bold headers are inferred for ordinary ranges. All-text ranges can use explicit header selection. Text collation uses the host locale, with lowercase first for case-sensitive ties, following [Excel's sort options](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel).

Sort safety checks run before writes. Spilled/legacy arrays, opaque What-If data tables, differently sized merged cells, selections crossing table boundaries, and opaque filter kinds being edited are refused. Equally sized merged records sort together. Table sorts expand to the table's data columns and exclude headers/totals. Conditional formatting, data validation, row heights/styles, outlines, drawing anchors and multi-cell hyperlinks stay positional; cell styles, notes and single-cell links follow records. Manually hidden rows participate in sorting and their hidden state follows the record, as confirmed with LibreOffice.

Same-row relative references follow records; absolute references inside the data stay positional. Cross-row relative references inside the sorted rows keep their original offset, including running-total range endpoints. References to rows outside the sorted data and to other sheets retain their identities. A real Basic/UNO LibreOffice sort verifies cross-row references, running totals, qualified same-row references, absolute outside references, hidden rows, heights and positional CF/DV. Formulas and defined names outside the sorted records keep their worksheet coordinates. Calc's `BindFormatsToContent=false` is used for positional validation ranges. Calc normally shifts relative references outside the selection too; Pulpo deliberately retains those outside identities according to its collaborative record model. Filtered formulas are allowed and predicates are recalculated after relocation.

Value-list filters combine columns with AND. Filter-hidden row identities and per-row manual-hiding provenance are kept separately; sorting recomputes value predicates from the current records and moves filter visibility in the same undo step. Clearing/reapplying a filter preserves manual hiding. Imported value filters infer hiding provenance from the stored visibility and displayed predicates; Standard XLSX row attributes do not separately record a row that was both manually hidden and excluded by a filter; a namespaced autofilter extension preserves that provenance for Pulpo-generated files, including file application and restore. Foreign files without the extension retain the import ambiguity. Unsupported custom/date-group/top-10/color filters remain opaque and their editing/sorting is refused. Moving actively filtered cells to other rows or sheets is refused until filters are cleared, because row visibility would affect unrelated destination cells. Sort state follows complete range/table cut moves; partial moves drop descriptive plain-sort state. Sort state is exported in worksheet/table XML, replaces stale imported conditions, preserves filter extensions in schema order, and survives import and file application.

Sorting works in shared views. When the selection covers every cell with content, style or annotations in the reordered rows, sorting permutes row identities. Concurrent edits therefore stay with their record; concurrent sorts resolve duplicate IDs with the axis's first-occurrence-wins rule. Two-document tests cover sorts racing cell edits, row inserts and other sorts. If content exists beside the selection, sorting rewrites a snapshot of the selected cells and leaves that adjacent content in place. This bulk edit has paste semantics: a concurrent edit to a moved cell can land at its old position or lose to the bulk write. Presence or exclusive locks are not required. Sorts undo in one step, run synchronously, refuse nested transactions or selections over one million cells, and abort if the workbook changes during preparation. The Chromium sheet suite exercises filter-menu sorting in a shared awareness session; the table-driven audit also covers formulas, metadata, XML round-trips and file application.

Spreadsheet schema version 2 adds stationary worksheet-slot axes (`sheetPositions:<sheet-id>` and `sheetDeadPositions:<sheet-id>`). Positional anchors use `~p<slot-id>` tokens, so concurrent row permutations cannot choose different winners for content and metadata. Formula relocation is held separately in `raw.sortFormula:<cell-key>` and gated on the original Yjs cell Item: concurrent replacements take precedence. Cross-row offsets use `~r<record-id>_<offset>` until a structural edit freezes them into ordinary references. Undo carries gates through Yjs redo lineage. Engine integrations must read effective content through `SheetModel.cell`, `cellData` or `forEachCell`, use `rowProp`/`rowMetaPosition` for row properties and `linkAt` for positional range links, and include the slot axes in custom undo scopes (the shared view does this). Existing version-1 documents acquire slots lazily; older editor clients cannot join version-2 sessions. Metadata objects retain normal Yjs last-writer merge semantics: editing the same CF/DV object concurrently with its initial positional reanchoring can lose one of those object edits. Cell replacements are protected by their version gates; formulas authored concurrently with an unseen sort retain their author’s reference identities. No LiveFormatCodec or asset-store contract changed.

## Selection command safety

Commands which expand cells share a preflight limit of 1,000,000 cells across all selected ranges. Ctrl+Enter, dense styles, borders, merges, clipboard fill/paste, filtering and structural edits check their work before writing. An oversized Ctrl+Enter fill is refused with a message and leaves the draft open for correction; it does not silently truncate to the used area. Excel's [Ctrl+Enter command fills the selected range](https://support.microsoft.com/en-us/accessibility/excel/keyboard-shortcuts-in-excel). Calc's equivalent is Alt+Enter; its [EnterBlock implementation](https://github.com/LibreOffice/core/blob/master/sc/source/ui/view/viewfun2.cxx) pastes across the selection and its [SelectionFillDOOM guard](https://github.com/LibreOffice/core/blob/master/sc/source/ui/view/viewdata.cxx) refuses expansion beyond 23 million cells. Pulpo deliberately uses the lower engine limit, so even one entire column exceeds the dense-fill budget.

Whole-row/column styles and number formats use axis metadata; Select All styles every column, including blank tails, and updates existing row-style exceptions. All Borders and No Borders use axis styles too. Other border presets and merges require bounded cell expansion. Clear Contents visits stored cells; Clear Formats removes matching cell and axis bases/overrides, including positional row slots and imported column intervals, and subtracts conditional-format coverage. Widths, heights, visibility and outlines are preserved. At intersections with unselected formatted axes, bounded explicit cell resets prevent inherited formatting from reappearing. Clear All preflights these resets before clearing contents. The clipboard snapshots effective inherited formats, and an axis-format change after cutting makes the old cut a copy. Input inference respects each target's effective number format.

The command regressions cover whole columns, whole rows and Select All, atomic refusals, imported/positional formats and inherited intersections; the Chromium suite checks Select All + Ctrl+Enter promptly returns control and permits a subsequent edit. No document-schema or live-format contract changed.

## On mobile

The app runs the same core in its locked-down web view (`apps/mobile/editor/sheet/`, about 0.7 MB inlined), on the replica of the document the app owns, as the text editor does (see [Live formats](./live-formats.md)):

- **The page** adds a phone formula bar (the selection's address, the cell's contents, and Cancel and Done while editing; Done commits and moves down, as Return does), a find bar (all sheets, with previous and next), and a strip of sheet tabs with Add sheet. It follows the app's light and dark appearance, opens read only when the document isn't editable, and shares the user's selection with their name and color through the bridge's `selection` message.
- **The keyboard bar** (`src/features/files/editor/sheetToolbar.ts`): undo, redo, bold, italic, and menus for fill color, alignment and wrapping, number format, and rows and columns (insert above, below, left, and right; delete), then freeze first row, sort, filter, and find. iOS draws the menus natively; Android's bar opens them as action sheets. The page reports which are on for the active cell (`sheetState`), and CSV files grey out formats.
- **Not yet on mobile**: pictures and charts show their placeholders, since the bridge carries no asset requests and the page loads nothing from the network; inserting pictures, notes, links, the context menu (cut, copy, paste, hide, resize), sheet rename and reorder, replace, and other freeze options are web only. Downloads come from the server's export, so edits not yet synced aren't in them.

## Review diff

`diffWorkbooks(before, after)` and `diffSheetFiles(beforeBytes, afterBytes)` (`diff/workbook-diff.ts`) describe a change the way a person would: sheets added, removed, or renamed (renames are recognized by content); rows and columns inserted or deleted; and cells whose value, formula, or format changed, by address, with shown values. Formulas that only moved with their row aren't reported. The web component `SheetDiff` renders it for agent Suggest-mode review.

## Files and agents

- **Web**: the registry entry (`features/files/live/registry.tsx`) gives the editor (`SheetDocEditor`), the review diff (`SheetFileDiff`, which diffs two versions' bytes), the **New spreadsheet** menu item (an empty `.xlsx`), and a local export that calculates formulas first. `LiveEditorProps` carries the document's asset store (`ApiLiveAssetStore`), which images and kept parts need.
- **Desktop** runs the web app, so it has the same editor.
- **Mobile**: the app's web view page and native toolbar (see [On mobile](#on-mobile)).
- **Server**: the codec is registered in `office/codecs.ts`, so creation, conversion of uploads on **Edit** (an upload keeps its bytes until then), export, compaction, and search text (`toText`) need nothing format-specific. Uploads convert at once, since the codec is lossless.
- **Agents**: `pulpo files pull` gives the real file and `push` applies it with `applyFile`, which merges it with what people typed meanwhile. The agent prompt and `pulpo files --help` say to edit `.xlsx` with openpyxl and `.csv` as text. openpyxl doesn't adjust references when it inserts rows, so row alignment compares formulas by shape (functions and which sheet each reference points at), not by their exact references. `pulpo files cat` prints the values and formulas.

## Structural metadata

`insertAxis`, `deleteAxis`, and `moveAxis` reconcile table columns and filter offsets by worksheet-column identity, rather than truncating their parallel arrays. Surviving table columns keep their XML, including totals functions and calculated-column formulas; inserted interior columns receive unique names. Deleting a referenced table column permanently produces `#REF!`, including in formulas on other sheets. Deleting the totals row clears its flag. Axis moves that would split a table, merged cell, or worksheet autofilter are rejected before modifying the axis.

Cell formulas, defined names (including print areas), conditional formats, validations, merges, links, notes, and drawing anchors follow stable axis ids. Axis moves preserve range membership, using a union when the referenced cells become discontiguous. Conditional and validation ranges retain their member intervals. Pane boundaries, selection, and compact column-style intervals are reconciled alongside the axes. Drawings honor `editAs="absolute"` and `editAs="oneCell"`.

Imported table-formula XML, chart-series formulas, sort ranges, extension formulas/sqrefs, sparklines, and threaded-comment positions carry reference tokens too. Export resolves those tokens against the current workbook, removes deleted comment destinations, and clears chart caches when their references change. Preserved chart/comment parts retain their exact bytes until a reference changes. Three-dimensional formulas retain sheet identities across tab renames and endpoint deletion.

`moveCells` implements cut/paste as a relocation: it redirects references throughout the workbook, snapshots overlapping moves, moves notes and links, transfers whole tables/merges/filters and drawings, splits partial validation/conditional-format coverage, and transfers sparkline/comment ownership across sheets. Partial table/merge cuts and overwriting existing table/merge objects are rejected. Sorting a table sorts its data records with notes and hyperlinks while leaving its headers, totals, and column definitions in place; row heights and outline settings belong to worksheet rows.

`model/structure.test.ts` includes the deleted-table-column regressions and a seeded edit sequence covering rich metadata, xlsx re-import, and openpyxl table-name/column-name comparisons after every operation. With `PULPO_OFFICE_FIDELITY=1`, the final export also opens in LibreOffice. The sheets corpus/fidelity suites use `PULPO_SHEETS_FIDELITY=1`. A local Basic/UNO oracle confirmed surviving table-column identities after interior deletion; LibreOffice discarded calculated/totals formulas in that experiment, so those fields are checked directly against the exported XML instead.

## Not supported yet

What's kept but not editable: pivot tables, slicers, sparklines, form controls, OLE objects, threaded comments (their legacy-note fallback shows), x14 conditional formats and validations in `extLst` (their reference fields follow structural edits), chart sheets and dialog sheets (kept as tabs), external links (references keep their cached values). Copying a sheet copies cells, formats, merges, rules, and notes, but not pictures, charts, or tables. See the pull request for the full list in order of importance.

A range whose both edges are deleted after its surviving rows were moved past each other may resolve to `#REF!`.

## Clipboard and fill safety

Internal HTML clipboard data contains a detached copy-time snapshot of source row/column positions, A1 formulas, evaluated values (including spill results), cell formats, notes, links, merged ranges, validation and conditional-format rules. Paste-values never recalculates or rereads the copied source. HTML and TSV expose the displayed text to other applications; HTML also carries spans, basic styling, string types and Excel R1C1 formula attributes. Invalid or older internal markers fall back to the visible HTML table. Snapshot pastes continue to work after deleting the original sheet or in another workbook; style definitions are imported before use.

Copy omits hidden rows, retaining their actual source positions for formula translation; cut includes the full rectangle. Hidden columns are included. Paste writes consecutive destination rows and columns, including hidden ones. A larger selection tiles the source when both dimensions are multiples of its dimensions; a smaller selection expands from its corner. Incompatible tiling, partial merged destinations, partial array edits and pastes beyond the sheet edge are rejected before any mutation. Relative references translated beyond the grid become `#REF!`.

Default paste carries validation, notes and links as well as formats and conditional formats. Values-only leaves those destination properties intact. Formats-only carries formats, merges and conditional formats while retaining destination values, validation, notes and links. Cut relocation requires a matching local session token and an unchanged source: stale, repeated or externally supplied cut data is copied from its snapshot instead. Cross-sheet moves retain the existing relocation of tables and dependent references. Copying a table's cells keeps the original table and its structured references; it does not create a second table object.

Fill prepares all source lines before writing, skips hidden rows, carries inherited formats, validation and conditional formats, and commits in one undo step. Horizontal autofill advances qualified table column references; copying and explicit column-range references retain their columns. Merged fill patterns, legacy array fill patterns and filtered dynamic spill anchors are currently rejected rather than flattened; transpose is not exposed. Interactive clipboard parity is tested in jsdom and Chromium. The opt-in `PULPO_SHEETS_FIDELITY=1` clipboard interaction test exports its results and checks formula recalculation and copied values through the private-profile LibreOffice tooling; this validates the file results, not LibreOffice's interactive clipboard UI.

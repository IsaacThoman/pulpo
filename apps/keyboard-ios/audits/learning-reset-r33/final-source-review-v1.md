**Blocking finding R1 — P1: embedded NUL truncates normalized registrar identity and revokes unrelated learning.**

Committed source: `Shared/LearnedDataPersistence.swift:26–35, 485–490, 577–600, 732–738`; in particular line 736 calls `sqlite3_bind_text(statement, slot, value, -1, transient)`. Normalization in `Dictionary/Lexicon.swift:391–420` preserves embedded U+0000. The approved input rules and actual admission validation permit a short nonempty String containing that character. No contract/API provision treats it as a terminator or permits truncating its normalized key.

SQLite's negative text length takes bytes only through the first NUL. Consequently the accepted token for `r33nul\u0000suffix` is stored with key `r33nul`. Another process's immediate forget of `r33nul` updates this token to revoked at line 590, although the two full normalized keys differ. The original writer's save then synchronizes that terminal token, drops its replayable operation, and reports successful completion. The payload merge cannot recover the operation because it was incorrectly revoked. This violates the explicit promise that normalized forget revokes matching earlier tokens and preserves unrelated valid learning. It is data loss on healthy storage, independent of reset races, I/O faults, or native UI limitations.

The exact pin schedule, through the frozen v4 runner, was available and failed its final semantic oracle:

**Minimal correction:** bind each Swift String using its explicit UTF-8 byte length, preserving interior NUL bytes, with a checked conversion to the SQLite length type and the existing copy/lifetime semantics. Apply this consistently to text bindings; do not silently truncate or hash away exact equality. Rejecting NUL after having approved arbitrary bounded strings would instead narrow the contract and legacy acceptance policy and would require an explicit protocol decision. Add public-path cross-process regressions covering an accepted full key versus its prefix and two different NUL suffixes, including pin/learn and target-pair preservation; retain ordinary same-key revocation and exact-once checks. No fix is authorized or applied in this review. Review the replacement source and refreshed gates in a new round; this rejection does not carry approval forward automatically.

**Transaction, observation and bounds audit.** The main serial protocol is implemented as approved: a canonical authority contains both stores; reset puts both new epochs/empty payloads and pending-token revocations inside one SQLite transaction; ordinary saves read the latest base and status before replay; payload updates and committed statuses share COMMIT. Lifetime writer slots are lazy and acquired before global ownership. Reads, migration, immediate forget and resets do not acquire a slot, so slot exhaustion does not itself prevent these operations. Nonblocking local/global acquisition reports busy; kernel filesystem calls remain unbounded in time. One-store reset selects only that store. Local projections use each instance's still-eligible tokens, and query/letter paths perform no new persistence observation.

The local mutex serializes replayable collections. Successful payload commit removes records before retaining bounded terminal receipts; a subsequent boundary deletes receipts. Uncertain false admissions remain ineligible and are cancelled rather than taught later. COMMIT error reconciliation reads durable identities under the same global lock; a still-active failed connection is repaired on the next boundary. Background requests capture the coordinator, not payload copies, and use one scheduled/running attempt plus a retry bit. Foreground capacity can try one nonblocking flush. These choices support the intended at-most-once design; R1 invalidates the exact-key eligibility part of that proof.

The 256 per-kind coordinator cap includes records and acknowledgement backlog; eight slots and token validation bound durable registration. Encoded payloads are checked before updates; SQLite page/cache/temp settings are explicit. Touch tokens persist no text/numeric sample sequence; ordered numeric records remain local and replay holds reference offsets once per word, including clamp/decay. Dedicated namespace and marker fencing prevent legacy reimport after authority loss. Cleanup failure follows committed reset and remains distinguishable. Malformed/unknown/inaccessible inputs are not adopted as empty success. Mixed-version old writers and inaccessible fallback storage retain their stated limits.

At the 32-live-domain registry cap, `find` (Persistence 175–183) returns uncached, admission-disabled coordinators. Repeated same-authority lookups there do not literally share one local NSLock as binding correction A describes. They do share the stable global flock, cannot register payload-bearing work, and do not bypass serialization. I have not derived unrelated-data loss from this registry path and do not present it as a second reproduced safety blocker.

# R49 filesystem seam v1 — proposed harness correction

This bundle corrects filesystem mechanics and blocked-row error retention only. It does not author a heldout benchmark, change fixtures/oracles, run a model or product, establish product acceptance, rerun R48, or reclassify any R48 failure. Parent-reported R48 results remain failed and unchanged. Independent review of this immutable proposal is required.

The input Runner.r48-frozen.swift was read from the author's original unchanged v2 directory. Its SHA-256 is 2718e44462cf19625484ef2b82b40771475ef5c546c2cf034523fc7de6730255, exactly the frozen execution-copy hash provided by the parent. The initially supplied nested source path did not exist; no content was read from that path. No retained R48 temporary store, payload, raw result, product source, dictionary, device or product binary was inspected. All explicit artifact writes are within this bundle except explicitly requested fresh, uniquely named probe-owned filesystem roots under FileManager.temporaryDirectory and /tmp. Those probe roots were removed by scoped cleanup.

Inventory.swift imports only Foundation and CryptoKit. The standalone proposed Runner.swift embeds its exact source and retains every product API call, action input binding, result/state schema, save/reload behavior and raw format from the frozen runner. The exact unified diff is Runner.diff. assemble.py verifies the frozen input hash and reconstructs the proposed runner using only the inventory replacement and the three first-blocked-reason/control-flow replacements. `python3 assemble.py` verifies without writing. Runner.swift was neither compiled nor executed against a product or stub. The only compiled and executed Swift binary is the Foundation/CryptoKit filesystem probe executable.

The inventory standardizes and resolves the root and each entry, then compares full path components for strict descent. It derives the root in the entry's own lexical spelling and verifies that this ancestor canonicalizes to the same root. This accommodates aliases with different component counts, including the observed /var versus /private/var and /tmp versus /private/tmp spellings, without hardcoded alias rewriting in the seam. Ordinary sibling-prefix paths and traversal components fail before content access. Every descendant component is checked for symbolic links and Finder aliases before content, including intermediate directory traversal. A supplied leaf root symlink/alias is rejected. Non-directory intermediate components and nonregular leaf entries are rejected. Duplicate canonical relative paths are rejected before another content read. Directory entries are traversed but never included as regular content rows.

Regular-file content is read only after both canonical containment and original-spelling component checks, duplicate detection, type checks and the pre-read bounds. Diagnostics emit contained, beforeRead and afterRead stages adjacent to the actual guarded Data read. They are optional and nil in the proposed runner. The inventory retains the original exact declared limits: at most 128 regular files, at most 16 MiB per file and at most 32 MiB total, with pre-read metadata checks and post-read actual-byte checks. It retains hidden regular files, sorted unique relative paths, byte lengths and SHA-256 content hashes only. No filesystem metadata is asserted immutable and no database/payload content is decoded. This Foundation seam makes no guarantee of atomic exclusion against a concurrently hostile filesystem mutator; the harness schedule remains sequential with no added background work or retries. Windows reparse-point behavior is outside the fixed macOS runtime; the macOS symbolic-link and Finder-alias cases are exercised directly.

Blocked actions now append an explicit unavailable/uninvoked row using the original first reason, then continue without throwing and recursively wrapping that reason. Catch paths and status-based blocking also preserve the first reason rather than overwrite it. No mutation or observation is automatically retried. A diagnostic error can still make the current action unavailable after it ran; no return/status/state is invented to repair that action.

Probes.swift uses only Foundation and CryptoKit and creates its own fresh roots. The final 28 real-filesystem checks cover nil/empty roots, ordinary nested/hidden files with immutable literal SHA-256 expectations, deterministic independent inventory observations, actual temporary-directory aliases and inode identity, both direct root/entry spelling directions, /tmp and /private/tmp when available, sibling-prefix escape, root-as-entry, dot-dot traversal, inside/outside leaf and intermediate symbolic links, a symbolic-link root, a real enumerator link entry, a real Finder alias, duplicate paths, exact and exceeded byte/file bounds, and first-reason retention across 1,000 uniquely identified explicit unavailable rows. Every rejected entry tested for containment/type/duplicate/bounds records zero content-read attempts. The 1,000 blocked rows retain the same 26-byte reason.

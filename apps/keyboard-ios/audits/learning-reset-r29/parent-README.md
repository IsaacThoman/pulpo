## What the successful barrier sequence proves

The writer uses public `pin`, `save` and `saveInBackground`. After its first completed save, it pins a second old word and arms a test-only syscall interposer. The background write reaches Foundation's atomic replacement syscall and blocks on a pipe before replacement. Only that standalone writer is instrumented. A separate real process calls public `clear`, then a fresh public dictionary reads **zero words**. The driver releases the writer and reads after its queued work completes: disk now contains **durableold and queuedold, total two**. Its later public reload returns **false** with those two words still present. No post-clear learning or synthetic notification occurs in this schedule.

The gate changes scheduling at the atomic replacement boundary; it does not modify dictionary memory, snapshots, production code or private state. Notification/select and worker-response barriers establish ordering rather than elapsed-time guesses. Driver timeouts raise errors, not success. The C release read itself blocks; timeout cleanup/liveness has not been independently fault-injected or certified. The recorded successful sequence completes.

One source qualification matters: `hasUnsavedChanges` is `dirty || files.sync { failedWrite }`, so it **does not drain the queue when dirty is true**. The worker's two `state` observations occur after `clear`/background snapshot capture set dirty false, so they do drain the appropriate process queue and construct fresh disk readers. The frozen executable contract's general statement that dirty checks drain earlier writes is broader than the implementation. The four heldout background cases subsequently use reload/save/new-instance barriers, or a no-URL actor; this qualification does not invalidate their recorded counts. No original contract text is edited here.

The source permits the product path: extension disappearance queues a full dictionary snapshot; the app clears through a different process; that earlier extension write later replaces disk and updates its own file stamp. A process-local serial queue cannot order the other process. The parent's replay corroborates this storage failure on current Core bytes. It is **not** an installed-iOS reproduction, suspension/termination test, frequency estimate, private-field policy proof or proof of every user-visible reset property.

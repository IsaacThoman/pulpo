# R15 frozen protocol

Frozen before reading implementation, 2026-10-16. Small synthetic development cases, each executed with actual English, Spanish and bilingual stacks (not content labels). All 38 templates remain scored in each mode, including inappropriate-language misses. Baseline is checkout HEAD. No dictionaries, ranking changes, R11 predicate import, or before-existing-text policy changes (parent R14). No push/deploy/devices/parent edits.

Replay fresh KeyboardEngine/provider/settings/document for every case. Seed full before/selected/after, perform optional backspaces or external caret move, type every character via controller-equivalent character/space/return pipeline, consume suggestions before final delimiter, record alternatives separately from automatic commits. Exact full document including accents/case/suffix/selection is primary oracle. Pair each with autocorrection-off raw replay, with capitalization still active. Never remove failures from denominators. Record learning and Undo; test field privacy and calibration through existing regression suite. Keep raw corpora/logs/build products outside Git; commit only these small synthetic cases/protocol/runner/per-case results and audit.

Development balances technical anchors (rooted/relative/home/drive/UNC), ambiguous filename/barepath/options/identifier, URL, slash prose, ASCII/Unicode ellipses, spaced/unspaced sentences, ordinary typos/accents at valid boundaries, true inside-word cases separately, marker deletion/caret/selection/suffix/private/Undo/capitalization. Known R11 exposed slash/ellipsis/path cases are diagnostic development only, never fresh evidence. Bare filenames and slash words can be ambiguous; no per-word/extension exceptions or blanket disable. Prefer narrowly anchored syntax, permit documented remaining ambiguous failures.

Select at most one candidate after development with technical gains and zero previously passing ordinary/control regressions in every actual language mode. Freeze source/runner hashes and commit before single held-out reveal. Held-out is independently authored, target-disjoint from development and old R11 (input terminal fragment and desired correction); author receives schema/protocol/exclusions but no implementation/failures/proposed fix. At least 30 templates balanced technical/prose, at least 10 meaningful ordinary boundary correction templates plus separately labelled inside-word controls, all three stacks. Author must not execute keyboard or inspect implementation. Keep held-out sealed outside checkout until freeze; report hashes/counts only. Reveal once, run unchanged baseline and candidate; no post-reveal tuning even on losses. Preserve every outcome and reject candidate on ordinary/safety regression; no-change audit is acceptable. Independent source review and core/data regressions required. Native controller runtime is unavailable under no-device instruction.

Schema: JSON array; id/group/before/selected/after/typed/expected strings, optional field secure|email|url|oneTimeCode (default normal), delete integer before typing, moveBefore/moveAfter external document reposition, undo bool after final space. Every template runs all modes. Raw oracle derives literal editing with normal capitalization (raw failure kept). The final typed character is generally space. before/selected/after concatenate full initial document. expected is final full document, selected replaced at first key. Exclusions include all terminal input/expected fragments; avoid lexical target reuse, including exposed diagnostics. Semantic category overlap is required.

## Proposed protocol for independent review

One JSON authority for the two product stores, at the existing PersonalDictionary.json URL, contains version 2, independent dictionary and touch reset UUID epochs, a monotonically increasing commit revision, dictionary words/pairs/blocks, touch sums, and normalized-key forget revision metadata. TouchModel.json becomes read-only legacy import; after migration it is never consulted while v2 authority exists. Arbitrary standalone URLs use their own authority at that URL; canonical sibling PersonalDictionary.json and TouchModel.json share PersonalDictionary.json. The two-store clear API only accepts canonical siblings (or both nil local-only); other combinations fail explicitly. Storage outside this reachable domain is never claimed cleared.

Every participant uses the same stable authorityURL + '.lock' sidecar. Open/create and flock(LOCK_EX|LOCK_NB); zero waiting or spinning. Keep the descriptor open through read/validate/reconcile/commit. Never replace/unlink the lock. A process-local serial IO queue orders own writes but is not the cross-process protocol. Crash/termination closes descriptors; stopped/suspended holder causes immediate busy results. No lock breaking or wall-clock ownership.

Word-learning, pin, forget and kept-word touch-learning boundaries, existing public reload/appearance paths, and save execution attempt nonblocking observation under that lock. No new per-letter work. Read durable epochs and revision, with file stamps used ONLY to avoid redecoding unchanged authority, never as reset inference. On epoch change discard that store's revoked pending operations and old in-memory learned data; retain transient contacts/replacements. Current-epoch operations replay on latest durable state. Public learning after successful observation enters that observed epoch, including identical spellings. Busy/IO observation failure remains explicitly distinguishable from successful observation; it may teach only the last observed epoch and cannot promise new-epoch preservation. Existing private-field gates unchanged.

Each store has a bounded local pending operation buffer (maximum 256 records, touch record <=40 numeric slot/delta samples; no persisted text/touch traces). At capacity attempt synchronous nonblocking save; if it cannot commit, return false from the learning API, teach nothing for that new operation, and leave existing pending learning retryable. Normal successful learning returns true (existing callers can ignore). Dictionary records exact learn count/after/pin, pin-only, normalized forget; touch records raw normalized numeric samples and replays the existing clamp/decay algorithm against current offsets, preserving word grouping. No use of lastUsed as causal identity.

Commit execution locks, rereads current authority, rejects only revoked epochs, reconciles ordinary same-epoch changes, then writes ONE new authority. Learn/pin applies if its observed revision >= last-forget revision of its normalized key; forget removes all forms/target pairs and blocks that key. Explicit later learn/pin that observed a forget unblocks it. Forget followed by relearn must retain the last-forget watermark so older pending learning cannot reappear as extra counts. Pending local operations must survive ordinary reload. Save returns false on failure, retains unchanged pending operations; a retry applies them once. Successful commits acknowledge/remove precisely the committed prefix; later pending operations survive.

Atomic writer: encode complete envelope, create unique sibling O_EXCL temp, write all bytes, fsync temp, then rename temp over authority while holding the stable lock. All possible returned failures occur BEFORE successful rename; after rename return success without a fallible postcommit step. No Foundation atomic replacement result ambiguity. Process termination before rename leaves old state; after rename leaves new state. This is durable against process death and older cooperating writes, not a claim of power-loss directory-entry persistence. Temp cleanup is bounded to this attempted temp; no caches/logs in Git. Metadata/payload are committed together. Clear generates both new epochs, empty states and forget metadata, and performs the same single replacement. Clear's success is its replacement, never a pre-lock check or an enqueued request. Legacy touch cleanup after commit must be evaluated independently; a failed cleanup cannot allow reimport.

Potential incompatibility requiring review: exact stale learn/forget/relearn semantics require a durable last-forget watermark even after relearn/pruning. A per-normalized-key map is one entry per explicit user forget choice, NOT a transient mutation journal, but can grow with distinct historical forgets. The user forbids unbounded mutation journals/caches and requires bounded new transient metadata. Is that durable map acceptable? If not, preflight MUST choose a bounded registrar/lease or database alternative with a justified exact compaction protocol, never silently discard unrelated valid learning. No product implementation until resolved.

Nil group URLs mean inaccessible storage: fail (no claim of fallback erasure). Individual no-URL clear/reset remains immediate in-memory only. Failed two-store reset never reports success.

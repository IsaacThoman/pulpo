## Decision

Accept the proposed distinction between `insertTranscript` and shared `insertText`, and accept the one explicitly authorized historical expectation update, subject to the implementation and evidence gates below. This is acceptance of a narrow explicit phrase-boundary contract, not a finding that its character predicate identifies prose, that every changed output improves UX, or that a candidate implementation is safe. A separate frozen-candidate review remains required.

No other ordinary expectation change is justified by this review. Existing full historical results must remain visible. Failures of conservation, privacy, ownership, or ordinary controls require rejection even if aggregate target gains are larger.

## API and historical capitalization adjudication

Baseline `insertTranscript` trims Foundation `whitespacesAndNewlines`, returns on empty input, reconciles pending host changes before its lexicon-based initial-lowercasing decision, and calls `insertText(..., spacing: true)` (`KeyboardEngine.swift:504`). Shared `insertText` applies a left separator predicate, preserves supplied whitespace, consumes genuinely owed swipe spacing, and inserts its payload without a right separator (`:462`). It also serves literal `.text` keys and emoji routes (`KeyboardController.swift:1121`, `:1134`, `:1236`). Giving those routes phrase semantics would be a regression. Preserve the shared left predicate exactly, including bounded punctuation runs, punctuation-led tokens, straight opener detection, and its historical behavior when prose policy is disabled. The new right-boundary decision alone is gated by `policy.autoSpaces`.

The existing `pendingCursorMovePrecedesTranscriptCapitalization` test (`AccuracyEditingTests.swift:22`) documents actual old fusion: `Hello againA note. please `. The host moved to offset zero without a callback, so reconciliation must retain capital H. At that visible start, the new contract deliberately adds an owned separator before the existing A. The new exact result `Hello again A note. please ` and Swift Character caret 12 are coherent with that specification. I accept changing this single expectation as a documented semantic change, not as removal of a capitalization failure.

Strengthen the test to assert the original document/caret setup, capital H, complete unchanged `A note. please ` suffix, exact caret 12, no selection, and zero deletion primitives. Preserve nearby tests for pending host clears/pastes, literal proper-name capitals, and known own-edit lag. Do not replace reconciliation coverage with a spacing-only example or normalize baseline output to the new oracle.

## Critical implementation gates

1. **Track phrase ownership separately.** Existing `automaticSpace`, accepted suggestions, and glides have their own `smartSpacing`-gated relocation behavior (`KeyboardEngine.swift:291-305`). Reusing that state risks moving an unowned host space or changing suggestion/swipe behavior. The owner must identify the exact logical insertion context and persist only through an immediate run of eligible one-Character punctuation. Shared `insertText`, literal `.text`, emoji, return, deletion, and other keys/actions end ownership. Include shift/page and conservative cancellation for suggestion, alternate, glide, and language changes; a later punctuation tap must not revive ownership.

2. **Remove the owned space before shaping a straight quote.** Baseline `curlyQuote` chooses opening versus closing from the current left context (`:336`). Shaping first while the owned space remains would produce an opening quote. Shape after removing that one owned ASCII space, restore exactly one separator after the inserted character, and preserve ownership throughout subsequent closers. With smart punctuation or smart quotes disabled, preserve straight glyphs while still relocating the explicitly owned phrase separator. Restrict this to `key.count == 1`; a multi-character key beginning with punctuation does not receive this behavior.

3. **Reconcile logical text without inventing visibility.** On a fresh engine, `expectedAfterContext` starts as an empty string until expected context is prepared (`:182`, `:1196`); do not mistake that default for the original host suffix. On own lag, use the reconciled expected sides rather than the stale physical proxy snapshot for boundary content, while requiring actual visibility of both sides. `reconcilePendingHostChanges` can return early for both-hidden sides or for a snapshot judged unchanged/previously owned (`:1156`). `documentDidChange` also intentionally preserves some natural-nil edges and own echoes (`:1047`). Those historical accommodations cannot by themselves prove the stronger phrase-owner visibility requirement. Explicitly end the phrase owner for a newly hidden side, identity/privacy/policy transition, selection/cursor change, or unrelated host edit before any deletion. Do not broaden global reconciliation to fix a phrase-only concern without preserving ordinary controls.

4. **Relocation must conserve host bytes.** Checking only `before.hasSuffix(" ")` is insufficient proof that the space is still owned. A host move or replacement before a callback must not let punctuation delete another space, replace a host selection, or reposition host content. In queued and reentrant execution, preserve optimistic context through callbacks without confusing stale snapshots for a new destination. Check every primitive's removed text and both document sides. Undetectable moves with identical observable snapshots remain a platform observability limit, not a proven guarantee.

## Ambiguity and degraded failures

The eligibility predicate is deliberately a shape predicate. It can admit punctuation-led words, dotted identifiers, apostrophe-containing text, and parentheses that look like prose or code. A right suffix starting with a Unicode letter can also be the continuation of a token. A visible left start/whitespace/opener reduces uncertainty but cannot establish intent. Do not call a boundary gain semantically correct merely because the oracle changed from fusion to separation. Preserve ambiguous rows and their rationale, including punctuation/code-shaped payloads and any in-word smart-join controls. Alphabetic mixed-language text also does not establish model identity.

For every output changed by the candidate, compare full exact output, caret/selection, suffix, all deleted characters, and spacing/ownership state, even when baseline and candidate both fail the final expected string. A failed-to-failed row can gain another space, lose a host character, change quote direction or capitalization, or become a worse partial result. Binary pass-to-fail counts would hide that degradation. Report such changes individually; required safety failures are vetoes. Numeric/code/emoji payloads, unowned spaces, right whitespace/newlines/punctuation/emoji/code starts, hidden sides, literal APIs, and disabled prose policies must remain explicit controls.

## Controller reachability and Undo

Production automatic dictation delivery requires the original request, unchanged continuously observed destination, document identity, both visible context sides, no selection, a non-private field, and Full Access (`KeyboardController.swift:955`; `DictationInsertionGuard.swift`). Recovery confirmation allows a non-private no-selection destination, including hidden context, after explicit confirmation and revision/snapshot checks (`KeyboardController.swift:999`, `:1022`). Selection replacement is reachable through the engine primitive, not through current automatic or recovery controller dictation. Direct private-field engine insertion likewise does not prove controller delivery. An old diagnostic comment describing request-ID-only protection in `DictationDestinationBaselineTests` is not the current controller's contract.

The non-UIKit harness cannot establish controller delivery or rejection; controller-route rows must remain unavailable and denominator failures, with source reachability explained separately. Do not silently substitute engine execution, treat controller rows as passing no-ops, or equate hidden confirmation with automatic insertion. Engine selected insertion needs an actual mutable selected range; existing `MockDocument.selectionOverride` reports selection without physically replacing it and is not sufficient for that evidence.

`TextDocument` exposes insertion/deletion, not native Undo grouping. Engine Backspace has correction/glide undo branches, but a transcript ending with an owned separator must retain ordinary one-Character deletion. It is not transcript Undo. Recording inverse abstract primitives or reporting UTF-16 offsets cannot prove UIKit Undo delivery/grouping. Native Undo is unavailable and a full denominator failure here; no native cursor-unit command should be invented from Swift Character offsets.

## Schema and freeze evidence

The schema intentionally allows action properties without per-kind requirements and cannot validate offset bounds, action-specific fields, Cartesian execution, dictionary identity, or capitalization expectations. The independent author and runner therefore must reject malformed or unsupported action combinations rather than defaulting them silently. Validate every checkpoint in Swift Character units, record UTF-16 caret independently, and execute all cases across real en_US/es/en_es stacks with matching settings and actual dictionary filename/SHA256. A `contentLabel` is not a language mode. `smartQuotes` is a host trait in current policy; `smartPunctuation` is a keyboard setting, and their disabled behavior must be exercised distinctly.

This review has not verified the contract's referenced five known core issues, historical suites, or heldout construction because those materials were excluded. They remain disclosures and evidence obligations for the final report. Freeze and reveal rules, unchanged baseline/candidate runs, full unavailable/ambiguous denominator, every changed failure output, and rejection/restore conditions must be enforced independently of this conditional source-contract acceptance.

R20 final pre-reveal scope and runner interpretation

The immutable pre-source v1 contract and 40 exact development cases remain broader than the candidate. No expected strings/carets were edited. Source-derived supplemental controls are explicitly separate, not new source-blind development or heldout gains.

Production diff is confined to KeyboardEngine.insertText and a letter-shape helper. Only spacing:true calls can gain a right space. Both live context properties must be visible; the suffix decision uses reconciled expectedAfterContext, initialized for fresh-engine calls. The original left insertion point must be empty, whitespace, a known opening delimiter/quote, or accompanied by supplied leading whitespace. The payload must contain only ASCII letters, standard Spanish accented letters/ñ/ü, and whitespace; it must end in one of those letters, and the suffix must start with one. This is a conservative shape filter, not code/technical/prose recognition. The existing R5 leading predicate and owed swipe space logic are unchanged. No dictionary, ranking, suggestion suppression, hasPathAnchor, or before-existing-word correction policy edits.

The new gap additionally requires existing policy.autoSpaces. Private/address/numeric fields therefore remain right-gap misses, despite existing explicit left spacing being ungated. Transcript API still performs its actual trim and optional casing; raw shared insertions do not inherit transcript trimming. Every payload is passed unchanged to the chosen actual API; no shortcut normalization or suggestion substitution. All panel/search/.text key UI calls remain default spacing:false. Raw means the new RIGHT gap is disabled; an already owed swipe LEFT space retains its existing behavior.

A single insertion primitive includes the right gap, replaces an actual selection once, advances the logical caret beyond the gap, and preserves host suffix text. Only when a new right gap is appended, lastEdit becomes existing automaticSpace(respace:true), so the existing punctuation handler can move that gap after an immediate comma/period. Smart punctuation disabled and consecutive punctuation remain explicit source-derived limitations. Backspace remains ordinary one-character deletion; native Undo grouping is unavailable.

The independent author confirmed before reveal that behavior-category metadata does not encode language mode. The frozen schema has no language-mode field. The final driver therefore uses the real production bilingual LanguageStack consistently for every case and records its resource ID. It does not infer language from payloads/categories. This covers natural EN/ES/mixed text through the bilingual model; it does not independently benchmark three selected modes. Dedicated language-mode behavior remains covered by existing full regression suites.

Runner uses a physical range-replacing document, actual key methods/dictionaries, and a delayed primitive queue with pre/post application callbacks. Source controls also exercise a fresh engine, second queued external insertion before first delivery, immediate punctuation, disabled punctuation, repeated punctuation and backspace. Extra optional smartPunctuation/deleteAfter/queuedSecondInput fields are source-control-only extensions declared before reveal. They are not retrofitted to heldout cases. Full-document primitive replay independently checks selected text, removed text, cursor offsets and host prefix/suffix after every applied primitive. Swift Character vs UIKit UTF-16 behavior and native callback/Undo behavior remain outside this host test evidence.

The author's availability:ambiguous annotation means no asserted oracle: retain actual text/caret changes but count neither successes nor gains/regressions. Expected/caret in such records are illustrative joins, not asserted successes. availability:unavailable stays a non-pass with no substitute action. Native reachability is separately unavailable for selected/private transcript delivery, even when direct engine API execution completes. Other native delivery is unverified because no devices are authorized. No native guard changes.

No delimiter filter can disambiguate an opt-in plain-word insertion before another letter from intended identifier/word-fragment joining. This remains a product tradeoff, not a safe-technical-preservation claim. Raw/literal APIs are the only justified exact deliberate-join controls. A right-gap change on ambiguous spacing:true cases must be explicitly reported even when excluded from oracle counts. Keep every failure/unavailable/ambiguous output, and reject any executable exact control or host conservation regression. If rejected, restore production and retain the frozen patch/runner/evidence without tuning.

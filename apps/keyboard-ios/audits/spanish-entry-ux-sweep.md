## Finding and candidate

Sentence-start `¿` / `¡` are absent from the engine's opening punctuation set. Inserting either clears automatic Shift, so entering `¿dónde` at the start produces `¿dónde` instead of `¿Dónde`; likewise `¡sí` instead of `¡Sí`. This also occurs after a completed sentence or newline, regardless of the loaded language. It forces an extra Shift tap in routine Spanish entry.

Retained fix: treat `¿` and `¡` like existing opening quotes/brackets when deriving sentence capitalization. Preserve the existing boundary rule: `Dime, ¿cómo` and `Entonces ¡sí` do not acquire a forced capital. This is a shared orthographic rule, including Spanish phrases typed in English mode. Implementation and development tests frozen in `f6d1df0ece31fc081cadb80a03cc27c7a6511377` (`fix(keyboard): preserve capitalization after Spanish openers`). No layout redesign, dictionary edits, ranking changes, or language-stack caching changes. The shared sentence-boundary helper also changes `insertTranscript` casing after sentence-start ¿/¡: an initial capital is now retained instead of lowercased. This indirect dictation behavior change was outside the original sweep’s tests.

Development regression coverage uses actual language stacks for all three modes and production engine insertions, checks sentence boundaries and nested opening punctuation, negative mid-sentence cases, host capitalization opt-outs, and shifted/locked ñ/á/ü. Held-out acceptance is evaluated only after freezing the implementation.

## Costs and limitations

No push, physical deployment, simulator boot, external API call, or source edits outside this checkout. Native touch gestures, VoiceOver interaction, and rendered active-language feedback require device verification and are not established by core tests. The core tests establish exact inserted text and engine state; source inspection establishes the controller's delegation, not a runtime UIKit result. Held-out **core acceptance passes; complete native UX acceptance is not claimed**. No simulator or physical-device time consumed, no dictionary generation performed; monetary/model costs are not exposed by this environment. Approximately seven minutes elapsed from the protocol commit to the final audit. The broad baseline dominated cost, including a roughly 141-second SwiftPM-lock wait for the development baseline.

Decision: retain the two-character sentence-opener extension because it removes a routine Spanish casing error, passes the targeted regression and held-out text checks, and introduces no new failure in those checks. Full-suite health and device-level affordance validation remain limited as described above.

## Reviewer integration characterization

`SpanishOpenerBoundaryTests` adds post-sweep regression cases, not new held-out acceptance or an expanded claim about native UX. Across all three modes, manual Shift-off **after** ¿/¡ permits deliberate lowercase. Manual Shift-off **before** an opener is rederived as automatic Shift, matching the pre-existing opening-quote/bracket policy; the new openers inherit that policy rather than establishing persistent manual-off state. The cases also cover sentence-ending closing quotes, newlines, ASCII ellipsis, and mid-sentence punctuation. Unicode `…` remains absent from the sentence-ender set and therefore does not establish a sentence boundary.

Transcript tests exercise the same helper through `insertTranscript`: sentence-start ¿/¡ now retain the capital in a known word such as `Hello`, while mid-sentence input still lowercases it. At that reviewer checkpoint, the pre-existing `insertText(spacing:)` behavior still added an unwanted space after ¿/¡ (`¿ Hello` / `¡ Hello`). The later inserted-text spacing integration removes that specific space; the current `SpanishOpenerBoundaryTests` deliberately update only the spacing expectation while preserving all casing checks. Broader transcript spacing remains outside the Spanish opener fix.

Focused reviewer validation passed in release: **31 test functions across five suites**, including the original development/acceptance suites, Shift and transcript accuracy regressions, and four new parameterized reviewer functions. The new cases execute 66 typed-entry sequences across all three modes and 12 English transcript sequences. Command: `swift test --package-path apps/keyboard-ios/PulpoKeyboardKit -c release --scratch-path /tmp/pulpo-spanish-boundary-review-spm --no-parallel --filter 'SpanishOpenerBoundaryTests|SpanishEntryTests|SpanishEntryAcceptanceTests|AccuracyEditingTests|ShiftSequenceTests'`. This is post-sweep regression evidence, not a new holdout gain.

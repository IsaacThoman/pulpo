## Remaining limits

This is a native hosted UIKit/controller experiment with a manually mounted UITextField, synthetic UITouch/UIEvent and direct accessibilityActivate calls. It does not run an installed UIInputViewController extension or UITextDocumentProxy, invoke the OS switch menu, demonstrate spoken VoiceOver, establish physical device behavior or exercise arbitrary holds/movement/cancellation. Secure-field behavior is outside V2's nonsecure oneTimeCode fixture. Live locale changes within one running controller remain runtime-unproven; the source cache handles resolved separators at an actual refresh, and static process locales do not demonstrate a live change. Defensive malformed-separator fallback has core injected evidence, not a naturally invalid native locale.

The domain review cites Apple's custom-keyboard documentation for phone/name-phone fields using system keyboards. That is an explicitly retained OS fallback, not an installed custom phone usability claim. The bounded source change leaves that dispatch unchanged. No phone workflow in this restricted fresh executor proves installed custom phone entry.

Full V2 acceptance remains blocked by the three retained mandatory failures. Preserve this complete failed paired evaluation unchanged. Any subsequent version must remain separately labeled and cannot convert this V2 packet into an all-passed result.

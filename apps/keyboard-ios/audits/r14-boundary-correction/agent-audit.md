# R14 new-word insertion before existing text

Decision: reject the sole candidate. Final production source is byte-identical to the starting `8c7d00a2` engine (the baseline e9f5d6bb-equivalent core). Useful synthetic gains did not satisfy all frozen safety/availability gates. No dictionaries or word exceptions changed, no post-reveal candidate tuning occurred, and no devices, deployment, push, or parent source edits occurred.

The protocol and 35 full-document development cases were committed at `a5e227b3` before inspecting the engine/controller implementation. Two manual fixture corrections and capitalization policy were documented before the first benchmark execution in `aeea2329`. These changed an offset transcription and made Backspace Undo match the existing remove-separator contract. No development expectations changed after execution. The report utility needed a mechanical fix for Swift omitting nil optional JSON keys; this did not change scoring, inputs, or outputs.

The author task received only the contract and exclusions, with no implementation, development cases/failures, candidate, or R11 cases. It authored 36 sealed full-document cases (12 each EN/ES/bilingual), reporting SHA256 `d83521fb1263e755bc30e5a536245ac3b0732fca9a0068cd6c0f3d8acaf96320` before candidate freeze. Candidate `024bde25` and [freeze.json](freeze.json) precede the first held-out file read. The independently authored file is retained unchanged as [heldout.json](heldout.json), including its contract errors and failed cases. R11's seven revealed boundary controls are development evidence only and were not reused as fresh held-out gains. Its rejected literal-token candidate was neither imported nor restored.

The one candidate tracked the prefix before the first newly typed word character, only at document start or after whitespace and without an initial selection. When the tracked prefix plus composition exactly matched optimistic before-cursor text, an explicit space could compute autocorrection despite a following word character. Deriving composition from an external edit cleared tracking. Ordinary suggestion refresh, punctuation/return commits, fragments, initial selections, literal-token checks, field policy, Undo, and proxy reconciliation otherwise retained baseline code. This experiment is preserved in commit `024bde25`; `ea85b181` restores production source. There were no other source candidates.

The executable [BoundaryCorrectionSweepTests.swift](../../PulpoKeyboardKit/Tests/KeyboardCoreTests/BoundaryCorrectionSweepTests.swift) drives actual `KeyboardEngine.insertCharacter`/`insertSpace` through the existing character-by-character helper with key-center taps, real language data, fresh personal/touch models, real selection replacement, exact initial documents and Unicode caret offsets. Automatic capitalization is disabled through normal field traits for this correction-focused benchmark; default smart punctuation remains enabled. The full expected document, never inferred intent, is the exact-output oracle. All prefix/suffix preservation therefore participates in success. It also records primitive edits, traces, learning counts, external changes and lag counters outside Git.

Each case runs four timing modes: immediate reports/callbacks per key; writes applied to the true host document while proxy text remains frozen until flush; optimistic proxy writes followed by earlier own-state reports; and two-second inter-key echoing reports that advance through prior own states. Host caret/selection operations flush and report context explicitly. Thus these modes do not claim to test an unreported external host edit or a true queued remote write pipeline. Actual UIKit `SimulatedProxy` supports queued writes; its new protection tests were compiled only, as described below. No model corpus or stochastic accuracy estimate is implied by these small synthetic tasks.

The 35 development cases comprise 33 scored tasks plus two explicit ambiguity diagnostics. In **every** timing mode, baseline passes **20/33**, candidate **31/33**, with 11 gains, zero new scored failures, and zero unavailable cases. Across timing executions this is **80/132 → 124/132**; timings repeat the same 33 tasks and are not 132 independent language examples. The fresh category is 1/12 → 11/12 unique, the flush-mid delayed task 0/1 → 1/1, and all other categories retain their scored outcomes. Fragment 3/3, literal 5/5, caret 2/2, privacy 4/4 and Undo 1/1 controls stay exact. Selection remains 2/3: the selection-suffix task stays uncorrected, as intended by the conservative selection guard, but still fails the desired user outcome. Spanish question opener `¿donde` also remains uncorrected because the tracking boundary requires whitespace or document start. All development outcomes and exact documents are retained in [dev-report.json](dev-report.json).

The two development diagnostics have deliberately incompatible intentions for otherwise ordinary observable keystrokes. `fragment-start` changes `teh token remains` to `the token remains`; `literal-ambiguous` changes `use teh build today` to `use the build today`. Both changes lose intended literal text. They are visible, excluded from scored denominators by the pre-frozen protocol, and emphatically not accuracy successes. A typed space provides a practical completion signal, but it cannot establish whether `teh` was an unmarked codename, prefix fragment, or typo. The candidate does not solve that ambiguity.

Held-out evaluation ran once per source version, using the unchanged frozen harness. There are 36 tasks: **33 scored plus three ambiguity diagnostics**. In every timing mode baseline passes **9/33**, candidate **15/33**, with **six gains**, zero scored regressions, and **six unavailable cases**. The unavailable cases remain in the 33-task denominator and count as failures. Across repeated timing executions: **36/132 → 60/132**, 24 gains, 24 unavailable. All six independently authored complete-word insertion cases improve (0/6 → 6/6 unique); EN, ES and bilingual each improve 3/11 → 5/11. This demonstrates narrow utility but does not establish production acceptance. The held-out accuracy gate returns false because unavailable cases violate the frozen gate. [heldout-report.json](heldout-report.json) retains every result, including ambiguities and failures.

All held-out failures and limitations remain accounted for:

- `en-05`, `es-05`, `bi-05`, `en-11`, `es-11`, `bi-11` request move offsets 37/39 that cannot execute as relative offsets from the current caret. The author brief named a move/offset schema but omitted explicitly saying relative, while the frozen development protocol/harness specified relative. This is an author/contract communication defect, not evidence of a keyboard caret bug. No offsets or expected strings were repaired after reveal. The delayed reconciliation user tasks therefore remain unavailable, even though their initial new-word insertions improve.
- `en-04`, `es-04`, `bi-04` fail technical literal retention in both baseline and candidate: source-like syntax with an unmarked misspelling is corrected in both. These are newly observed preexisting limitations in this round, not candidate regressions or solved issues. Existing literal-token policy does not fully recognize arbitrary source code/configuration values.
- `en-06`, `es-06`, `bi-06` remain uncorrected selection replacements in both versions. No claim that selection replacement correction was solved; exact selected-range removal and suffix conservation still hold in the executed traces.
- `en-07`, `es-07`, `bi-07` do not choose the intended grocery spelling in either version. The candidate does not change dictionary/ranking behavior, and these ordinary language failures remain failures.
- `en-08`, `es-08`, `bi-08` expect Undo to retain a separating space, contrary to the existing Backspace Undo contract. Both versions remove the separator and preserve the typed original plus the existing suffix, yielding joined words. These remain failed author expectations; no post-reveal oracle changes or UX success claims were made.
- The core restricted-number case intentionally exercises engine policy with alphabetic input that the actual numeric keypad cannot enter; it is policy evidence, not a native UX success. All three independent ambiguity diagnostics remain literal in both versions; their pass state is diagnostic only. All three fragment controls and six restricted/private-field controls pass in both versions. Personal learning count is zero in every restricted/private execution, in development and held-out, for both sources.

The full release core/services suite was run on candidate and restored baseline with serial execution. Candidate: **439 tests in 65 suites**, six issues including five existing known issues; the one failing test is `EngineFuzzTests.shortRandomizedEditingSequencesKeepInvariants`, which reports four `partialWordReplacement` violations in seeds 2, 5, 9 and 11. Its unchanged invariant forbids any terminator correction when a following character is a letter/number, including newly typed boundary words; these findings overlap the policy change being proposed. They are not proof that an existing suffix was deleted, but the gate was not relaxed or relabeled to make the candidate pass. Restored baseline full-suite command passes. Five known issues cover earlier-own-state host ambiguity and multilingual acceptance limits. The unreconstructable own-state ambiguity predates this round; it was not fixed or presented as a new bug. No fuzz expectations were edited.

Data checks pass: five language-data tests, six multilingual-data tests and four validation-word tests (15 total). No data changed. `git diff --check` passes. The actual UIKit [BoundaryCorrectionControllerTests.swift](../../UITests/BoundaryCorrectionControllerTests.swift) adds exact full-document protections for fragments, partial selection replacement, restricted fields and Backspace/retyped-space prefix/suffix conservation with immediate and queued/optimistic proxies. The first two generic iOS Simulator `build-for-testing` commands passed. Source inspection then found that a numeric keypad has no ABC/space key; the final test uses visible digits and preserves the suffix rather than pretending alphabetic numeric-field input is available through UIKit. The final rebuild verifies this correction. **These tests were not executed.** Runtime/native accuracy and real host UX remain unverified under the explicit no-device constraint. These protection-only tests do not validate fresh-word correction gains. No simulator was opened or driven, including the devices reserved for the parent/compact UX sweep; the unrelated device was never touched.

Independent [source review](source-review.md) recommends rejection and independently reproduces a concrete P2 trigger mismatch: `insertGlide` commits pending typed text with the same `" "` separator, so the candidate applies its supposed explicit-space exception on a swipe. With `join meeting`, caret 5, type `teh` (no space), then swipe `hello` with noise 0 and seed 123: baseline yields `join teh hello meeting`, candidate `join the hello meeting`. The frozen character/space action schema does not cover swipe, so this is an additional review finding, not another held-out accuracy gain or a changed denominator. Prefix/suffix survive and two-step Undo works, but behavior exceeds the candidate's trigger contract. No repair was attempted. A separate executable [source-review regression](../../PulpoKeyboardKit/Tests/KeyboardCoreTests/BoundaryCorrectionReviewTests.swift) now freezes this swipe-trigger and two-step Undo behavior on the restored baseline; it is not part of either accuracy denominator. The reviewer replayed the four fuzz seeds against immutable candidate and baseline sources and confirmed preserved suffixes/freshly typed boundary text, supporting the distinction between a red old invariant and proven inherited-word corruption. It also checked frozen hashes and regenerated the development comparison without reading held-out data. Its initial live-path replay was discarded because the shared source had changed during review; definitive evidence uses archived commit sources. Reviewer artifacts remain external under `/tmp/pulpo-r14-results/reviewer`.

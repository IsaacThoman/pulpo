# R40 normative capability and acceptance contract v6 (FROZEN FOR independent source-domain approval)

Baseline 00e2a0e7. One explicit shared picker searches English, Spanish, or mixed text regardless of the app's three language settings. Contextual EmojiSuggester.suggestions remains exactly English with unchanged legacy resource fields/order. No remote lookup, adaptive learning, cache or per-query index construction.

## Capabilities

Emoji retains value/name/version/tones/keywords and gains an optional Spanish CLDR48 speech name, JSON key s and initializer spanishName (default nil). Catalogs without s remain valid. The public APIs are EmojiSuggester(catalog:), suggestions(for:limit:prefixes:), search(_:limit:preferring:), emoji(for:), EmojiSearch.results(for:suggester:history:limit:), EmojiSearchQuery, EmojiHistory. Fixture catalogs use the existing JSON decoder and independent entries with optional s. A fixture alias for an absent glyph has no effect. No language/context parameter exists.

English names/keywords/exact names, folding of all diacritics, contextual behavior, prefix/order/ranks and legacy picker subsequence are preserved for every query and preference map at every existing limit. Existing English names such as consonant-diacritic words keep ASCII/case/NFD compatibility. New fields do not alter old fields or order. Duplicate base values are not introduced. The shipped catalog has unique bases; arbitrary fixtures must too. Tone selection maps base matches to the stored tone through unchanged wrapper behavior. Search does not write history. Empty wrapper searches use recents then popular and preserve recent variants/dedupe, exactly as baseline. Punctuation-only wrappers retain baseline empty-result behavior; they are not empty-query recents.

New localized interpretation lowercases with fixed en_US_POSIX locale, canonically decomposes, folds combining marks only after vowel bases, and recomposes. Leading/orphan Mn/Mc/Me marks without a preceding admitted base letter are discarded from Spanish interpretation. Legacy-normalized words are retained separately as described below, so discarded Spanish marks do not erase observable legacy distinctions. Consonant marks including n/ñ remain distinct for ALL Spanish speech names, including synthetic arbitrary controls; no word exceptions. All punctuation, symbols, digits and whitespace separate Spanish words; punctuation wrappers carry no operators. Vowel accents, uppercase and NFC/NFD are equivalent. No stemming, typo matching, transliteration, stopword removal or invented synonyms for Spanish. Every unique query token must prefix a word of the SAME entry's English-plus-Spanish vocabulary, using legacy folding against English and Spanish orthography against Spanish. At least one Spanish token match is required. English vocabulary includes name words, keyword words and the legacy compact forms. Canonical search identity C(q) is the PAIR (T(q), W(q)): T is the sorted unique Spanish orthographic token set; W is the sorted unique whole-word set from the UNCHANGED legacy normalized(q), INCLUDING ignored words. Both are observable deterministic token sets. T determines localized eligibility/ranking; W determines English reservation. Reordering/repeating whole raw tokens preserves both components and changes neither selected localized membership nor order, for fixed limit/preferences, including caps1,48,60 and overfull synthetic catalogs. Equivalence requires the SAME PAIR, not only T: apostrophe joins, orphan mark folding, and other raw normalization differences that change W are explicitly different search identities. Ordinary case/NFC/NFD/vowel-accent spelling and whitespace order/repetition equivalence are retained when both sets agree; no universal invariance across arbitrary punctuation joins or raw legacy-fold differences is claimed. English subsequence may retain its inherited order dependence.

An ASCII one-letter canonical token returns exactly the baseline list, including punctuation wrappers and repetition. Non-ASCII one-letter tokens (including ñ/NFD) may add localized matches while preserving baseline results. Empty localized token sets and raw queries over80 Characters add nothing. The unchanged R36 EmojiSearchQuery buffer has its accepted40-Character behavior; direct search supports up to80. Search nonpositive limits return[], default48, ceiling60. Wrapper limits and buffer behavior remain unchanged, including its uncapped empty-query path. No blanket invariance is claimed across different raw buffer truncations; equivalent tokens must reach the search API.

## Fixed merge policy, including constrained capacity and explicit two-set equivalence

First compute the unchanged legacy English result at the requested limit/preferences. Separately compute an order/repetition-invariant English envelope E(W) using the sorted unique LEGACY whole-word set W. Let B(e) be exactly the final actual legacy index keys whose bounded postings retain entry e (same minimum3/maximum80, ignored-term filter, ranks and 12-per-key bound). Let N(e) be the sorted unique word set from unchanged normalized(e.name). Let V(e) be the union of the unchanged searchWords(of:e) (normalized English name/keyword words), every actual final indexed key in B(e), and every space-separated word of each such key. V includes compact indexed forms; merely using name words would incorrectly exclude compact-name whole-query matches. Let G(W)=W minus the unchanged legacy ignoredWords. Define:

E(W) = {e : N(e) == W OR [there exist w in W and k in B(e) such that k.hasPrefix(w), AND every g in G(W) prefixes at least one v in V(e)]}.

Use the SAME Swift String.hasPrefix as legacy collect, not a projected or transliterated comparison. If W is empty, E is empty and localized additions are also empty. Include ignored words in W and existential prefix tests because they can anchor whole-query phrase matches. No English vocabulary substring, coarse projection, scalar table, language/word exception, generic full-catalog reservation or alias-disabling fallback is used. Entries whose names/keywords contain a query word only internally do not reserve a slot unless the separately necessary exact-name word-set witness exists.

Source proof obligation: a returned legacy entry either (1) wins exact folded-name lookup, implying N(e)==W, (2) occurs in a posting whose key starts the complete normalized raw query, implying that key starts its first whole word in W, or (3) originates in a per-word collect call for some nonignored word in W before fallback verification. Limits/preferences/ranking only remove/reorder members. For (2), every whole word of a complete-query prefix is a prefix of some space-separated word of the indexed key; the final query word may itself be partial. V explicitly contains those words and compact keys. For (3), the source already verifies every nonignored whole word against searchWords, which is a subset of V. These are the THREE actual entry sources, so every actual legacy result must belong to E(W). Independently prove this word-prefix lemma with actual Swift grapheme/whitespace splitting and prefix semantics; it is not assumed merely because it sounds plausible. Independently verify the exact-name implication, Swift Character/Unicode boundary behavior, empty/technical keys, final posting bounds and every public parameter before implementation. This source-level argument does not assume that Foundation projection commutes with localized tokenization. All earlier v1-v4 projection counterexamples remain rejected with their full denominators.

Useful capacity is REQUIRED: for any localized eligible alias whose raw query has nonempty T/W and passes the ASCII guard, if every English entry fails the exact-name word-set witness AND fails at least one of the two conjuncts of the postings witness above, E(W) is empty. Unrelated internal English substrings consume ZERO slots; return min(cap,eligible.count) canonical localized results at caps1/48/60, including arbitrary canonical non-ASCII base letters/marks (ñ is only one control, never a special branch). Genuine mixed intent MUST be observable: an English modifier plus a Spanish noun that jointly select an existing alias (e.g. synthetic English red heart/Spanish corazón, query red corazón) must return that target even at cap1 when E(W) is empty. An English-only word match cannot by itself reserve or exclude that target when another required nonignored legacy word lacks every English V prefix. These controls must be overfull and cover EN/ES/mixed, vowel/consonant marks, uppercase/NFD, ignored words, apostrophes and fixed C order/repetition variants. Native/query-buffer truncation still defines a separate raw input if it changes C.

Reserve min(limit,envelope.count) slots for English. Localized candidates exclude the ENTIRE English envelope. Fill at most limit-reserved slots from canonical localized candidates. This fixed localized tranche is then appended after the actual legacy list. Never evict, interleave or reorder legacy results. Unused reserved slots intentionally stay unused. This prevents order-dependent legacy occupancy from altering new localized membership at the cap. Envelope completeness is a required executable arbitrary-control safety gate, not an assumption.

Localized ranking: canonical Spanish speech-name token-set equality first, then fewer tokens requiring prefix completion across combined vocabulary, then fewer distinct Spanish name words, then original catalog order. Every ranking input is canonical and token-order/repetition independent. Existing recent/popular preferences keep their legacy effect only; they do not change localized ordering. No whole-string equality bonus. No first-token bonus. A Spanish exact match can follow an English prefix match because legacy preservation has priority. Conservative reservation can suppress an otherwise available localized result; audit this as a limitation, never count mechanically added arrays as useful alternatives.

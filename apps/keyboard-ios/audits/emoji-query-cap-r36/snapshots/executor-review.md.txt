# R36 independent executor/comparator review — changes required before freeze

Reviewed current `measure.swift.txt`, `compare.py`, exposed `smoke.json` and `smoke-baseline.json` after pre-author commit e59d5bf1. No Git actions, ROOT edits, builds, devices or sealed author inputs were used. Python loaded the comparator via compile/exec without import-cache writes. The only probes use twelve uniquely identified in-memory copies of already-exposed smoke data; they are not fresh or heldout cases.

## Sound scope

The Swift observer calls actual public EmojiSearchQuery initialization, append, Backspace, deleteWordsBackward and clear. It does not read expected buffers, implement a competing query algorithm or invoke search/ranking/model code. It records initial state plus every action, actual text, Character count, emptiness and Unicode scalars. The exposed smoke has exactly 19 checkpoints and all pass the current comparator's observations checks.

The comparator strictly validates input top/case/action fields, required oracles, unique IDs, action-specific value/count, integer range excluding bool, ordered result identities and exact state counts. It checks step/op identity, scalar-array-to-text binding, Bool emptiness and scalar-exact expected buffers. All paired transitions, including fail-to-fail, remain present; passed-case aggregation is not vacuous because every case has initial plus nonempty actions. Missing states, Boolean counts, wrong scalar arrays and duplicate observed IDs reject in independent probes.

## Concrete required fixes

1. Observed `characters` is only checked as a nonnegative integer and <=40 for scoring. It is not bound to text segmentation. Replacing every observed Character count with 0, while retaining nonempty texts/scalars, still gives acceptance=true for twelve exposed smoke clones. Recompute observed and expected grapheme counts with an independent segmentation-only Swift helper (or a separately audited exact segmentation receipt), reject stale observed counts and impossible >40 expected buffers. Do not use Python scalar counts or copy the production query algorithm. Swift decoding also supplies a suitable boundary for rejecting invalid lone-surrogate pseudo-scalars.

2. Outputs contain no binding to exact input bytes. Changing an append value to `CHANGED INPUT` while leaving IDs/op/gold and reusing the original observation report still gives acceptance=true. Have the observer record exact input SHA-256 and require the comparator to bind both versions to the provided fixture bytes. External freeze/command receipts still need to establish which production sources/executable produced each report; a hash is consistency evidence, not execution authenticity. Do not manufacture this metadata for stale reports.

Both gaps concern reusable result integrity, not an observed production failure. They must be fixed and smoke/reviewed before candidate/runner freeze and any sealed reveal. Expected strings or production policy must not be adjusted to resolve them.

## Anticipated cap algorithm

The approved contract is naturally implemented by normalizing each presegmented incoming Character exactly as today, making the tentative whole-string concatenation, stopping if its newly segmented count exceeds40, otherwise assigning it. Do not preguard solely on existing count, sum component counts, split a nonfitting incoming Character, continue after overflow, or retroactively normalize storage. Keeping the exact current whitespace suppression and deletion/clear code preserves non-cap behavior under the approved decorated-whitespace and chunking semantics. This assesses the algorithm shape only: no candidate patch exists or is accepted in this review.

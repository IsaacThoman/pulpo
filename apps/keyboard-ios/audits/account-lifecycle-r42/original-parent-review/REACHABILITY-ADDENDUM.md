# R35 reachability and contract addendum

This addendum supersedes the severity and adoption conclusion in REVIEW.md, without changing that historical review, its source ordering, or its unexecuted proposed countercheck. Reviewed immutable worker tip dd882f4c9658ac38ed11c4c7c36c50c60fc2fef8; production b2b31684; base e6871a16. No build, device, account API, audio upload, or proposed test was executed.

## Qualified finding

The old-upload401/pending-loginB ordering is a conditional source-level lifecycle interaction. It is NOT presently a demonstrated ordinary release-UI regression or a failure of the frozen executable contract. My earlier categorical wording, “blocking introduced regression” and “not acceptable for adoption,” exceeded the demonstrated reachability and accepted oracle. With that qualification, this finding alone is not a source veto to isolated parent validation of the narrow account/presentation candidate.

The source ordering remains exact: beginSignIn changes account authority without cancelling dictation (AppModel.swift192–196); the actual upload's current/noncancelled 401 can invoke onUnauthorized (DictationService.swift215–217); the installed callback calls signOut(remote:false) (AppModel.swift69), which clears pending login authority (272). A held B login would then fail its authority check (214/224), while SignInAttempt suppresses CancellationError (42). Successful replacement cancels dictation only later, at231, before publishing session B. This describes what happens IF model replacement B is begun while A's upload remains current. It does not establish that current release UI can produce that state or that B-success is the accepted oracle for that additional event.

## Actual release entry points and cancellation barriers

- HomeView presents its route-account sheet only for route==account AND session==nil (PulpoKeyboardApp.swift207–208). handle(accountURL) only changes the route (AppModel.swift320–321); it does not bypass that session gate or directly start login.
- AccountSection's local signingIn sheet binding itself is not gated by session, but its only visible opening button is in the session==nil branch (PulpoKeyboardApp.swift350–374). The signed-in branch offers Sign Out, not replacement Sign In. Existing local presentation state is not proof that a second submission is reachable after a successful login: the current successful submission immediately invokes dismiss (SignInAttempt.swift38–40), and submit is disabled while working (SignInView.swift68). No ordinary release sequence was established that keeps this sheet available for B while A has begun an upload.
- DictationSessionView offers account routing only when session==nil (117–124). Its transcribing state exposes Cancel (109–113), not another account login.
- Explicit Sign Out synchronously invalidates dictation lifecycle and cancels its upload before clearing session (AppModel.swift274/285; DictationService.swift226–235). A subsequently exposed Sign In therefore does not retain a current A upload. Upload completion tests cancellation and lifecycle before invoking onUnauthorized (216). A cancellation that runs first suppresses that callback.
- Successful replacement likewise cancels before publishing B (AppModel.swift231–234). Under the app's MainActor default there is no await between the upload's guard and callback, or between this cancellation and B publication; no demonstrated interleaving defeats these barriers.
- Existing cached session loads only during AppModel initialization; refresh requires an existing session and cannot create A from a signed-out state (65–66/243). The app targets iPhone and disables multiple scenes (project.yml13/47; Info.plist UIApplicationSupportsMultipleScenes=false). A hypothetical independent second-window login is not an established release path.
- PK_TEST_LOGIN can call signIn independently, but it is under #if DEBUG (AppModel.swift90–118), not evidence of an ordinary release UI route.

These are source observations, not a formal proof that every SwiftUI presentation or external event schedule is unreachable. No speculative animation/nested-sheet race is promoted to a reproduced bug.

## Exact accepted contract and coverage boundary

The pre-exploration intended-contract.md admits model replacement and requires stale refresh isolation; development scenario6 explicitly starts loginB with accountA/refreshA present. It also states pending dictation must not transfer owners, while excluding full audio from this proof. It does not specify that an A-upload401 during pending replacement B must preserve B's login authority rather than revoke it.

The frozen public-protocol.md exposes exactly startLogin, startRefresh, awaitRequest, respond, waitTask, cancelTask, revokeLogin, signOut, checkpoint, and reload. Its HTTP vocabulary is config/login/me/logout. It explicitly excludes simulated audio, permission dialogs, dictation deep links, Keychain write failures, SwiftUI tapping, and UI challenge/focus/back state. Thus:

1. A stored previous account plus a pending replacement login IS an admitted public-model schedule.
2. Dispatching an old dictation upload's unauthorized callback while that login is pending is NOT an operation or endpoint in the frozen runner. The callback witness extends the executable domain.
3. The frozen rule that an explicit signOut revokes all login/refresh work remains coherent. An unconditional call to the same method by the dictation callback is the source interaction to review, but the existing protocol does not establish the new callback event's desired authority semantics.
4. countercheck.swift.txt invokes that real installed callback directly. It is an UNCOMPILED/UNEXECUTED development proposal, not a faithful audio/upload reproduction, fresh case, frozen counterexample, or independently accepted oracle. Its expectation that B survives belongs in a separately agreed new-round contract.
5. The author's reported candidate24/24 versus baseline14 pass/9 fail/1 unavailable remains evidence for the bounded actual model schedules. This source review has not independently replayed or audited every raw row and adds no empirical pass/fail count. It neither invalidates those results nor broadens them to full account/dictation lifecycle acceptance.

## Pre-seal domain review clarification

The final concurrent-refresh paragraph of domain-review.txt says: “An unauthorized sign-out must also revoke pending sign-in authority per contract.” Its preceding sentences discuss eligible current refresh results, matching captured generation, session identity, and latest refresh sequence. The frozen public protocol subsequently makes refreshes predating a new login stale and refreshes begun during that login permanently ineligible; those stale refresh events cannot invoke current unauthorized sign-out. If an authorized sign-out does occur, however, revoking pending login authority is the required effect rather than a defect. The paragraph does not establish that an old dictation upload is eligible after a new login begins, nor promise that pending B must survive such a callback. Therefore the proposed B-survives oracle is new desired account/dictation policy, not mandated by the original frozen contract. In particular, do not label AppModel.signOut's new authority revocation itself a regression merely because the existing unqualified callback reaches it.

The frozen validate.py operation/endpoint vocabulary independently confirms the ten operations and four endpoints above. Both public-protocol.md and validate.py match their candidate freeze.json SHA256 bindings (f7b210b1b71d7beb288f5f65d0a87ce75136863faf06037730598a65a7a1475f and 5cd1eb697a933c4b36063fae59d1bf5ba684259573c5543526e9a8f6adca0337). The schema validator uses Python asserts; I did not execute it, infer optimized-mode validation, or independently certify all raw report rows from reading it. No production or oracle change is proposed here.

## Revised recommendation and new-round countercheck boundary

Narrow R35 source changes are worth isolated parent validation: presentation/attempt revocation, refresh authority, and checked session persistence have no other source-confirmed blocker from this review. Full adoption still needs the parent's chosen native/error gates; largest-accessibility drag dismissal remains unresolved, Keychain failure behavior was not injected, and four unpaired timing failures must remain disclosed rather than labelled proven regressions or passes.

Broader account/dictation authority remains a risk-review item for the separately frozen round, not a demonstrated admitted-domain regression in R35. Before any new candidate, explicitly specify whether pending replacement login revokes/cancels A's dictation authority and whether an A401 may cancel B. Freeze a faithful release-UI action sequence if one exists; otherwise label model-only capability tests as such. Include post-signOut and post-successful-replacement cancellation controls, current-account401, pending permission return, and an actual or explicitly injected upload boundary. Do not silently reuse the proposed B-survives oracle as a prior accepted requirement, retune the revealed R35 source, or claim runtime evidence from this addendum.

## P2: memory-only touch learning rejects previously valid long words

Location: `Core/Geometry/TouchModel.swift:109`.

The new guard `target.count <= 40` executes before sample construction and before checking whether persistence exists. Baseline `TouchModel.swift:110–117` required matching normalized lengths and at least two bytes, with no upper length bound. The approved contract's domain/admission sections preserve NoURL existing ordinary length semantics and put the <=40 numeric-sample bound on durable registrar records.

Concrete public source-path sequence (not executed in this review):

1. Construct `TouchModel(url: nil)`.
2. Construct a `TypedWord` whose text is 41 ASCII `a` letters, with 41 taps at qwerty `a` center plus `(0.1, 0.2)`; intended string is exactly the same text.
3. Call `learn(typed, intended: text, geometry: .qwerty)`.
4. Baseline passes its length guard, retains all 41 finite samples, and changes weight 0→41. The fixed per-word reference and radius0.45 allow these offsets without a nonlinear ambiguity. The final candidate returns false/invalid before collecting samples and leaves weight0.

This is reachable through the public model API, and public `LanguageStack.init(dictionaryURL:personalURL:touchURL:)` defaults `touchURL` to nil (`Core/Dictionary/LanguageStack.swift:14–16`). `TypedWord.keyed` preserves one byte/tap for each ASCII letter (`Core/Correction/SpellCorrector.swift:27–37`). The unchanged engine delegates accepted touch words to this model (`Core/Input/KeyboardEngine.swift:1014–1016`), but I did not establish that a shipped dictionary exposes a >40-letter accepted word in an ordinary installed UIKit typing flow. Do not inflate this finding into an observed app reset failure or a measured user-visible accuracy loss.

The durable bound is independently enforced by `LearningMutation.valid(.touch)` at `Core/Shared/LearnedDataPersistence.swift:36–38`, reached only for a persistence-backed model (`TouchModel.swift:118–123`). Thus enforcing the registrar's actual sample bound does not require this global guard. It also matters that normalized target length and the count of actual nonnil letter tap samples are different: a >40-letter target with only two known taps could produce a bounded durable record, yet the global guard rejects it. The contract explicitly speaks of words requiring more samples, not an unconditional target-length limit.

Recommended disposition: preserve memory-only behavior and enforce the durable sample cap only at the persistence boundary; add an ordinary regression for long finite aligned memory input and, if the sample-based policy is retained, sparse long persistent input. This review does not modify code or tests. Because the parent says the blind round has now executed, do not silently retune its frozen contract/oracles or relabel old results as a fresh test of changed source. A later fix needs explicit source identity and ordinary regression/revalidation.

Coverage gap: existing `TouchModelTests` exercise short memory words and policy gates; new `memoryLongHistoriesPruneTheSamePairsAndQueryIndexes` is a **dictionary** history test, not a touch length test. The reported ordinary-suite passes do not contradict this source-traced case.

## Storage authoritativeness and ordering

- Canonical sibling PersonalDictionary/TouchModel URLs map to one dedicated SQLite authority in a canonicalized parent directory (`LearnedDataPersistence.swift:110–139`). Combined clear requires both nonnil canonical sibling URLs and matching derived authority. It cannot accidentally claim to clear unrelated/mixed URL pairs.
- Initialization imports both legacy canonical siblings, validates payloads before marker creation, creates the marker before the SQLite schema/import transaction, and thereafter uses only SQLite (`290–350`). Existing DB/marker mismatch, missing/replaced opened DB inode, unsupported schema/meta identity, malformed store, and invalid token registrar produce non-ok. It does not infer “clear” from authority disappearance or reimport old JSON after loss. Interrupted first initialization may permanently require external recovery; that fail-closed availability cost is explicitly accepted in the preimplementation contract.
- Local nonblocking exclusion and a stable exclusive nonblocking global flock enclose SQLite migration/operations/legacy cleanup (`175–245`, `275–289`). Eight independently flocked lifetime writer-slot files prove slot reclamation; slot acquisition is lazy, outside global ownership (`264–274`, `417–425`). Clear/read/forget do not require a writer slot. At registry capacity, ephemeral slotless coordinators still share fixed local exclusion stripes (`175–191`). These invariants assume cooperative protocol users and stable sidecars; arbitrary external replacement/removal is not a supported peer protocol.
- Admission observes the durable epoch and registers a new sequence/token transactionally while reserving the immutable local operation; only confirmed .ok makes it eligible and permits model teaching (`468–511`; dictionary `235–246`, touch `118–126`). Failed/uncertain admission is not retrospectively taught. Sequences are not reused.
- Before reset: A admits a token in epochE; B's completed combined clear empties both payloads, assigns fresh epochs, and marks all earlier pending tokens revoked in the SAME transaction (`616–652`). A's later save must synchronize durable status before applying operations (`430–454`, `545–573`); revoked tokens become acknowledgements, not replay payloads. A newly accepted learn after clear observes the new epoch and survives. No wall-clock timestamp orders these operations.
- Before forget: A admits normalized keyK; B's forget removes all corresponding durable forms/target pairs and revokes pending keyK tokens in the SAME transaction (`588–614`). A cannot restore those pre-forget tokens. Distinct-key tokens remain; a genuinely later keyK learn/pin is a new admission and deliberately unblocks/relearns. Word-history pairs are not removed merely because the forgotten word is their history, preserving the stated old policy.
- Save applies still-eligible records in coordinator sequence to latest store payloads and sets their tokens committed atomically (`545–573`). The next reconciliation sees terminal status and removes local replayability before token deletion; delayed/lost acknowledgement cannot authorize reapplication (`430–456`). Pending data from other local model instances can be committed together; projection overlays only the querying owner's pending records (`457–465`). A confirmed save is not a snapshot replacement that could overwrite another process's whole store.

These are source-derived schedule arguments. I did not execute a fresh process race, stop/kill test, fault interposer, or journal recovery test; the ordinary tests mostly share one process/coordinator. Cross-process/process-death claims require the independent parent execution evidence.

## Projection refresh and privacy/policy boundaries

A successful observation reads current epoch/revision and returns the latest durable base plus only that session's eligible pending operations (`376–385`, `458–465`, `519–533`). Dictionary adoption rebuilds known/used/word/history indexes; touch adoption invalidates offset cache. Failed observations return no payload, so an existing model retains its previous view. Constructors may instead expose initial empty state with a non-ok result. Reload Bool means visible change, not observation success; callers/test oracles must also inspect `persistenceResult`.

Queries remain in memory (`PersonalDictionary.swift` query section, TouchModel offset/weight getters). Existing controller initialization/appearance invokes both store observers (`UI/KeyboardController.swift:248–251`, `347–353`); successful new admissions also observe. There is no cross-process notification or per-letter refresh. Suggestions may use old local projections until an existing successful observation/kept-word boundary. Dictionary/touch are individually observed and may straddle a reset; simultaneous in-memory two-store coherence is not claimed.

The existing field and settings gate remains `InputPolicy.learns = plain && settings.learnWords`, with plain excluding private/address/numeric (`Core/Input/InputTraits.swift:62–68`), and engine word/touch learning checks it (`KeyboardEngine.swift:950`, `1015`). Storage does not newly receive document text or bypass these guards. Touch payload/registrar contain numeric aggregates/opaque tokens, not word/tap traces; the **same authority also contains the dictionary's intentionally stored learned words**, so no claim that the whole shared SQLite file is text-free is warranted. Source guards and short ordinary policy tests do not establish a full native private-field/secure-input proof or forensic erasure.

NoURL models stay local and create no coordinator; transient contact words survive clear. Aside from the reported touch-length regression, the reviewed known/pinned count, normalized block/unblock, lowercased history, pair-target forget, and clamp/decay/group-reference logic are retained. Persistent byte/capacity/validation backpressure intentionally rejects some inputs the old best-effort format accepted; this is an explicit design tradeoff, not unchanged availability for arbitrary legacy data.

## Unicode identities and SQLite NUL handling

The final pair grammar (`PersonalDictionary.swift:103–177`) escapes only ASCII backslash/control separator and splits bytes rather than persisting a runtime-dependent Character count. The control separator fences history/target Unicode composition; the byte escape grammar disambiguates embedded separators and backslashes without encoding a byte length that would distinguish canonically equivalent strings. Dictionary keys retain Swift String canonical equality; conversion of old pair formats explicitly checked-adds colliding counts. Format1/2 are recognized, unshipped development format3 is rejected intact, and format4 is current (`LearnedDataPersistence.swift:66–94`). Test stores from a rejected earlier candidate can therefore require explicit recovery; do not present that as a shipping-format migration guarantee.

Token keys use the existing normalizer's output as an opaque identity. The final registrar validator no longer normalizes that result a second time (`LearnedDataPersistence.swift:407–412`): lowercasing-before-compatibility-decomposition can emit capitals, so idempotence is not a valid invariant. Admission and forget both normalize the ORIGINAL spelling. This preserves the existing normalizer's equivalence policy, rather than introducing a new case-folding policy.

SQLite binds TEXT with the explicit UTF8 byte count (`LearnedDataPersistence.swift:747–749`) and reads it with `sqlite3_column_bytes` plus strict UTF8 decoding (`764–768`). Token schema length uses CAST-to-BLOB byte length. Embedded NUL therefore is neither an implicit terminator nor a prefix-match forget key in this source. Ordinary regressions cover embedded-NUL distinct keys, canonical composed/decomposed histories, control/combining/escape boundaries, and non-idempotent compatibility keys. I inspected these tests but did not run them.

## Failure semantics and integration limits

`transaction` rolls back active failures and reconciles failed COMMIT reports using durable identities in a fresh transaction under the global lock (`355–371`). Healthy post-COMMIT confirmation can return .ok; unresolved outcome is .uncertain. Failed uncertain admission remains ineligible and is cancelled on later reconciliation; uncertain save consults durable token status. Unknown/missing matching-epoch token is invalid, not permission to recreate it.

Combined clear returns .ok only after the atomic two-store commit and reachable legacy-file cleanup. Postcommit legacy failure returns .cleanup; individual models adopt the cleared payload for .cleanup while returning false (`clear:616–652`, dictionary clear, touch reset). Reset/forget .uncertain/.cleanup can have committed: false MUST NOT imply unchanged data. AppModel passes group URLs with **nil fallback**, maps only .ok to true, and gives neutral retry copy for all other outcomes (`App/AppModel.swift:229–238`). The keyboard may use application-support fallback when the App Group is not writable (`UI/KeyboardController.swift:277–287`); the app's clear cannot reach that extension-local store and does not clear nil-memory or transient data. No full-device/old-binary erasure claim is justified.

Immediate foreground operations do not wait for local/global/slot locks, but once open/read/SQLite/fsync begins they have no hard kernel deadline. Admission performs synchronous transactions on kept-word boundaries; work scales with outstanding registrar entries and payload refresh, and an at-capacity foreground admission may flush payloads. Source bounds are not a latency measurement. Actual iOS input/clear performance is not established here. Parent-reported macOS timing outliers and later controls were not opened or analyzed; they cannot be treated here as causal performance proof either way.

Background save is coalesced best effort, not durable completion or guaranteed retry under contention. Accepted learning is locally installed after token registration; killing a process before payload save can lose those unsaved local values by design. `save(inBackground:true)` acknowledges enqueue semantics, not success UI. Ordinary persistence-test changes now explicitly finish/retry busy before checking counts/blocks/offsets, and retain those original semantic assertions; this accepts the new nonblocking API instead of falsely relying on constructors to drain a queue.

R33 storage alone does not make the old Settings unconditional alert truthful. The parent-owned R41 conditional-Bool success/error and explicit Forget failure feedback remain separate integrated/native gates. Parent reported R41 tests against an earlier storage revision; this source-only report neither admits the latest merged UI nor waives final-byte compilation, ordinary regressions, AX5, actual real-fault/retry, controller, or native validation. The AppModel merge must retain unrelated newer account changes owned by the parent.

Sentence-local bilingual next-word backoff — proposed next implementation round

Disposition and evidence boundary
This is a source-backed feature proposal, not a measured baseline accuracy result. The pre-ranking intent and 12 unexecuted scenarios are retained with receipts. The v2 execution file only corrected mode label en to actual en_US before ranking was read; original bytes remain. No existing report, heldout or payload was read, no engine was executed, and no build/device/Git/ROOT write occurred.

Concrete implementation opportunity
KeyboardEngine passes previousWord and precedingWord to LanguageModel.context. The latter resolves precedingWord only into an exact trigram ID, then discards it. Without that table, ranking has no preceding-word signal. Bilingual compilation equally mixes shared histories and discards their source-specific conditional components. Its META explicitly says no code-switch corpus. Runtime predictions gather trigram successors, bigram successors, personal pairs and 32 global fallback words, rank by the shared model, return three, and center the strongest in the visible bar. For an unknown previous word and empty personal data, predictions reduce to the same unigram fallback regardless of the earlier frame. This is a real context-capacity limitation, not proof that a specific rendered suggestion is wrong.

Suggested narrow candidate
Preserve English/Spanish component evidence for shared bilingual histories; use an unambiguous immediately preceding word's source membership as a bounded sentence-local backoff hint ONLY when bilingual next-word prediction lacks an exact trigram. Keep both languages eligible, retain the current equal mixture when the hint is absent/shared/unknown, and leave exact trigram predictions unchanged initially. Do not translate, change the explicit typing mode, persist a language preference, infer from hidden/private text, insert automatically, or replace tokens. No word-specific lists/exceptions or new training sentences. Compiler provenance is general dictionary source membership, not word popularity or offensive-policy reclassification.
Store optional compact provenance and per-component conditional data in the bilingual dictionary, derived reproducibly from the current bundled monolingual binaries. Preserve all original word flags, IDs, display forms, suppression semantics and original English/Spanish bytes. Existing single-stack lifetime is retained; do not load all three LanguageStacks simultaneously. The existing model.context(precedingWord:) call can supply a new prediction-only hint without changing KeyboardEngine or UI. Confine use to LanguageModel.predictions, not global logProbability: correction, completion and glide currently share that scoring API and must not change indirectly. If safe component data cannot fit the resource budget or development usefulness is absent, stop rather than broaden policy. Shared-history conditional storage and the exact interpolation rule must be separately frozen before independent author reveal.

Complete public executor capabilities for authoring
Use Swift Release core, a concrete mutable TextDocument with String Character cursor/selection, and real LanguageStack(dictionaryURL:personalURL:nil) per row. Settings.language must equal the actual stack; missing/invalid assets are fatal, never English fallback. All cases run en_US/es/en_es independently. Primary normal settings: predictions=true, learnWords=false, autoCapitalization=false, smartPunctuation=false; no emoji suggester/text replacements. KeyboardController normally adds emoji, so core results explicitly isolate lexical utility and require later native smoke validation. All rows start in a newly constructed engine/empty personal model; documentDidChange establishes initial prefix/selected/suffix. At least one launch/staged-typing equivalence control uses actual insertCharacter/insertSpace instead of only prefilled documents.
Allowed scenario fields: unique id, familyId, contentLabel(en/es/mixed/control), prefix, selected, suffix, route(nextword/completion/control), typed (completion only), acceptableByMode (three explicit nonempty word sets for scored rows), oracle(scored/ambiguous/control), rationale, actions. Plain nextword primary rows have selected empty and prefix ending ASCII space; completion controls dispatch typed via actual one-Character insertCharacter calls. Capitalization differences are not silently normalized: primary cases use the explicit none policy, authors supply intended display forms. Accent distinctions are preserved; no normalized-key matching for score.
Allowed actions: observe; type(text) split into Character insertCharacter; space; return; backspace; setMode(raw enum) by real LanguageStack sharing and matching settings/useLanguageStack; hostMove(Character offset, selection length, callback flag); hostReplace(full doc, Character caret/range, callback flag, optional new document ID); setPolicy(only explicitly enumerated normal/private/url/numeric plus predictions/learnWords toggles); acceptSlot(index0..2); replayCapturedSlot(capture index). Bounds and action fields are strictly checked before execution. Each action records a full document/range/state snapshot and all actual insert/delete primitives, not just safety booleans. Unsupported/native actions are invalid before authoring; native Undo/VoiceOver/controller delivery are outside this interface, never replaced with Backspace or simulated successes.
Observe records all displayed slots, text, kind, isAutocorrection, composingText, logical contextBeforeCursor, settings mode, resource SHA and model object identity. Diagnostic access to the engine's internal languageContext is optional @testable-only evidence; public primary scoring never injects history IDs or calls model predictions in place of engine.suggestions. The visible center is strongest when >=2 slots; left is not rank one. Capture and accept the exact engine-returned object, preserving its hidden generation, never reconstruct Suggestion(text:kind:).
AcceptSlot does not select a golden word invisibly. Missing slot remains an explicit full-denominator acceptance failure. Normal isolated acceptance oracle is mechanical: prefix excluding actual composing text + actual chosen display text + one ASCII space iff original right context does not begin whitespace + unchanged suffix; capitalization/smart quote transforms are disabled in primary acceptance rows. Author action templates for moved/selected/stale controls provide complete expected documents/carets and expected primitive counts. Full text, caret and selection must agree, independently replaying each primitive/removed character and checking wrong-destination writes. Conservation alone does not prove destination safety. Score semantic usefulness separately from acceptance mechanics.
Privacy controls snapshot personal counts/hasUnsavedChanges and require no new learned data; primary learnWords=false prevents benchmark pollution. Optional prelearned controls use only public personal.learn/pin/forget with disclosed counts in a fresh nil-URL instance; these are a separately reported cohort. No disk, contacts, history, private host text, corpus, network or hidden resource mutation is an author capability.

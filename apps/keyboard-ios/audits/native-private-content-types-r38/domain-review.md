## Review and privacy boundary

**Preserve the current 24 semantic categories and every existing exact legacy spelling.** `InputTraits.swift:33–43` currently recognizes exactly:

`username`, `password`, `newPassword`, `oneTimeCode`, `emailAddress`, `URL`, `telephoneNumber`, `creditCardNumber`, `creditCardSecurityCode`, `creditCardExpiration`, `creditCardExpirationMonth`, `creditCardExpirationYear`, `creditCardName`, `creditCardGivenName`, `creditCardFamilyName`, `creditCardMiddleName`, `creditCardType`, `postalCode`, `flightNumber`, `shipmentTrackingNumber`, `birthdate`, `birthdateDay`, `birthdateMonth`, `birthdateYear`.

The current implementation is a case-sensitive `Set<String>.contains`; `isSecure` unconditionally makes a field private. The 24 literals above are verified source strings, **not verified UIKit raw values**. Extend recognition with independently calibrated exact SDK raw values for these categories while retaining all 24 literals. Preserve `contentType` readback as supplied; do not normalize, trim, case-fold, strip prefixes, search substrings, or infer privacy from a custom type's resemblance to an Apple identifier. Unknown custom strings, empty string, and nil remain non-private unless secure or exactly a declared alias. SDK types outside this fixed category scope must not be added by pattern.

**Ordinary exceptions retain ordinary behavior.** Generic personal-name components, nickname, job title, organization, location, street/city/state/country and other ordinary address components stay non-private. Relevant named selectors to calibrate include name/namePrefix/givenName/middleName/familyName/nameSuffix/nickname, jobTitle/organizationName, location/fullStreetAddress/streetAddressLine1/streetAddressLine2/addressCity/addressState/addressCityAndState/sublocality/countryName. This selector inventory is not a raw-value mapping or SDK availability claim. Postal code remains the declared private address exception; cardholder names remain the declared private name exceptions. Ordinary means normal **subject to keyboard type, settings, and field traits**; an ordinary name with an email keyboard does not gain normal prose assistance. Secure overrides all ordinary exceptions.

**Primary risk / contract blocker:** `KeyboardHost.swift:49–101` uses `source.textContentType??.rawValue` without translation; a symbolic-name/raw-value mismatch therefore reaches every privacy caller. Core tests supplying hand-written aliases cannot validate actual SDK adaptation. Existing `DictationDestinationControllerTests` uses a host with stored `InputTraits`; despite exercising `ProxyDocument`, it does not exercise `InputTraits(UITextInputTraits)` for content types. Calibrate named SDK values through that actual public initializer and report the resulting raw string, adapted traits, and policy independently before freezing expectations. Do not bless the current set as proof of the SDK mapping.

## Complete policy behavior to expose

From `InputTraits.swift:46–75`, let `addressLike = keyboard in {email,url}`, `numeric = keyboard in {numberPad,decimalPad,phonePad}`, and `plain = !isPrivate && !addressLike && !numeric`.

- `autocorrects = plain && settings.autocorrect && autocorrection != false`.
- `appliesTextReplacements = plain && autocorrection != false` (independent of the global autocorrect switch).
- `showsSuggestions = plain && settings.predictions`.
- `learns = plain && settings.learnWords`.
- `capitalization = traits.capitalization` iff autoCapitalization is enabled and !addressLike; otherwise none. Privacy and numeric status do not independently turn it off.
- `smartQuotes = plain && settings.smartPunctuation && smartQuotes != false`.
- `smartSpacing = plain && settings.smartPunctuation`; `autoSpaces = plain`.
- `allowsGlide = settings.swipeTyping && !numeric && !isSecure`. A nonsecure private content type can currently allow glide. Preserve this formula; R38 must not expand glide changes or introduce glide scenarios.

Expose all nine policy fields, `isPrivate`, and `isNumeric`, including nil/false/true traits. `spellChecking` and `smartDashes` are mirrored but do not gate these policy fields; return kind, enablesReturnKeyAutomatically, and appearance also do not classify privacy. KeyboardAdapter maps namePhonePad to standard; asciiCapableNumberPad to numberPad; numbersAndPunctuation is not numeric here. Adapter `.yes` for smart quotes/dashes becomes nil, `.no` false; default also nil. Read back actual values rather than assuming round-trip identity.

`KeyboardEngine.traits` and `.settings` recalculate policy; trait changes invalidate stored suggestion choices when policy or privacy changes. Public caller verification must read real `suggestions` and edits, not reproduce the policy formula as the sole oracle. Important caller paths are typed word commits, replacements, offered suggestion selection and stale selection, correction undo/pinning, pending correction acceptance on a later edit or `save()`, and word/touch learning. Refresh/document notifications are explicit ordered operations: setting traits alone does not simulate UIKit's full document callback. `documentDidChange()` resets reversible/composing/pending learning when document identity, privacy, or relevant context availability changes (`KeyboardEngine.swift:1028+`).

Keep externally supplied text distinct: `insertText` and `insertTranscript` are public insertion primitives, **not dictation authorization**. `insertTranscript` trims whitespace, may adjust first-word case using the real lexicon, then calls `insertText(..., spacing: true)` (`:462–519`). It has no private-field refusal. It can commit an existing composing word; it does not itself learn every word in the transcript. Authorization claims require the actual controller/guard path. A manually constructed `Suggestion` also lacks the context token of an engine-offered choice; capture and replay the real offered object for stale-choice checks.

## Dictation reachability and flags

Actual public/core building blocks are `DictationDestination`, `DictationInsertionGuard`, `DictationRequestLifecycle`, `DictationState`, `DictationBridge`, `KeyboardController(host:dictationBridge:)`, and `InputTraits(UITextInputTraits)`. Controller internals are not new public production APIs. An offline adapter can drive UIKit controls through `rootView` using accessibility identifiers (`dictate`, `dictation-action`, `dictation-done`, `dictation-cancel`) and record a fake host's `openApp` requests without opening anything. Existing test-only `@testable KeyboardUI` access can additionally capture the actual onAction/onStop/onCancel closures for replay; advertise this separately from public control taps. No new production seam is necessary for this review.

- **Normal begin:** visible microphone tap reaches `startDictation` (`KeyboardController.swift:814+`). Preconditions are Full Access plus a bridge, signed-in account, dictationAvailable, then a non-private live destination. Accepted begin creates a request/origin guard, sets bridge.pendingRequest, binds controls, shows connecting, and marks the mic active. Inside-app or standby sends `.start`, with a 2.5-second fallback URL; otherwise it requests a dictate URL immediately. No selection/identity/context guard prevents begin: these affect delivery later. Full Access/account/availability failures precede the privacy message. Observe requested commands/URLs, not actual app activation or recording.
- **Private/numeric begin:** `sync()` hides the mic for private OR numeric (`:543`). An ordinary tap is consequently unreachable there after layout. Forced dispatch to the real hidden control is a distinct adversarial capability: private begin is refused before creating a new request; numeric alone is not refused by the begin handler. A silent host trait change after a normal mic was drawn can also reach the live privacy guard. Record UI visibility separately from handler acceptance and compare pending state against its prior value, rather than assuming a refusal clears pre-existing requests. Ordinary email/URL keyboards hide assistance but can still begin dictation if contentType is non-private.
- **Destination flags:** private capture reads document ID but skips before/after/selection getters; its `hasSelection` is consequently false, while `isPrivate` blocks confirmation. Normal confirmation requires only !private and no nonempty selection. Automatic insertion additionally requires nonnil ID and both contexts, exact equality of the entire destination (including traits), and no invalidation. Empty string differs from nil. Instrument per-getter reads for the destination-capture operation only; the engine itself reads text for editing and does not promise zero private reads globally.
- **Automatic finished delivery:** visible controller, existing bridge, matching pending/state request, finished state with a nonnil transcript, not delivered, same in-memory origin request, guard acceptance, and current Full Access are required (`:928–967`). Live host traits are reread before insertion, so a silent switch to private cannot use stale engine traits. The controller marks delivered, updates engine traits, inserts, clears pending, and exits. Repeated finished notifications do not duplicate insertion. Whitespace-only transcripts can be marked delivered with zero text edits; delivered does not mean a nonempty insertion occurred. Finished with nil transcript clears pending/exits without inserting.
- **Recovery:** changed ID/context/traits, selection, missing identity/context, invalidation, recreated controller or lost visibility prevents automatic insertion. Pending transcript survives; recovery shows Insert Here only for a non-private, unselected destination with Full Access (`:991–1020`). Missing identity/context permits explicit confirmation. Private/selected/no-access recovery offers no insert action. A later normal destination plus document callback refreshes recovery. Recovery does not require signedIn/dictationAvailable again; those are begin requirements. Resuming matching recording/transcribing state also does not rerun begin privacy guards; late insertion is checked separately.
- **Late confirmation:** an actual captured recovery action validates visibility, pending request, finished phase, exact updatedAt, nonnil transcript, not-delivered, destination revision, exact live destination, confirmation eligibility, and Full Access (`:1022–1042`). A stale action cannot insert after host change, request replacement, cancellation, or a new result timestamp. Host will-change and did-change invalidate automatic insertion/revision even if proxy data still matches; disappear does too. Returning to an identical snapshot does not revive an invalidated guard. Observe refreshed recovery rather than asserting every rejected callback is a pure UI no-op.
- **Stop/cancel/error:** stop requires visible controller, matching pending request, and live bridge state recording for that request; stale Done cannot turn finished recovery into transcribing. Cancel sends only for its still-pending request, clears pending, and finishes; stale controls cannot cancel a newer request. A requirement/error close only finishes its panel. Failed state clears request/origin and offers Try Again, which reruns begin requirements; matching idle clears pending. Replies with no pending or wrong request are ignored for insertion. Hidden controllers ignore updates; reappear resumes a matching pending request through recovery as appropriate.
- **Recorder lifecycle without recording:** `start` creates a fresh generation even when the request UUID repeats; preparing → recording via beginRecording(attempt); recording → transcribing via beginTranscribing(); transcribing → finished via finish(attempt). Each public return value is observable. Duplicate/out-of-stage callbacks fail; cancel clears attempt/stage but preserves responseRequestID for the waiting keyboard; a new start replaces it. fail(attempt) accepts only the current nonterminal attempt. In `App/DictationService.swift`, permission, host-return, and upload callbacks use these generation/stage guards. Exercise the lifecycle value itself, never instantiate the audio service or upload client. The keyboard bridge carries no attempt-generation token; distinguish lifecycle protection from UI request/timestamp/revision checks.

## Remaining risks

1. SDK named/raw mapping and availability remain unverified here; this prevents a final privacy compatibility claim.
2. Alias-only tests can pass while the real UIKit boundary leaks learning or authorizes dictation. Ordinary name/location/job controls are needed to prevent overbroad matching, with no newly authored blind cases in this review.

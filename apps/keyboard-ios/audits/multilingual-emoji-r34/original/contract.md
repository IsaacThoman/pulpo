## Capabilities

Emoji retains value/name/version/tones/keywords and gains an optional Spanish CLDR48 speech name, JSON key s and initializer spanishName (default nil). Catalogs without s remain valid. The public APIs are EmojiSuggester(catalog:), suggestions(for:limit:prefixes:), search(_:limit:preferring:), emoji(for:), EmojiSearch.results(for:suggester:history:limit:), EmojiSearchQuery, EmojiHistory. Fixture catalogs use the existing JSON decoder and independent entries with optional s. A fixture alias for an absent glyph has no effect. No language/context parameter exists.

English names/keywords/exact names, folding of all diacritics, contextual behavior, prefix/order/ranks and legacy picker subsequence are preserved for every query and preference map at every existing limit. Existing English names such as consonant-diacritic words keep ASCII/case/NFD compatibility. New fields do not alter old fields or order. Duplicate base values are not introduced. The shipped catalog has unique bases; arbitrary fixtures must too. Tone selection maps base matches to the stored tone through unchanged wrapper behavior. Search does not write history. Empty wrapper searches use recents then popular and preserve recent variants/dedupe, exactly as baseline. Punctuation-only wrappers retain baseline empty-result behavior; they are not empty-query recents.

New localized interpretation lowercases with a fixed locale, canonically decomposes, folds combining marks only after vowel bases, and recomposes. Consonant marks including n/ñ remain distinct for ALL Spanish speech names, including synthetic arbitrary controls; no word exceptions. All punctuation, symbols, digits and whitespace separate Spanish words; punctuation wrappers carry no operators. Vowel accents, uppercase and NFC/NFD are equivalent. No stemming, typo matching, transliteration, stopword removal or invented synonyms for Spanish. Every unique query token must prefix a word of the SAME entry's English-plus-Spanish vocabulary, using legacy folding against English and Spanish orthography against Spanish. At least one Spanish token match is required. English vocabulary includes name words, keyword words and the legacy compact forms. Query tokens are canonicalized to a sorted unique set BEFORE matching/ranking/caps. Reordering or repeating tokens changes neither the selected localized membership nor its order, for fixed limit/preferences, including caps1,48,60 and overfull synthetic catalogs. English subsequence may retain its inherited order dependence.

An ASCII one-letter canonical token returns exactly the baseline list, including punctuation wrappers and repetition. Non-ASCII one-letter tokens (including ñ/NFD) may add localized matches while preserving baseline results. Empty localized token sets and raw queries over80 Characters add nothing. The unchanged EmojiSearchQuery buffer has its existing40-Character behavior; direct search supports up to80. Search nonpositive limits return[], default48, ceiling60. Wrapper limits and buffer behavior remain unchanged, including its uncapped empty-query path. No blanket invariance is claimed across different raw buffer truncations; equivalent tokens must reach the search API.

## Fixed merge policy, including constrained capacity

First compute the unchanged legacy English result at the requested limit/preferences. Separately compute an order/repetition-invariant English envelope: every catalog entry whose English vocabulary contains each canonical reservation token as a substring under the SAME coarse reservation projection. The projection applies fixed en_US_POSIX Foundation case/diacritic-insensitive folding, then canonical decomposition, then retains only scalar bases satisfying BOTH Foundation CharacterSet.letters.contains AND Swift Unicode.Scalar.properties.generalCategory in {uppercaseLetter,lowercaseLetter,titlecaseLetter,modifierLetter,otherLetter}, joining them without separators. Requiring BOTH classifications intentionally excludes Foundation letter-set members that are actually Mn/Mc/Me marks, and newly assigned Swift letters absent from Foundation. The localized tokenizer admits base letters through this SAME intersection, accepts scalars of generalCategory nonspacingMark/spacingMark/enclosingMark only after an existing base-letter token, and treats every other scalar as a word separator (unless it was already removed as a vowel mark). Mark removal after vowel a/e/i/o/u uses those THREE explicit generalCategory mark values, before letter admission; other marks are retained in the token. The coarse projection removes ALL of those mark categories because none is a base-letter category. This defines arbitrary Unicode by the exact two runtime predicates, without word exceptions. Apply it separately to EVERY English vocabulary term and EVERY canonical localized query token; deduplicate the projected query tokens and remove projected legacy ignored words. Never tokenize the raw query anew for this envelope. If a projected query token is empty, or all tokens are ignored, reserve the entire catalog. The vocabulary is the name/keyword words and compact forms defined above, including full normalized name/keyword terms; projection happens after the unchanged English normalization. This projection is for capacity ONLY, and deliberately folds all vowel/consonant marks and removes retained spacing/enclosing/nonspacing marks and digits alike. If those words are empty the envelope is the entire catalog. This is a conservative superset of possible legacy results for token-order/repetition equivalents, including compact forms, punctuation exact names, apostrophe joining, digit separation and Unicode combining marks of ALL categories (Mn/Mc/Me). Substring membership is ONLY a conservative capacity-reservation predicate; actual localized eligibility remains token-prefix matching. Apostrophes disappear in legacy English but split Spanish tokens; each projected piece must therefore occur within a projected matching English term, even if it is not a word prefix. Digits similarly split Spanish tokens but remain inside English terms before projection. The separate coarse projection bridges the different mark removal of Spanish and legacy English: retained spacing marks cannot split a projected substring. It is never used for actual eligibility, so Spanish n/ñ distinctions remain intact. The envelope must depend ONLY on the canonical localized token set. This intentionally broader envelope may reserve more slots than a prefix envelope. Reserve min(limit,envelope.count) slots for English. Localized candidates exclude the ENTIRE English envelope. Fill at most limit-reserved slots from canonical localized candidates. This fixed localized tranche is then appended after the actual legacy list. Never evict, interleave or reorder legacy results. Unused reserved slots intentionally stay unused. This prevents order-dependent legacy occupancy from altering new localized membership at the cap. Envelope completeness is a required executable arbitrary-control safety gate, not an assumption.

Localized ranking: canonical Spanish speech-name token-set equality first, then fewer tokens requiring prefix completion across combined vocabulary, then fewer distinct Spanish name words, then original catalog order. Every ranking input is canonical and token-order/repetition independent. Existing recent/popular preferences keep their legacy effect only; they do not change localized ordering. No whole-string equality bonus. No first-token bonus. A Spanish exact match can follow an English prefix match because legacy preservation has priority. Conservative reservation can suppress an otherwise available localized result; audit this as a limitation, never count mechanically added arrays as useful alternatives.

# R20 independent source review v1

Reviewed the frozen `contract-v1.txt`, repository instructions, production engine, controller, adapters, preview document, and local UIKit declarations. No development/heldout cases, results, sealed temporary files, corpora, raw logs, devices, or deployments were read or used. This is a source review, not evidence that a candidate passes. No candidate diff was available when this version was written. Source references below are workspace-relative and refer to the inspected baseline.

## Recommendation

Proceed only with a narrowly described, opt-in prose-spacing change in `insertText(..., spacing: true)`, reached by `insertTranscript`. Preserve the R5 left-side predicate and owed swipe space. Reject a rule that applies the new right-side space to default/raw calls, emoji callbacks, literal typing, unknown suffixes, or all after-letter positions. The contract supports useful engine-level natural-prose claims; it cannot establish universal text-join correctness or native delivery/Undo behavior.

A known boundary on the left and a letter on the right are necessary restrictions, not proof of prose. At document start, inserting `pre` before `fix` can intentionally form `prefix`; before `Bar`, `foo` can intentionally form `fooBar`. Replacing a selected stem before an existing plural `s` can intentionally preserve the inflection. These are independent source-review examples, not test observations. A short payload ending in a letter is observationally indistinguishable from an independent word. Keep that ambiguity explicit and unscored as the contract requires. If success is defined as preserving *all* smart-API technical/in-word joins while adding the prose gap for the same observable input, reject that requirement as unattainable without stronger caller intent.

## Findings

1. **Native transcript delivery has stricter reachability than the engine API.** `KeyboardEngine.insertTranscript` trims and optionally changes first-word case, then calls `insertText(..., spacing: true)` (`PulpoKeyboardKit/Sources/KeyboardCore/Input/KeyboardEngine.swift:503-517`). It has no selection/private guard. Native automatic delivery instead requires an unchanged destination, document identity, visible before/after context, no selection, a non-private field, and Full Access (`Sources/KeyboardCore/Shared/DictationInsertionGuard.swift:20-40`; `Sources/KeyboardUI/KeyboardController.swift:954-964`). Recovery confirmation also excludes selection/private fields (`KeyboardController.swift:1003-1039`). Therefore an engine transcript replacement/private case is executable at that layer but does not prove that the native controller can deliver it. Native automatic insertion with withheld suffix is unavailable; explicit recovery may remain available without a selection because `allowsConfirmation` does not require contexts. Do not change these guards to make engine cases reachable.

2. **`spacing: true` is an explicit opt-in used by transcript; raw callers must stay raw on the right.** Current external insertion supplies a leading separator for `spacing || phantomSpace` and clears the owed space (`KeyboardEngine.swift:461-484`). Repository UI callers for `.text` keys, their alternatives, emoji panel, and emoji search all use default `spacing: false` (`KeyboardController.swift:768-771,1119-1135,1234-1237`). No native general-purpose `spacing: true` caller other than transcript was found. A direct `spaced` engine test is still valid API coverage, but not evidence of an existing independent UI delivery path. Existing owed swipe spacing is intentional: even `spacing: false` can insert a leading space if `phantomSpace` is set. Thus “raw preserves joins exactly” must be read as protecting the new right-boundary behavior, not an instruction to erase existing owed-space semantics.

3. **Unknown before-context is not a known start.** `before` returns `expectedContext ?? documentContextBeforeInput ?? ""` (`KeyboardEngine.swift:255`). Initial optimistic preparation also converts nil before/after contexts to empty strings (`:1195-1204`). Consequently `before.isEmpty` alone cannot prove a visible beginning of document. A new “known start” branch needs actual visibility evidence or a trusted optimistic snapshot with established provenance; otherwise a hidden middle-of-word cursor can be classified as start. Preserve hidden-before limitations explicitly instead of manufacturing a prose boundary. UIKit declares both context properties nullable (local iPhoneOS27.1 SDK, `UIKit.framework/Headers/UIInputViewController.h:20-24`).

4. **After-context must respect reconciliation, queuing, and visibility independently.** The engine tracks `expectedAfterContext`, `expectedSelection`, document identity, observed availability, and own-edit history (`KeyboardEngine.swift:179-218`). Its insertion primitive appends to the optimistic prefix and clears the logical selection while retaining the suffix (`:1132-1139`). Reconciliation compares both sides and selection, recognizes old own snapshots, and accepts prefix/suffix context windows (`:1027-1123,1152-1175`). Merely copying `cursorInsideWord` is insufficient: that helper directly reads the live proxy's suffix (`:1256-1258`), which may lag a newer logical cursor. Conversely `expectedAfterContext` by itself cannot distinguish hidden context from a known empty suffix because preparation collapses nil. Any new suffix test needs an explicit account of which visible/reconciled state it trusts. A fake queue may demonstrate correct primitive application order; it cannot prove the actual host's callback ordering or that a later host selection did not intervene.

5. **One insertion primitive is the safest narrow implementation shape.** `TextDocument` exposes insertion/deletion, but no engine cursor adjustment (`KeyboardEngine.swift:3-13`), and `ProxyDocument` forwards directly to UIKit (`Sources/KeyboardUI/KeyboardHost.swift:27-46`). The preview's contexts partition the document around `selectedTextRange.start/end`, confirming that suffix means after the selected range rather than the selection's first character (`App/KeyboardPreview.swift:51-67`). Constructing the complete output, including at most one trailing ASCII space, and sending one `insertDocumentText` retains existing selection replacement and suffix semantics. Inserting a gap first can consume the selection before the payload; deleting/reinserting host suffix text or moving the cursor introduces unnecessary risks. Expected caret is after the inserted gap, before unchanged suffix. The contract's Swift `Character` offset is a harness convention, not proof of UIKit/UTF-16 cursor behavior. The preview stores `NSRange` selection (`KeyboardPreview.swift:71-74`).

6. **A trailing gap changes followup behavior, not just the first resulting string.** External insertion sets `lastEdit = .typed`, not a spacing-aware state (`KeyboardEngine.swift:481-484`). Literal punctuation moves/removes an automatic gap only for accepted suggestions, glides, or `.automaticSpace` (`:291-304`). A newly appended ordinary space therefore leaves a subsequent comma or period after that gap unless the implementation adds another semantic change. Retain and report followup expectations exactly. Avoid claiming that the new right gap has swipe/suggestion punctuation behavior. Extending last-edit/respace/deletion semantics would enlarge the patch and require separate review.

7. **Punctuation sets are not a technical-language detector.** Existing R5 handling deliberately distinguishes bounded attaching punctuation from punctuation-led words or mixed runs, including curly apostrophe words (`KeyboardEngine.swift:472-500`). Preserve that logic. On the right, an existing whitespace/newline requires no addition and must remain byte-for-byte; suffix punctuation and closing delimiters should remain attached. A payload closing quote or bracket can mark sentence completion or technical syntax; a trailing apostrophe can be a word fragment. Likewise `Character.isLetter` covers scripts whose writing conventions do not use ASCII word spaces. The contract's prose hypothesis should not become an unsupported multilingual/technical correctness claim. Do not add dictionaries, parsers, or changes to the separate `composingLiteralToken` heuristic (`:1261-1268`) to hide that ambiguity.

8. **Private/restricted engine policy and controller privacy are different.** Input policy disables suggestions, learning, and auto-spaces for private/address/numeric fields, while existing explicit external spacing is not gated on those flags (`Sources/KeyboardCore/Input/InputTraits.swift:62-73`; `KeyboardEngine.swift:475-479`). New privacy exclusions would be a deliberate change in opt-in external API behavior, not an inference from suggestion policy. Native dictation already blocks private delivery. Preserve privacy controls and report engine-only private coverage accurately; do not broaden learning or expose host text in diagnostics. `DictationDestination` explicitly avoids reading private before/after/selection text (`DictationInsertionGuard.swift:11-17`).

9. **Engine deletion and native host Undo must remain separate claims.** There is no host Undo registration/grouping in the document adapter or insertion path (`KeyboardHost.swift:27-46`; `KeyboardEngine.swift:461-484,1132-1139`). Engine backspace can undo corrections/glides but treats external insertion as `.typed` (`KeyboardEngine.swift:522-563,639-647`). `undo(WordDeletion)` restores a delete gesture and is unrelated to host Undo (`:650-707`). One primitive reduces unnecessary operations; it does not establish a host Undo group. The contract correctly marks native Undo unavailable. Keep it unavailable until host evidence exists outside this audit's authorized scope.

## Acceptance interpretation

Use unchanged exact full-document, selection, caret, primitive-order, and followup assertions to evaluate the single frozen candidate. Separate natural-prose gains from ambiguous joins, native-unreachable transcript cases, and direct engine API controls. Keep every failure/unavailable record; source limitations do not authorize changing expectations. Reject any candidate that achieves gains through raw/emoji right spacing, host-text mutation, guessed hidden suffixes, reordered replacement primitives, or changes to the R5 predicate, correction machinery, or native privacy guards. Even a clean engine pass supports only the bounded engine behavior; controller delivery and host Undo remain separately unverified.

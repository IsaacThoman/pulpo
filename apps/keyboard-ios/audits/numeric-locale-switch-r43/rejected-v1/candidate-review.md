## Production review

- **Locale and fallback:** `KeyboardLayout.make` defaults to `Locale.autoupdatingCurrent.decimalSeparator`; the initial root layout therefore receives region punctuation before first display. `sync` independently resolves the same autoupdating value whenever sync actually runs, and includes the resolved value in the existing layout cache key. This addresses unchanged-traits refreshes and does not tie punctuation to EN/ES/BI. The initial constructor's later `sync` converges on the same value. No locale notification/live-immediate guarantee is added. A change of locale with an unchanged separator need not rebuild identical keys.
- **Defensive domain:** the resolver accepts one grapheme whose scalars are Unicode punctuation, and falls back to period for nil, empty, whitespace, control, digit, letter, or multi-character strings. It is not ASCII-only. A source-independent local Foundation enumeration over `Locale.availableIdentifiers` found only comma (429 identifiers), period (599), and U+066B ARABIC DECIMAL SEPARATOR (44); all satisfy the resolver. This establishes coverage of this machine's currently enumerated Foundation decimal separators, not a timeless guarantee for all future Foundation data or a definition that arbitrary punctuation is a legitimate decimal symbol. The explicit injected separator API permits defensive core checks without pretending an ordinary process locale can manufacture nil/invalid values.
- **Row fit:** actual `KeysView.layoutSubviews` defines numeric pitch `u=(W-2m+g)/3`; `rowFrames` uses cap width `key.width*u-g` and advances by cap width plus `g`. Four `.75` controls occupy `4*(.75u-g)+3g = 3u-g = W-2m`. Thus the new row starts at the existing margin and ends at the existing opposite margin, including real gaps; it does not multiply already gap-reduced digit caps. Each new cap is `(W-2m-3g)/4`. Upper digit rows, row count, height, gaps, outer margins, root docking and style selection are unchanged.
- **Preservation:** phone dispatch remains first and its rows/actions are unchanged; ordinary number pads keep their existing blank-or-globe/zero/delete row. Normal letter/punctuation/email/URL layout construction is unchanged. The only four-control row is decimal plus required globe, ordered separator/globe/zero/delete. Digits, delete and separator retain existing action types; the same locale string supplies character action and label/identifier. There is no engine, policy, document adapter, learning, storage, R36 literal-preservation, touch-routing, accessibility or host-callback implementation change. Numeric/private policy remains disabled for learning in existing production code. This is a source-preservation finding, not substitute regression execution.
- **Globe routes:** existing touch `.nextKeyboard` tracking forwards supplied events to `keysView(inputModeListWith:)`, which forwards the original keys view/event to the host; existing accessibility activation reaches controller `.nextKeyboard` and `advanceToNextInputMode`. The new numeric globe uses that exact action/identifier/style. These branches return without document insertion/deletion. Source confirms unchanged callback routing; a hosted counter cannot establish an installed OS menu.

## Revised geometry executor

The runner now isolates probes with a temporary recording delegate restored by `defer`, records initial and final snapshots, and separates visible caps from conservative targets. Each proposed target keeps cap x bounds and extends vertically by one point, clipped to KeysView bounds. It checks center plus four inset corners and a dense two-point grid for production `keyIndex` identity and root hit routing; the five explicit points additionally exercise began/ended touches. Missing/nil routing resolves false, and boolean failures remain in the output for mandatory oracle rejection. Geometry probes do not drive controller-backed document edits. Target width is the visible cap width, so horizontal fit is not inflated by assuming a whole pitch. In inset portrait the bottom target can be 44 points high (43-point cap plus one point above, lower edge clipped); landscape retains a short target and cannot support a 44-by-44 usability assertion.

These are **sampled guaranteed rectangles at the disclosed resolution**, not exact full routing partitions, actual UIKit event dispatch, physical device rotation, or installed menu evidence. Dense sampling does not mathematically prove every unsampled real coordinate. `rootRoutes` checks the root superview route, not OS/window dispatch. `identityRoutes` uses recorded key callbacks, including touch-down identity for function controls; it is a routing check, not full action semantics. Separate controller-backed workflow observations establish the latter. No sampled guarantee should be expanded to the larger production hysteresis rectangle, full pitch, or AX frame.

## Remaining gates and bounded findings

1. **Final semantic acceptance is blocked until the independent frozen oracle validates all inputs/references and scores every output row.** XCTest only checks nonempty execution/count; geometry booleans, locale current/autoupdating values, dictionary hashes/loaded-language identities, learning observations, actions and exact outcomes require oracle gates. A green XCTest alone is insufficient. The scorer is being written independently and was not reviewed here.
2. **Live-locale-refresh and defensive fallback execution are not established by this workflow protocol.** Public workflows use one process locale and forbid in-workflow locale mutation; source supports refresh invalidation, but real locale-transition and explicit injected-fallback evidence must be reported separately. Do not claim that static process-locale workflows prove a live transition.
3. **Executor remains deliberately narrow.** It uses `first(where:)` for action lookup and does not itself strictly validate the whole public input schema, match cardinality or every enabled/accessible condition. The independent validator must reject unsupported/ambiguous actions and invalid schemas; unique IDs/geometry and exact outcomes must fail closed. Existing prose pages can have repeated punctuation IDs (for example email numbers-page punctuation and bottom shortcuts), so strict all-key uniqueness can legitimately fail a workflow even when its chosen tap has an apparent match. Do not silently drop such failures or relabel them as R43-specific production regressions. No broad prose-native-usability pass follows from this scaffold.
4. **Observer and launch setup remain external evidence obligations.** Requested/effective Foundation locale validation, fresh locale-grouped host launches, nonempty requested dictionary selection, nonvacuous learning observer positive control, and disposable/reset storage must accompany scoring. This review did not inspect smoke outputs or installation behavior. Secure-only public privacy inputs do not establish all nonsecure sensitive content-type cases. The public protocol has no phone/name-phone workflows; unchanged source branches cannot establish installed phone usability.
5. **Installed OS keyboard list remains untested.** Two synthetic touch callbacks prove hosted callback count only. AX direct activation proves its callback route only. Existing short landscape vertical targets are retained under the domain addendum; they must remain disclosed. No blanket native 44-point, VoiceOver interaction, device/menu or installed-extension success claim is permitted from these observations.

No issue above requires changing the bounded production repair before fresh authoring. They restrict execution/scoring claims and must remain visible in the final report. Any subsequent source/executor/protocol/schema change invalidates this exact-artifact review until checked.

Binding decisions

1. Host and caret. A real UIWindow contains a plain UITextView. Production
PreviewHost and PreviewInputView attach the production KeyboardController.
Fixture setup inserts the initial literal and sets its initial selection before
numbered actions. UIKit transformations and authored keyboard transformations,
auto-capitalization, correction and learning are disabled before actions.
The public UITextView.text, selectedRange, selectedTextRange and caretRect are
actual host presentation/selection output, not engine state. Literal comparisons
use UTF-16 equality and the expected collapsed UTF-16 boundary. Each checkpoint
records actual public selection and a host image immediately. A mounted visible
caret rectangle is required. No later key is used as a substitute caret oracle.
The deferred documentDidChange and begin/end host lifecycle notifications mirror
the production preview host; they do not perform an edit or select an output.

2. Keys and contacts. Ordinary keys invoke the existing production key view's
accessibilityActivate path; actual UIControls receive their installed actions.
The adapter never calls engine editing methods or controller action handlers.
For a cursor slide it supplies ONE UITouch carrier through actual KeysView
touchesBegan/Moved/Ended callbacks, retaining the production delegate. After a
space hold, one-point continuous advances stop ONLY when the actual UITextView
caret reaches the authored boundary. No fixed displacement determines success;
no caret setter, cursor custom action, witness insertion, retry or repair is
used during numbered actions. Failure to reach the boundary on the visible
contact surface fails the binding. This tests mounted callback handling, not
OS HID routing or installed extension delivery.

3. Real settings visits. Before actions, settings/language may be initialized
through SettingsStore, and HomeView/AppModel may be mounted with setup dismissed.
During visits, the actual keyboard-settings UIControl opens a UIHostingController
of the REAL production HomeView through PreviewHost's URL navigation callback.
The fixture traverses public UIKit/SwiftUI accessibility containers, scrolls the
real settings list, activates the named real toggle, and reads displayed values
of ALL FOUR feedback/slide controls, including disabled retained trail values.
A real UISwitch uses its valueChanged action; a SwiftUI accessibility toggle uses
accessibilityActivate. There is NO numbered-action SettingsStore.save,
model.settings assignment, fake settings view or fallback binding. Returning
focus causes the normal hostWillAppear lifecycle reload, and host text/caret
must remain unchanged. The fixture-owned presentation/dismissal is explicitly a
mount navigation adapter, not a claim to have navigated the installed app.

4. Emoji and local search. Queries are typed and corrected with actual visible
production keys. Their displayed field accessibilityValue is checked, along
with unchanged real host text/selection. Only an actually visible, nonclipped
rendered emoji image is eligible. BEFORE selection, record the full Unicode
string used by that live cell's presentation: EmojiCell.emoji for the collection,
or EmojiResultControl.result.value beside its rendered UIImageView for search.
These are render operands of mounted production UI objects, not the controller's
query buffer, engine state, catalog, search result list, history or identifier.
The image and full scalar sequence are attached before selection. No fixed
identity, rank, category, default-tone assumption or ID parsing supplies E/R.
Cell identity/render operand is rechecked immediately before the actual control
action or the existing UICollectionView delegate selection. The delegate remains
the production delegate; the adapter does not insert emoji itself.

Frequently Used is selected using the actual labeled production button. Its
public control tag identifies the collection section addressed by that button;
there is no hardcoded section number or presumed emoji category. Visible recent
cells in that section are matched against the recorded full string and may be
scrolled into view. Adjacent-category membership cannot satisfy the check.
R is observed anew from the displayed matching recent cell before selection.
No empty history, count, ordering, uniqueness or persistence assertion is added.

Reading the current cell's render operand together with its actual image is the
mounted presentation binding for otherwise visually indistinguishable Unicode
selectors/joiners. It is not a transcription guessed from pixels or a later
host insertion. This is an explicit scope decision: the fixture is not purely
external accessibility/XCUITest observation, and must not be relabeled as such.

5. Glide and trail. One retained contact traces the named visible key centers
continuously through KeysView's actual touch callbacks and unchanged delegate.
No controller/engine glide method or decoder state is invoked or observed.
Actual changed nonempty committed host span and end caret are recorded, with no
exact spelling, word, ranking or boundary-spacing oracle. G/H are actual entire
resulting host strings and are used literally by subsequent authored actions.
Before release, the actual mounted keyboard hierarchy is rendered to an image.
No trail layer path, opacity, settings flag, stats or after-release screenshot
is treated as a visibility oracle. The 12 interpolation steps/segment and event
pump timing are contact-generation mechanics, not correctness thresholds.

6. Feedback. All three ES-04 edit checkpoints explicitly record physical system
click audibility and tactile haptics as unavailable. Only the authored displayed
independence and editing continuity are asserted; no silent physical pass.

Remaining uncertainty and boundary of clearance

protocol. There ARE unverified mechanical dependencies because execution and
compilation were expressly prohibited in this review:

  and its SDK must permit the UITouch carrier overrides. Compile-only can check
  this before freeze; this report does not claim it already compiles.

  through UIKit accessibility (or actual UISwitch). If it does not, the precise
  remaining obstacle is real settings UI activation/readout, not permission,
  audibility or a need to invent an operator protocol. No store/model fallback.
- The mounted input view, production resources, real collection selection and
  during-contact hierarchy rendering must be available in the eventual runtime.
  None has been probed. Missing bindings fail explicitly, never skip/pass.
- This adapter does not establish OS gesture dispatch, installed extension
  sandbox/lifecycle behavior, Full Access propagation, physical feedback, or
  installed app navigation. Those are outside the mounted packet's claims.

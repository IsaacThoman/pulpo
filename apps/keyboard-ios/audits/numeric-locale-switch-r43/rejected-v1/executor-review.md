## What the runner actually exercises

The host owns a real `UITextField`; its document adapter reads UIKit selection/context and delegates insertion/deletion to the field. `InputTraits(field)`, `KeyboardController.hostWillAppear`, `documentDidChange`, `layoutChanged`, `KeysView` touch methods, and `KeyView.accessibilityActivate` are production paths. The host is a test double, not `PulpoKeyboardViewController` or a `UITextDocumentProxy`. The field never becomes first responder and the custom root is manually attached beside it. That is sufficient for a hosted document-adapter test if asserted, not installed-extension validation.

The touch path calls `KeysView.touchesBegan/Ended` directly with an artificial `UITouch`; it bypasses UIKit event dispatch and initial root/window routing. `centerRoutes` separately checks only that a cap center resolves to the grid, not which key the grid picks or how an edge press behaves. Rendered layer attachments are hosted screenshots, not installed keyboard or OS menu evidence.

Production baseline corroborates the supplied gaps: numeric decimal corner is hardcoded `.` and wins over `needsGlobe`; ordinary number pad has an existing globe corner. Controller's cached layout key currently excludes locale. Scope can remain numeric layout plus controller synchronization; no engine change is necessary to address these supplied issues.

## Blocking runner issues and concrete fixes

1. **All expected outcomes are currently ignored.** `expectedText`, `expectedAdvance`, and `expectedLists` decode but are never compared. The sole assertion is `results.count == rows.count`, and zero rows pass. Missing keys, bounds violations, rejected AX, and unsupported actions only append strings. Require nonempty valid input, unique IDs, exact expected final outcomes, zero unexpected errors, and explicit success/failure per row. Preserve results for diagnosis, then fail XCTest or an obligatory external scorer on any failure. If an external scorer owns comparisons, freeze and hash that scorer and its complete gates before case authors begin. Do not advertise executor XCTest success as semantic success by itself.

2. **Locale is a decorative input today.** `row.locale` is never used; every row gets the same process `Locale.current`, whatever that happens to be. `project.yml` supplies no AppleLocale launch configuration. Run each requested locale in a correctly configured fresh test-host process (and record launch settings); validate effective current and autoupdating locale/separator against requested locale before action execution. Reject mixed-locale rows inside one immutable-locale process. Changing `UserDefaults` in a running process is not sufficient proof that Foundation caches changed. A separate controlled in-process locale seam may test the explicit refresh contract, but must be disclosed and must not replace real process-locale runs. Freeze both execution and scoring here.

3. **Action protocol needs validation and complete explicit semantics.** Current supported kinds are only `tap`, `key`, `delete`, `globeTouch`, `globeAX`, `refresh`, `field`. Unknown kinds must fail visibly, with no action omitted from trace. Validate required/forbidden values, supported keyboard/language/oneHanded values, finite positive widths, and nonempty action arrays. Resolve exactly one matching actionable view and verify enabled/visible/accessible conditions as applicable. In particular `key: key-globe` currently supplies nil event: the production input-mode tracking branch calls neither list nor advancement, yet no error is recorded. Route every touch globe action through an event or reject the ambiguous generic form. A blank layout corner is spacing, not a successful key press. Add or explicitly disallow protocol operations before cases are authored for language/globe/private/width/locale changes, cursor/selection, edge touches, move/cancel/hold, and lifecycle events; do not silently reinterpret them as simple taps. Known unsupported operations should produce failures, not successful rows.

4. **Language availability and no-learning need nonvacuous gates.** Real `en_US.pkdict` (~12 MB), `es.pkdict` (~15 MB), and `en_es.pkdict` (~26 MB) are present in the supplied resource directory, and production really loads them through `LanguageStack`; no fake lexical data is needed. Existence is not successful parsing. Require nonnil stack, successful loading of requested language, matching engine language and host-reported typing language, and dictionary identity/size or another nonempty resource proof. The controller can fall back to English if requested data fails; current flags do not fail that row. `learnedBefore/After = -1` permits a vacuous nil-stack equality. Require valid nonnegative counts and assert unchanged numeric/private counts, with policy checked at each relevant stage rather than only at final traits. Use a normal prose positive control that actually commits a word to prove this observer detects learning. Isolation/reset or uniquely scoped test-host storage is needed because `sharedStack`, standard defaults, and application-support personal data persist across rows/runs. Restore settings after test or use a disposable host environment. This host's `hasFullAccess=false` selects standard settings, but production dictionary persistence independently probes App Group writability; record which path is in use. Sample after `hostDidDisappear` too if making lifecycle no-learning claims. Secure-only `privateField` does not cover nonsecure sensitive `textContentType`; expose such traits or bound claims accordingly.

5. **Native target evidence is insufficient.** Recorded `w/h` are visible cap frames (landscape 32 pt high), not actual hit targets. `KeysView.keyIndex(at:)` uses nearest-cap distance across the grid; `hitRects` additionally affect tracking hysteresis. Do not call a pitch or AX frame the effective target. Before claiming compact/native fit, record requested root width, effective docked keys width, style/orientation and root/grid bounds; derive or empirically sample each control's initial routing region within actual ancestor bounds, report target width/height separately from caps, test centers plus both sides of each shared edge, and verify no overlap/ambiguous routing/clipping. A `root.hitTest` result of `keys` must be followed by `keyIndex(at:)` identity verification or a real routed press. `row.width > 500` triggers the production landscape style; a nominal width alone is not physical device rotation. One-handed mode may not actually dock at a narrow width or in landscape, so report effective width/mode. Preserve upper rows/keyboard dimensions per domain addendum; retained landscape sub-44-point vertical space must remain disclosed and cannot be called full 44x44 usability success. Frames are final-only today; snapshot initial and transition layouts so a final `field` switch cannot conceal a broken numeric row.

6. **Touch globe and AX globe must remain separate outcomes.** Production touch `.nextKeyboard` forwards each received `UIEvent` via `handleInputModeList`, while AX activation invokes controller `.nextKeyboard` and `advanceToNextInputMode`. A synthetic `UIEvent()` plus began/ended reaches the test host's counter twice, which means two callback invocations, not two menu openings or real OS advancement. Record event callback phases/order where supported and assert each switching route leaves text and selection unchanged. Extend hosted touch coverage to move/cancel if claiming all-event forwarding. Host callbacks must record originating view/event identity so an unrelated event is not counted as proof. Actual installed tap advancement and long-press OS keyboard-list behavior require a separate installed extension/device interaction; the present scaffold cannot establish either. AX direct method invocation establishes callback behavior, not VoiceOver focus discoverability or real gesture usability.

## Refresh and case-coverage constraints

Every action currently triggers an unconditional `c.documentDidChange()`, and `refresh`/`field` trigger it twice. This obscures whether a dedicated refresh caused the change and limits testing stale-before-refresh versus updated-after-refresh behavior. Make automatic host callbacks explicit in the protocol/trace; record state before and after actual refresh. Initial `row.locale` fixtures alone cannot prove an already-live controller's locale cache invalidates at refresh.

Use literal ordinary-text controls (including space/return through key identifiers where appropriate) as regression controls, and require their exact observed document results. Digit/zero/delete entry, number versus decimal layout, globe false versus true, language independence, sensitive text traits, compact/docked/landscape layouts, and transitions must stay separately observable. Phone tests here can cover production branches; hosted `phone` must never become evidence that installed iOS custom phone keyboards are usable. `namePhone` is not currently supported by this protocol; fail or add it explicitly if authoring includes it.

Missing/invalid separator fallback cannot be forced merely by choosing ordinary process locales. Cover that defensive API behavior with an explicit core-layout injection path and frozen expectations, while preserving real Foundation locale controller runs. Test any legitimate non-ASCII Foundation separator in the core domain; do not impose an ASCII-only oracle by accident.

## Acceptance boundary

After the blocking execution/scoring/schema changes are frozen, fresh cases can be authored without looking at implementation outputs. Later results should label four layers separately: core layout, hosted UIKit/controller callbacks, measured routing/targets, and installed OS extension/menu. No hosted screenshot or callback count can upgrade the final layer from untested to passed.
